# WebUI 实施计划

Spec 已写入 `docs/superpowers/specs/2026-08-29-webui-design.md`，5 个 ADR 已在 `docs/adr/`。以下是基于代码探索后的精确实施计划。

## 探索发现的关键事实

1. **set_cwd 实现极简**：`this.cwd`（agent.ts:41）是 private 字段，`runTurn`（:279）每次从 `this.cwd` 读取传给 `runLoop` → `LoopDeps.cwd` → `executeOneTool` 构建 `ToolContext = { cwd: deps.cwd }`（tool-calls.ts:63）。改 `this.cwd` 后下一轮次自动生效，loop/tool 层零改动。
2. **set_cwd 应 run-guarded**：运行中改 cwd 会让 in-flight 工具写到错误目录，需 `if (this.running)` 守卫。
3. **ack 复用 status_state**：`status_request` handler（:221）已 emit `status_state`（含 cwd），set_cwd 成功后 re-emit 同样的 `status_state`，不加新消息类型。
4. **viewport.ts + browse.ts 有重复 ICON 检查**：两处都 `b.icon === ICON.thinking || b.icon === ICON.tool`，shared 重构时改为 `b.kind === 'thinking' || b.kind === 'tool'`，可提取 `isExpandable(b)` 消除重复。
5. **navigation.ts 有死 import**：`import type { Config }` 未使用，移动时清理。
6. **架构测试**：pkgDir 硬编码 map，walk 对不存在目录返回 []（空通过）。加 server 时需加 `existsSync` 守卫。
7. **构建**：build.mjs 的 workspacePlugin 解析 `@dogegg/*` → `./name/src/index.ts`。build-web.mjs 需同样插件解析 @dogegg/agent + @dogegg/server + @dogegg/bridge。
8. **执行顺序调整**：P6（构建流水线）必须在 P3 之前，因为开发 WebUI 需要 Vite dev server。

## 实施阶段（调整后顺序）

### P0 — 契约扩展 + set_cwd + /cd 命令

**文件改动**：
- `bridge/src/contract/ui-to-agent.ts`：`UiToAgentMessage` 末尾加 `| { type: 'set_cwd'; path: string }`（在 quit 前）
- `agent/src/core/agent.ts`：
  - `send()` 加 `case 'set_cwd'`（纯查询组，run-guarded）：验证 `fs.statSync(path).isDirectory()` → `this.cwd = path` → re-emit `status_state`（复用 status_request 的字段集）→ 失败 emit `notice`
  - 提取 `emitStatusState()` 私有方法（status_request 和 set_cwd 共用，消除重复）
- `ui/src/tui/input/commands.ts`：COMMANDS 加 `/cd`，parseCommand 加 `case '/cd'`（参数解析：`/cd /path` → `{ type: 'set_cwd', path }`）
- `ui/src/tui/app/app.tsx`：/cd 命令提交后吞回车（与其他 overlay-opening 命令一致，因 set_cwd 回 status_state 会切 view）

**验证**：typecheck + TUI 手测 /cd

### P1 — shared 重构（Block 语义化）

**文件创建/移动**：
- `ui/src/shared/index.ts`：纯 re-export（block + reducer + commands + config）
- `ui/src/shared/block.ts`：从 tui/chat/block.ts 移入，重构：
  - 删 `import { palette }`，删 `ICON`（emoji）、`COLOR`（hex map）
  - `BlockColor` → `ColorToken` union（`'accent'|'text'|'cyan'|'yellow'|'red'|'subtext'`）
  - 加 `BlockKind` union（`'user'|'assistant'|'thinking'|'tool'|'error'|'notice'|'auto_compact'`）
  - `Block` 用 `kind: BlockKind` + `color: ColorToken` 替代 `icon` + `role` + `color: BlockColor`
  - 加 `isExpandable(b: Block): boolean`（提取重复的 thinking/tool 检查）
- `ui/src/shared/reducer.ts`：从 tui/chat/reducer.ts 移入，重构：
  - `palette.red` → `color: 'red'`，`palette.yellow` → `color: 'yellow'`，`palette.subtext` → `color: 'subtext'`
  - `ICON.thinking` → `kind: 'thinking'`，`ICON.tool` → `kind: 'tool'` 等
  - import 从 `./block` 改为 shared 内部相对路径
- `ui/src/shared/commands.ts`：从 tui/input/commands.ts 移入（含 P0 的 /cd），原样（已纯净）
- `ui/src/shared/config/`：从 tui/overlays/config/ 移入 build.ts/navigation.ts/label.ts/entries.ts/index.ts
  - navigation.ts 删未使用的 `import type { Config }`
  - 各文件 import 路径调整（相对路径不变，仍指向同目录兄弟）
- `ui/src/tui/theme/token-map.ts`（新建）：`KIND_ICON`（kind→emoji）、`TOKEN_COLOR`（token→hex）、`KIND_ROLE`（kind→中文标签）
- `ui/src/tui/chat/block.ts`：删（已移到 shared）
- `ui/src/tui/chat/reducer.ts`：删（已移到 shared）
- `ui/src/tui/input/commands.ts`：删（已移到 shared）
- `ui/src/tui/overlays/config/`：删（已移到 shared）
- `ui/src/tui/chat/viewport.ts`：保留在 TUI（终端专属），但 import 改为 `../../shared/block`，ICON 检查改为 `isExpandable(b)`
- `ui/src/tui/chat/browse.ts`：保留在 TUI，import 改为 `../../shared/block`，ICON 检查改为 `isExpandable(b)`

**验证**：typecheck + test + TUI 全功能回归

### P2 — server 包 + 组合根

**文件创建**：
- `server/package.json`：`@dogegg/server`，type: module，exports: { ".": "./src/index.ts" }，deps: `@dogegg/bridge: "*"` + `@dogegg/agent: "*"`（组合根需要 import Agent）
- `server/tsconfig.json`：5 行模板（extends ../tsconfig.base.json, include src + test）
- `server/src/index.ts`：纯 re-export
- `server/src/channel/sse.ts`：`createSseChannel()` → { agentPort, uiPort, sseHandler, postHandler }
  - SSE handler：写 `Content-Type: text/event-stream` 头，注册 res 到 `Set<ServerResponse>`，`uiPort.post` 回调写入 `res.write('data: ' + JSON.stringify(msg) + '\n\n')`
  - POST handler：读 body → `JSON.parse` → `agentPort.onMessage` 回调触发
- `server/src/channel/index.ts`：re-export
- `server/src/http/server.ts`：`startServer({ uiPort, sseHandler, postHandler, staticDir, port })`
  - `http.createServer` + 路由分发：`/api/events` → sseHandler、`/api/message` → postHandler、`/api/fs` → fs handler、其余 → 静态文件
  - 静态文件：用 Node 内置 `fs.readFile` serve（不用第三方库）
- `server/src/http/routes.ts`：路由匹配逻辑（URL pathname → handler 映射）
- `server/src/http/index.ts`：re-export
- `server/src/fs/browse.ts`：`listDirs(path)` → `{ current, dirs, parent }`，只返回子目录
- `server/src/fs/index.ts`：re-export
- `server/test/channel/sse.test.ts`：SSE channel 基本测试（post → listener、SSE handler 注册/断开）
- `main-web.ts`（根目录）：组合根——loadConfig → createSseChannel → new Agent → startServer
- `package.json`（根）：workspaces 加 `"server"`，typecheck 加 `&& tsc --noEmit -p server`

**验证**：typecheck + SSE channel 测试 + 手测 SSE 连通（curl + 浏览器）

## 技术约束

- 遵循 module=folder 约定（index.ts 纯 re-export，实现归兄弟文件）
- 零 emoji 图标（WebUI 用 Lucide SVG，TUI 保留 emoji 因终端限制）
- CSS 变量 + CSS Modules（零运行时样式库）
- 零运行时动画库（纯 CSS @keyframes + transition）
- prefers-reduced-motion 全支持
- 架构测试强制依赖方向（server 不 import ui，webui 不 import agent）
- 每阶段 typecheck + test 通过后再进下一阶段
