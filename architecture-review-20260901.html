改进候选（按优先级排序）

1. 为 reducer.ts 补测试 Strong

195 行纯函数，标记 ★可单测但零测试。最近 8 次提交 6 次修 thinking 对齐 bug。纯函数零 mock，投入产出比极高。覆盖：流式累积/flush、工具块配对、session_ready 重建（含 thinking 空/非空/混合）、compaction、error/cancel、history_cleared。

2. 拆分 app.tsx 上帝组件 Strong

581 行，6 内联 modal，~15 useState，110 行 onMessage if 链。拆为：5 个独立 modal 文件夹 + usePanelState hook + 精简 App。是项目中最大的未测试逻辑集中点。

3. 强制 barrel import 规则 Worth exploring

架构测试加一条规则：非 index 文件的 import 不能指向其他模块的非 index 文件。修 72 处现有违规（agent 38 + ui 34）。成本中等但一劳永逸。

4. 清理死代码 Worth exploring

移除：SSE uiPort、StatusBar 组件、5 个未用 primitives（~525 行）、saveConfig 无用导出。成本最低，立即减少维护负担。

5. 消除跨模块重复 Worth exploring

将 STATUS_LABELS、getToolConfigPerm、isRunning、onCommandFeedback、0.8 阈值统一到 shared/ 或 bridge。消除 7 处重复，减少漂移风险。

6. 修复 server 安全问题 Speculative

CORS 回显 Host header 不安全；detectShells 应从 routes.ts 独立；路径穿越检查用 path.resolve 替代 fileURLToPath。需配合 server 测试。

7. 补 AgentToUiMessage zod schema Speculative

UiToAgentMessage 有 zod 校验但 AgentToUiMessage 没有——SSE 下行消息无校验。对称性缺失。优先级低（内部消息，非外部输入）。

8. 为 shared/config/build.ts 正名 Speculative

build.ts 在 shared/ 但实际只被 TUI 用（WebUI settings 自己实现了配置编辑）。要么移到 tui/ 下，要么让 WebUI 也用。

首要推荐

候选 1（reducer 测试）是最高优先级——纯函数、零 mock、6 次 bug 修在同一个未测函数里。有了测试后候选 2 的拆分也有了回归保护。

候选 4（清死代码）成本最低——删 ~525 行未用代码 + 修 2 处违规，立即减少维护负担。

候选 2（拆 app.tsx）+ 候选 5（消重复）一起做——拆分时顺便把重复逻辑移到 shared。
