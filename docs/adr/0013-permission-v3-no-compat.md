# ADR-0013：权限桶值结构化（whole + patterns）与配置演进不兼容原则

状态：已采纳（2026-09-15）

## 背景

ADR-0012 落地后，"整选"开关（整工具/整组 + 保留已配规则）最初靠 `**` 模式串兼任：
它恰好在三类匹配语义里都命中一切，且桶内条目 OR 求值使其天然压过其余条目。审查发现两个问题：

1. **契约寄生在巧合上**："整选"的含义依赖「`**` 在 path glob、command 通配、工具名通配
   三个匹配族里都等于 match-all」这一实现事实。任何一处匹配语义演进（如 path glob 改锚定
   规则）都会让 UI 声称整选而引擎不再整选——allow 静默收窄、**reject 静默失效（fail-open）**，
   且无任何机制强制三处同步。
2. **"空数组 = 整工具"语义阻塞交互闭环**：`whole:false` + 零模式（"取消了整选但还没勾选"）
   这一编辑中间态无法表达，导致 UI 被迫做"virgin 态不渲染开关"之类的特例。

同时确立项目级策略：为旧配置格式维护兼容链（归一层、union schema）会让每次格式演进的成本
随迭代累积膨胀，不可持续。

## 决策

1. **桶值结构化（v3）**：`"键": { "whole": boolean, "patterns": string[] }`。
   - `whole: true` → 整键命中（整工具/整组）；patterns 不参与匹配，仅作取消整选后的恢复内容；
   - `whole: false` + 非空 patterns → 按模式匹配（OR，语义同前）；
   - `whole: false` + 空数组 → 键存在但**不命中任何规则**（编辑中空选）——
     旧「空数组 = 整工具」立法删除，编辑死锁在语义层面消失；
   - `**` 回归纯 glob/通配语义，与整选状态彻底解耦（引擎与 UI 都不再从模式内容读取状态）。
2. **配置演进不兼容原则（项目立法）**：schema 只接受当前版本格式；旧格式（M1 条目数组、
   v2 字符串数组、`**` 标记）加载即报错拒绝。不设版本号字段、不做归一层/迁移机器；
   失败路径沿用 `loadConfigOrExit`（人话原因 + config.md 链接 + 退出），
   错误文案补恢复指引（删除 permission 字段回退出厂默认后经 /config 重配）。
   启动失败时进程未起、后续 save 不可能覆写旧文件——无数据破坏风险。
3. **patterns 恒校验**：即便 `whole: true`，patterns 仍按作用域锚点立法校验——
   它们是规则的待命态（取消整选后生效），编写期就该正确。
4. **会话提升（sessionRules）不动**：运行时内存结构而非配置文件，内部「空 = 整工具提升」
   自洽且不可手写，不随配置 v3 立法改变。
5. **删除**：`permissionLegacySchema`、`entriesToBucket`、`permissionEntrySchema`、
   `toolRuleSchema` 及编辑器 paths 的 legacy 防御分支；工厂默认权限改写为 v3 形态。

## 落选方案

- 继续用 `**` 标记 + 不变量测试钉死：契约仍寄生在匹配巧合上，测试只能把静默失效降为红灯，
  不能消除语义混载（一个字符串既是功能模式又是状态位）；
- 专用标记常量（引擎特判 `@whole` 类保留串）：改动小且优于 `**`，但仍是「数组里塞非模式
  语义的字符串」，不如显式字段诚实；作为过渡方案已被 v3 取代。

## 后果

- 存量配置（v2/M1/`**`）升级后启动报错，需手动改写或删除 permission 字段重配——
  一次性成本，换取此后每次格式演进零兼容负担；
- UI 两端状态机简化：开关恒渲染、空选可表达、无 virgin 特例；"删光模式不再自动回整选"
  （整选只由开关控制）；
- `PermissionConfig` 类型形状变更波及引擎/编辑器/两端 UI/全部权限测试——本次一次性改清，
  后续格式演进按不兼容原则同样处理。
