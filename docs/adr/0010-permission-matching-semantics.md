# ADR-0010：权限匹配——锚点作用域 + 按主参数分派的匹配语义

状态：已采纳（2026-09-09）

## 背景

参数化权限规则（桶 → 工具 → 模式数组，见 `2026-09-09-permission-config-design.md`）需要定义「模式如何匹配一次工具调用」。实现迭代了多版，暴露了三个必须回答的问题：模式的作用域由什么决定？相对路径怎么比？`*` 和 `**` 是什么关系？

中途出现过一个真实漏洞：`./**` 归一为相对模式 `**` 后，其正则（`.*`）能匹配逃逸到 cwd 外的绝对路径参数——仅靠「归一化约定」挡不住 fail-open。

## 决策

1. **作用域由锚点前缀显式声明**，归一化只做解析、不决定作用域，glob 算子不兼职作用域标记：
   `./`（cwd）、`~/`（主目录）、盘符（绝对子树）、`*` 开头（从文件系统根匹配）。字面量打头的裸模式
   （`docs/**`）从根匹配只能命中盘根条目，必然是忘了写锚点 → **schema 加载期拒绝**。
2. **归一化**：模式与参数的 path 经 `path.resolve` 统一为绝对 posix 路径——对整条路径做词法折叠，
   任意位置、任意深度的 `..`/`.` 都处理（`../../x`、绝对路径夹 `..` 皆然），两侧同函数。
3. **匹配函数按主参数分派**：
   - `path` 主参数 → `matchGlob`（分段 glob）：`*` 单段内任意（不跨 `/`）、`**` 跨任意层、`?` 单字符、
     其余字面量、整串锚定。路径有层级，段边界是安全性质（`./docs/*` 刻意不覆盖 `./docs/sub/x`）；
   - `command` 主参数（shell）与工具名 → `matchWildcard`（平文本通配）：`*` = 任意字符序列（含 `/`，
     与 `**` 同义）。命令没有层级概念，`git *` 通配到结尾即够。
4. **判定顺序**：reject > 会话内 allow_always > ask 规则 > allow 规则 > 默认 ask（固定安全默认，
   不可配置）。

## 理由

- 显式锚点消灭了「模式写法 → 作用域」的隐藏映射（对齐 gitignore 式直觉），配置可随项目搬迁；
- 路径与命令是两种东西：前者有层级（段边界即安全边界），后者是平文本（通配到头即够）——
  分派两个贴合的函数，比为「统一」而牺牲任何一方的直觉更可维护；
- 已知残余边界（立法注明）：词法归一化不追踪 symlink；shell command 模式是便利而非安全边界
  （命令链 `&&`/管道可绕过，命令链拆分器为独立后续批次）。

## 影响

- `bridge/src/contract/{config,permission,glob}.ts`：schema 作用域校验 + 双匹配函数（纯派生，三端共用）；
- `agent/src/permission/manager.ts`：锚点归一化（含 `~/` 展开），cwd 由 ToolExecutor 传入；
- 旧扁平条目配置加载期自动归一为 v2 形态（**已被 ADR-0013 撤销：兼容归一层已删除，旧格式直接报错**）；非法模式给出人话报错（组合根捕获 zod 错误）。
