# ADR-0011：压缩 = 全量交接总结（无保留尾巴、无淘汰）

状态：已采纳（2026-09-10）

## 背景

旧压缩语义为「超 80% 窗口 → 保留最近 4 条原文（keep=4）+ 旧消息 LLM 摘要 + 硬丢弃兜底（enforceContextLimit）」。
讨论中发现三个问题：

1. **切缝配对隐患**：keep=4 的消息级切分可能正好落在 assistant(tool_calls) 与其 tool 结果之间——
   拆散配对会让下一次 API 调用直接 400；
2. **淘汰即失忆**：从头部丢弃/淘汰消息，模型在不知情的情况下失去上下文，与「history 永不淘汰」的
   R1 精神相悖（模型侧的 context 同样不应被静默删减）；
3. **摘要定位模糊**：旧摘要是「压缩饼干」（越短越好），但它实际是模型继续工作的**唯一上下文**。

## 决策

1. **压缩 = 把整个 context 交给模型总结**，替换为一条 user 角色摘要消息（带头标注
   `[对话已压缩——…]`）。无保留尾巴、无轮次/工具输出淘汰、无 enforce 硬丢弃；
2. **摘要按「任务交接文档」设计**（结构化提示词）：任务目标/已完成步骤/涉及文件路径/重要决策及理由/
   未完成事项/用户偏好，逐项保留、中文条目、不编造；maxOutput 2000；
3. **诚实失败**：总结调用失败或摘要为空 → 异常上抛，轮次以 error 收尾并发通知——不做降级、
   不静默丢上下文，由用户决定 /compact 重试或 /new；
4. **删除** splitForCompaction 与 enforceContextLimit 及其测试。

## 理由

- 每次压缩是对「完整可见上下文」的重新总结（[摘要_v1 + 新对话] → 摘要_v2），不存在摘要的摘要的
  叠加劣化；且全量替换天然消灭切缝配对问题；
- 摘要可能丢信息，但结构化交接提示词把丢失概率压到最低；淘汰是**确定丢**。两害相权，
  选择可被提示词质量改善的那一个；
- R1 双写分离保证 history 永远是完整档案——压缩的有损性由「原文可查」托底。

## 后果

- 一次 LLM 调用完成压缩（无 keep 切分、无二级兜底），代码删多于增；
- 摘要失败时该轮无法继续（诚实失败）——换取模型上下文永不被静默删减；
- 手动 /compact 与自动触发走同一条全量总结路径。
