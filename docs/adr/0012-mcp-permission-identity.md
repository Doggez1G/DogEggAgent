# ADR-0012：MCP 权限服务键按身份匹配 + 注册表合规关口

状态：已采纳（2026-09-15）

## 背景

MCP 接入后，28 个 `mcp__<服务>__<工具>` 形式的工具涌入权限选择器，且 TUI 按键层与渲染层
各调一次 `buildEntries`（按键层漏传工具清单）导致 MCP 工具「显示得到选不中」。更深层的问题：

1. **权限粒度错位**：逐工具罗列把列表撑爆，而信任的真实单位是**服务**（你信任的是服务提供方，
   不是某个工具名）。服务升级新增/改名工具时，逐工具规则全部失效；
2. **拼接名的固有歧义**：扁平名 `mcp__<服务>__<工具>` 是有损摊平——服务名含 `__` 时前缀归属
   可嵌套歧义；供应商 API 对函数名有硬规定（`[a-zA-Z0-9_-]`、≤64），服务名含中文/空格/超长
   会让**每一次对话请求整体 400**（不是单个工具不可用）；
3. **配置校验的语境漂移**：权限模式的作用域前缀校验写于 MCP 出现之前，当时所有桶键都是内建
   工具；服务键的数组条目是内部工具名（如 `browser_close`），被误当路径模式拒绝加载。

## 决策

1. **服务键按身份匹配，不解析名字**：权限桶键增加 MCP 服务裸名形态（如 `"playwright": []`）。
   空数组 = 整组生效；非空 = 数组条目匹配服务**内部工具名**（精确/`*` 通配，工具启用匹配，
   永不涉参数）。匹配按**注册期记录的身份** `{ kind: 'mcp', server, name }` 进行——
   身份由统一注册关口随工具维护、随 `tools_list` 下发、注入权限引擎；LLM 可见名退化为纯调用
   管道，任何地方不从名字里解析归属。服务名由此**零约束**（任意字符，含 `__` 嵌套、中文、超长）。
2. **注册表统一合规关口**：`ToolRegistry.register` 同时完成——合规转换（原名符合
   `^[a-zA-Z0-9_-]{1,64}$` 则原样注册；否则整体哈希为 `h-<12位hex>` 确定性标签，变换落在
   Tool 对象上保证 `schemas()` 发出的名字必然合规）+ 冲突可见失败（标签被占即抛错，绝不静默
   覆盖）+ 身份记录（所有工具必带身份，builtin/mcp 两态，与工具同增同删）。适用于一切注册来源。
3. **作用域前缀校验收窄到内建 path 工具**（`BUILTIN_PATH_TOOLS`）：只有它们的数组条目才是
   路径模式；MCP 服务键、遗留 `mcp__x__*` 键、未来扩展工具的条目一律跳过校验。
4. **UI 两端同构分组**：权限选择器 = 内建工具逐个 + MCP 服务逐个（服务条目加入即整组）；
   服务键钻入 = 运行时工具清单勾选式细化 + 通配规则行。跨桶优先级不变（reject > 会话提升 >
   ask > allow）：「allow 整组 + ask 勾选个别」可行，反向不成立。

## 落选方案

- **转义编码扁平名**（服务段 `-5f` 式转义保单射）：能消灭歧义但把编码复杂度带进运行时命名，
  且身份层出现后编码完全多余——归属不再依赖名字，方案整体让位于身份匹配；
- **每服务一个元工具内部分发**：绕开拼名但牺牲原生 JSON Schema 透传与模型选型精度，架构倒退；
- **服务名字符约束**（如禁 `__`）：在拼接歧义上打补丁，违背零约束诉求；身份层让约束失去必要。

## 后果

- `tools_list` 载荷携带 `identity`（ breaking 契约扩展；WebUI/TUI 消费方同步升级）；
- 哈希标签对 LLM 不可读——仅发生在服务名/工具名不合规的场景，界面处处展示真实名；
- 服务删除后桶内旧键成为孤儿规则（不命中任何工具），UI 标注不自动清理；
- TUI 按键层改为复用渲染层 entries（单一事实源），消灭「两处 buildEntries 漂移」这类 bug 的
  再发土壤。

## 后续修订：整键标记 `**` 与保留式全选（2026-09-15）

> **⚠️ 本节方案已被 ADR-0013 整体取代并反向删除**：`**` 回归纯 glob/通配语义、空数组不再表示整键、virgin 特例随 v3 显式整选（whole 字段）消失。本节仅作决策过程存档。



权限细化界面增加**显式整选开关**（内建 = 整工具，MCP = 整组）：切回整选时保留全部已配模式/
勾选，取消整选时原样恢复。编码立法：**数组条目 `**` 为「整键」标记**——它在三类匹配语义里都
恰好命中一切（path glob 的 `**` 锚定为任意路径、command/工具名平文本通配里 `**` ≡ `*`），
而桶内条目按 OR 求值，因此 `["**", "git *"]` 自然表示「整工具生效 + 保留一条模式」——
**引擎与配置 schema 零改动**，标记只是既有语义的 UI 命名。

状态机：空数组 = virgin 整选（无开关，首次添加/勾选是唯一出口，无操作意义的开关不渲染）；
含标记 = 整选态（模式行灰显锁定、无添加入口，开关回车即恢复）；无标记非空 = 按模式态（全部
可编辑，开关回车插入 `**` 保留一切）。MCP 服务键因 `*` ≡ `**`，`*` 亦视为标记（切回整选统一
写 `**`）。选择即钻入（afterRunPath）落地的 virgin 视图与旧提示行语义不变。
