# R-PRM 权限与安全

权限系统回答一个问题：**这次工具调用允不允许执行**。它决定 agent 的自主边界——读代码可以放行，改文件要确认，删库必须拒绝。三层结构：配置三桶（持久）、会话提升（临时）、固定安全默认（兜底，不可关闭）。

## 术语与配置形态

### R-PRM-01 三桶

- `allow`（放行）/ `reject`（拒绝）/ `ask`（每次询问）三个桶，持久保存于 config.json。
- 一次工具调用的判定顺序固定：**reject 命中 → 拒绝；会话提升命中 → 放行；ask 命中 → 审批；allow 命中 → 放行；全部未命中 → 默认 ask**。
- 「未列出 → ask」是**固定安全默认**：宁可多问，不可漏拦；该兜底不可被任何配置关闭。

### R-PRM-02 规则形态（v3 结构化）

- 桶内是「键 → 规则」映射，每条规则 `{ whole: boolean, patterns: string[] }`：
  - `whole: true` → 整键生效：该键覆盖的所有调用都按本桶处理；patterns 不参与匹配，仅作取消整选后的恢复内容（编辑器保存用户配过的细规则，切换整选不丢）。
  - `whole: false` → patterns 生效（多条 OR 匹配）；**空 patterns = 键存在但不命中任何规则**（编辑中的空选态，语义上等于暂无规则）。
- 编辑器两端（TUI/WebUI）提供整选开关 + 细化编辑：切回整选保留已配规则，取消整选原样恢复。

### R-PRM-03 键的两类与主参数

- **内建工具键**（如 `read_file`、`shell`）：patterns 是**主参数模式**——shell 的主参数是 command（平文本通配，`git *`），文件类工具（read/write/edit/ls/glob/grep）的主参数是 path（路径 glob：`*` 不跨 `/`、`**` 跨层、`?` 单字符）。
- **MCP 服务键** `mcp:<服务名>`（必须带前缀，裸服务名键加载期拒绝）：patterns 是**服务内部工具名**选择器（如 `browser_close`、`browser_*`，平文本通配）——这是「哪些工具被本规则覆盖」的启用匹配，**永不涉及工具执行参数**（MCP 参数 schema 服务自定义，无主参数概念）。
- 服务键按注册期身份匹配（工具注册时记录 `{ server, name }`）——不解析 LLM 可见名，服务名零字符约束（含 `__`、中文、空格、与内建同名均无歧义）。

### R-PRM-04 路径作用域锚点

- 内建 path 工具的模式必须显式声明作用域，加载期校验（裸模式如 `docs/**` 直接拒绝——从盘根匹配必然是忘了写锚点）：
  - `./` 或 `../` → 相对 cwd；`~/` → 主目录；盘符或 `/` → 绝对子树；`*` 开头 → 从文件系统根。
- 该校验只对内建 path 工具生效（MCP 服务键的 patterns 是工具名选择器，无路径语义）。
- 判定前参数与模式都归一到绝对 posix 路径：**参数按 realpath 真实位置**——cwd 内符号链接指向 cwd 外时词法匹配会被骗，真实位置越界即失配落 ask（防逃逸，ADR-0010）。

### R-PRM-05 MCP 服务键细则

- 匹配按工具注册期身份（`{ server, name }`），服务名零字符约束（`__`、中文、空格均无歧义——前缀键 `mcp:<名>` 与内建工具名不可能混淆）。
- 服务离线时规则保留（纯配置匹配，不依赖运行状态），重连自动生效；服务删除后规则成为孤儿（UI 可见可清理，不自动删除）。
- 项目级服务键授权随 `.dogegg/` 进 git 与仓库共享。

### R-PRM-06 审批流（四档决策）

- 落 ask 的调用弹出审批，用户四选一：
  - **本次允许**（allow_once）：仅本次；
  - **始终允许**（allow_always）：整工具会话提升——本会话内该工具后续调用免审批；
  - **对此范围不再询问**（allow_always_scoped）：范围提升——agent 自动推导范围模式（如 shell 推导命令首词、read_file 推导所在目录），落库为该工具的范围规则；
  - **拒绝**（reject）：本次不执行，模型收到拒绝原因可调整方案。
- 会话提升**优先于配置 ask 规则**（用户最新显式意图），但 **reject 恒压过提升**（配置层硬拒绝是安全底线）。
- 提升可随时在 /permissions 面板撤销（整工具或单条模式），新建会话自动清空。

### R-PRM-07 优先级的完整立法

```
1. reject 命中                    → 拒绝（安全底线，最高）
2. 会话提升命中                    → 放行（用户本会话最新显式意图）
3. ask 命中                        → 审批（显式「强制确认」压过宽放行——例外强制确认）
4. allow 命中                      → 放行
5. 全部未命中                      → 默认 ask（固定安全默认，不可配置关闭）
```

- 推论：**「allow 整组 + ask 勾选个别」可行**（整组放行、个别询问）；反向「ask 整组 + allow 个别」不成立（ask 命中即问）。
- 桶内多条规则 OR 匹配（任一命中即命中）。

### R-PRM-08 编辑两端

- TUI /config 权限树与 WebUI 设置 Permissions 区**同等编辑能力**：三桶卡片、整选开关、模式就地编辑/删除、MCP 服务键勾选细化（对运行时工具清单勾选）、添加工具（内建逐个 + MCP 服务整组）。
- 校验失败（模式缺锚点等）编辑即报错回滚，不写坏配置。

### R-PRM-09 格式演进不兼容

- 权限配置只支持当前 v3 格式：旧扁平条目数组、v2 字符串数组、裸服务名键（未加 `mcp:` 前缀且与 mcpServers 服务同名、服务名与内建工具同名）加载期直接报错并指引文档（ADR-0013 不兼容原则）。
- 服务键强制前缀立法见 ADR-0012/0013。

## 边界与立法

- **命令模式是「便利而非安全边界」**：通配会命中命令链（`git *` 也命中 `git x && rm y`）——危险命令的防线是 ask/reject 显式压制，不是模式匹配。
- 固定安全默认不可配置关闭：未列出 → ask 是最后防线。
- 会话提升是运行时内存结构（随会话存档），与配置三桶分离；展示层必须区分「配置永久 allow」与「会话提升 always」。
