# R-PRM 权限与安全

权限系统回答一个问题：**这次工具调用允不允许执行**。三层结构——配置三桶（持久）、会话提升（临时）、固定安全默认（兜底）。

## 需求点

- **R-PRM-01 三桶**：`allow / reject / ask` 三桶；桶内是「键 → 规则」映射；未命中任何规则的调用走固定默认 **ask**（不可配置关闭）。
- **R-PRM-02 规则形态（v3）**：每条规则 `{ whole: boolean, patterns: string[] }`——whole=true 整键生效（patterns 仅作取消整选后的恢复内容）；whole=false 按 patterns 匹配，**空 patterns = 键存在但不命中**（编辑空选态）。
- **R-PRM-03 键的两类**：内建工具名（patterns = 主参数模式：shell→command、文件类→path）；MCP 服务键 `mcp:<服务名>`（patterns = 服务内部工具名/通配，**工具启用匹配，永不涉参数**；必须带前缀，裸名键加载期拒绝）。
- **R-PRM-04 服务键归属**：服务键按工具注册期身份匹配（不解析 LLM 可见名）；服务名零约束；项目级停用/授权随 `.dogegg/` 共享。
- **R-PRM-05 判定优先级**：reject > 会话提升 > ask > allow > 默认 ask。「allow 整组 + ask 勾选个别」可行；反向（ask 整组 + allow 个别）不成立。
- **R-PRM-06 路径锚点**：内建 path 工具的模式必须显式作用域（`./` cwd、`~/` 主目录、盘符绝对、`*` 从根）——裸模式加载即拒绝；`*` 单段、`**` 跨段。
- **R-PRM-07 realpath 防逃逸**：参数按真实位置（realpath）判定——cwd 内链接指向 cwd 外 → 失配落 ask。
- **R-PRM-08 审批流**：落 ask 的调用弹审批，四档决策——本次允许 / 始终允许（整工具提升）/ 对此范围不再询问（范围提升，路径解析为绝对）/ 拒绝。
- **R-PRM-09 会话提升**：提升只在本会话生效（可撤销、新建会话清空、随会话存档）；优先级压过 ask 规则，但 reject 恒压过提升。
- **R-PRM-10 编辑两端**：TUI /config 与 WebUI 设置同等编辑能力——整选开关、逐模式编辑、服务键勾选细化、空选可表达。
- **R-PRM-11 格式演进**：配置只支持当前 v3 格式；旧格式（扁平条目/字符串数组/裸服务键）加载报错并指引文档（ADR-0013 不兼容原则）。

## 边界与立法

- 命令模式是「便利而非安全边界」（通配可命中命令链）——危险命令用 ask/reject 显式压制。
- 固定安全默认（未列出 → ask）不可被任何配置拆掉。
- 语义决策详见 ADR-0010（匹配语义）/ 0012（服务键身份匹配）/ 0013（v3 结构化 + 不兼容原则）。
