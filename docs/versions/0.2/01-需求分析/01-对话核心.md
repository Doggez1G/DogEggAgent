# R-DLG 对话核心

与 LLM 的多轮对话循环是产品核心：用户提交一条消息，agent 驱动模型思考、调用工具、观察结果、继续思考，直到产出最终回复。所有其它功能域（工具、权限、MCP、技能）都是这条循环的参与者。

## 状态机

一轮对话自始至终由状态机驱动，状态对 UI 全程可见（状态栏 / 信息面板）：

```
idle → thinking → responding → tool_calling → waiting_permission → executing
                                                                    ↓（结果回填）
                 thinking ←────────────────────────────────────────────────┘
任何状态 → finished / cancelled / error；thinking 中 context 超 80% → compacting
```

- `thinking`：已把 context 发给模型，等待产出（可能流式思考、可能直接工具调用）。
- `responding`：模型在产出面向用户的正文（流式）。
- `tool_calling`：模型请求了工具、参数流式生成中。
- `waiting_permission`：工具需要审批，暂停等用户决策。
- `executing`：工具正在本地/远程执行。
- 结果回填后回到 `thinking` 继续下一轮，直到模型产出纯文本回复 → `finished`。

## 需求点

### R-DLG-01 流式响应

模型产出必须实时流式呈现，用户不需要等完整回复。

- 正文（面向用户的回答）与思考内容（reasoning）是**两条独立流**，UI 分别渲染——思考内容以可折叠的灰色块呈现，正文是正式回复。
- 思考流是否存在取决于模型（reasoning 模型才有），非思考模型只有正文流。
- 流式过程中状态栏与 token 估算实时跳动（估算器按 context 内容现算，不等 API 返回）。

### R-DLG-02 多轮上下文（R1/R2 双写立法）

- **history（对话历史）**：完整保存用户消息、助手消息、每次工具调用与结果，**永不淘汰**——它是"发生过什么"的唯一完整档案，随会话持久化。
- **context（模型上下文）**：每轮实际发给模型的内容视图。与 history 分离的原因：压缩只重写 context，history 原文永远可查。
- 每轮发给模型的 context 还包含：系统提示（含 skills 广告段、shell 环境引导段）与全部工具的 schema。

### R-DLG-03 工具调用循环

- 模型在回复中发起工具调用（可一次多个）→ 每个工具依次经过权限网关（见 05-权限与安全）→ 通过后执行 → 执行结果作为工具消息回填模型 → 模型继续思考。
- 一轮对话可以包含任意多次工具调用（受 R-DLG-08 上限约束），这是 agent「边干边看」的工作方式：读文件 → 改文件 → 跑测试 → 再改。
- 工具执行出错不终止对话：错误信息作为工具结果回填，模型自行决定重试、换路或向用户说明。

### R-DLG-04 上下文压缩（自动 + 手动）

- **触发**：context 估算超过模型窗口的 **80%** 时自动触发；用户也可随时手动 `/compact`。
- **语义**：把当前完整 context 交给模型做一次「任务交接总结」——结构化提示词要求保留：任务目标、已完成步骤、涉及文件路径、重要决策及理由、未完成事项、用户偏好。总结替换整个 context，成为一条带标注的用户角色消息。
- **立法**（ADR-0011）：无保留尾巴、无淘汰、无硬丢弃——因为总结是模型继续工作的唯一上下文，淘汰等于失忆；history 原文不受影响，摘要丢失的信息可人工回查。
- 压缩计数与前后 token 对比在信息面板可见；摘要失败 → 该轮以 error 收尾（诚实失败），不做降级静默处理。

### R-DLG-05 取消

- 对话进行中（thinking/responding/tool_calling/executing）用户可随时取消：正在执行的本地工具收到 abort 信号（shell 会终止整个进程树），循环立即终止，状态回落 `cancelled`。
- 取消不回填任何伪造结果——已产生的部分输出保留可见。

### R-DLG-06 错误重试

- LLM 请求失败或轮次异常时，原始提交文本**自动回填输入框**，用户直接重试，不需要重新打字。

### R-DLG-07 迭代上限

- `maxIterations` 限制一轮对话内的「模型→工具→模型」循环轮数：`-1` 无限（默认，靠用户取消兜底）；正整数供无人值守批处理防跑飞；`0` 非法。

### R-DLG-08 请求重试

- `maxRetries`（默认 3）控制对 LLM 的单次请求在失败后的重试次数（网络抖动、限流等瞬态错误）。

### R-DLG-09 会话标题

- 首轮对话结束后自动生成会话标题（单独一次 LLM 调用，限长 ≤32 字；reasoning 模型单独压低输出预算）。
- 手动命名（`/rename` 或界面铅笔按钮）优先于自动标题，且不会被子sequent自动命名覆盖。
- 标题同步到侧栏会话列表与状态栏。

## 验收场景

1. 提交「帮我读 a.txt 并总结」→ 模型发起 read_file → 权限放行 → 结果回填 → 模型输出总结 → finished。全程正文/思考流式可见。
2. 长对话 token 到 81% → 自动压缩，信息面板显示压缩前后 token 与次数；继续对话模型仍知道任务目标（来自交接总结）。
3. 对话中按取消 → 工具进程终止、状态 cancelled、输入框可立即提交新消息。
