# R-LLM 模型接入

通过 OpenAI 兼容协议接入任意模型服务商（GLM、DeepSeek、OpenAI、本地端点等），多 provider 多 model 可配，随时切换。

## 需求点

- **R-LLM-01 多 provider**：`providers` 数组配置任意多个服务商，每个含 `name / protocol / baseURL / apiKey / models[]`。
- **R-LLM-02 协议**：当前仅支持 `openai` 兼容协议（`/chat/completions` + `tools` 参数）；protocol 字段为后续协议预留枚举位。
- **R-LLM-03 模型条目**：每个 model 含 `name / contextWindow / maxOutput / reasoning`——reasoning 标记的模型请求时自动调低 maxOutput（思考 token 预算）。
- **R-LLM-04 默认模型**：`defaultProvider` + `defaultModel` 指定对话使用的模型；加载期缺省取第一个 provider 的第一个模型。
- **R-LLM-05 流式**：响应走 SSE 流式，正文与思考（`reasoning_content`）分通道产出。
- **R-LLM-06 工具声明**：每次请求携带注册表全部工具的 function schema（`schemas()` 现算——注册表变化即时反映）。
- **R-LLM-07 完整性判定**：`isConfigured` = 至少一个 provider 有 baseURL/apiKey 且默认模型可解析——决定能否对话，与「字段允许暂空」的编辑流程解耦。
- **R-LLM-08 配置编辑**：provider/model 支持自由创建节点后逐字段填写（校验层放宽，完整性由 isConfigured 把关）。

## 边界与立法

- 字段校验放宽是刻意的：编辑器允许先建节点再补内容；能对话与否由 isConfigured 判定。
- 配置格式演进不兼容（ADR-0013）：旧格式加载报错并指引文档。
- 切换 provider/model 即时生效（状态栏与右侧面板刷新，无需重开会话）。
