# R-LLM 模型接入

通过 OpenAI 兼容协议接入任意模型服务商（GLM、DeepSeek、OpenAI、本地端点等）。多 provider、多 model 可配，随时切换——模型接入层是可替换的，其余全部功能域不感知具体厂商。

## 需求点

### R-LLM-01 多 provider 配置

- `providers` 数组配置任意多个服务商，每个 provider 包含：`name`（显示与引用名）、`protocol`（协议，当前仅 `openai`）、`baseURL`（API 端点，如 GLM 的 `https://open.bigmodel.cn/api/paas/v4`）、`apiKey`、`models[]`（该服务商下可用的模型列表）。
- 多 provider 并存，`/model` 或 /config 随时切换；不同 provider 的模型混用互不影响。

### R-LLM-02 协议

- 当前仅支持 `openai` 兼容协议：`/chat/completions` 端点、`tools` 参数声明工具、SSE 流式响应。
- `protocol` 字段是枚举预留位（`openai` 是当前唯一合法值）——未来新增协议（如 Anthropic 原生）时在此扩展，并注册对应的 LLM client 实现，其余功能域不感知。

### R-LLM-03 模型条目

- 每个 model 声明 `name`、`contextWindow`（上下文窗口，驱动压缩阈值计算）、`maxOutput`（单次输出上限）、`reasoning`（是否思考模型）。
- `reasoning: true` 的模型：请求参数自动调整（思考占用输出预算），思考内容走独立通道渲染。

### R-LLM-04 默认模型

- `defaultProvider` + `defaultModel` 指定对话使用的模型。
- 加载期缺省规则：未显式指定时取第一个 provider 的第一个模型；空配置（无 provider）保持无默认值——程序照常启动，引导用户去 /config 配置。

### R-LLM-05 流式双通道

- 响应走 SSE 流式：正文增量（text_delta）与思考增量（`reasoning_content`，即 thought_delta）分通道产出，UI 双通道渲染。
- 流式中断/失败按 R-DLG-06 处理。

### R-LLM-06 工具声明

- 每次请求携带注册表**当前全部工具**的 function schema（`schemas()` 每次现算，不缓存快照）——MCP 工具注册/摘除后，下一次请求即时反映，模型永远看到当前可用的工具集。

### R-LLM-07 完整性判定（isConfigured）

- 「能对话」的判定：至少一个 provider 的 baseURL/apiKey 完整，且 defaultProvider/defaultModel 能解析到非空模型。
- 未配置时程序照常启动（空配置引导去 /config），对话入口给出明确提示。

### R-LLM-08 编辑期放宽

- 配置编辑器允许「先建节点、后补字段」：name/baseURL/apiKey/models 允许暂时为空——校验层放宽是刻意的，能对话与否由 R-LLM-07 的 isConfigured 把关，两者解耦。

## 边界与立法

- 配置格式演进不兼容（ADR-0013）：旧格式加载报错并指引文档。
- 需求分析只约定「OpenAI 兼容」这一协议契约；不同厂商对参数的私有扩展（如思考通道字段名）由接入层适配，不外溢。
