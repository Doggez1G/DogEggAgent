# R-MCP 工具系统-MCP

接入 MCP（Model Context Protocol）服务器，把外部工具纳入统一的工具/权限/展示体系。用户不写代码即可扩展 agent 能力——配一个 server，它的全部工具就出现在模型可用清单里。

## 需求点

### R-MCP-01 配置与作用域

- server 配置两个落点：全局 `~/.dogegg/config.json` 的 `mcpServers` 字段（所有项目可用），项目 `.dogegg/.mcp.json`（随仓库共享，同名 server 项目覆盖全局）。
- 每个 server：`name`（唯一标识，零字符约束——见 R-MCP-09）、`enabled`（停用不删除，调试时保留配置）、`transport`（stdio 或 http，见 R-MCP-02）。

### R-MCP-02 传输类型

- **stdio**：本地子进程——`command` + `args`（JSON 数组）+ `env`（JSON 对象，叠加在默认安全环境之上）；agent 通过 stdin/stdout 与其通信。
- **http**：远程 Streamable HTTP 服务——`url` + `headers`（如 Authorization）。

### R-MCP-03 连接生命周期

- 状态机：`starting`（连接中）→ `running`（可用）/ `error`（失败，含人话原因）；停用/删除 → `stopped`。
- 配置变化（增删改/启停）触发 **diff 重建**：对比期望状态与运行状态，停掉已移除/停用/配置变化的连接，启动新增连接——无变化时幂等空转不广播。
- 状态实时广播（mcp_list），面板与设置页实时可见；全部生命周期异步，不阻塞对话消息循环。

### R-MCP-04 工具注册与合规

- 服务的每个工具**独立注册**为 `mcp__<server>__<tool>`（命名空间防撞 + 权限可通配）。
- 注册走统一合规关口（见 03-工具系统-内建 R-TLB-08）：标签不合规 → 整体哈希 `h-<hash>`；与已有工具冲突 → 可见失败。
- 服务声明的**原生 JSON Schema 原样透传**给模型——参数校验权在服务，agent 不做本地强校验。

### R-MCP-05 单服务隔离

- 任一服务的启动/注册失败只影响自身：状态落 error（面板可见原因），其余服务照常；绝不因一个坏 server 拖垮对话或其它 server。

### R-MCP-06 冲突可见

- 注册标签与已有工具冲突（含内建工具）→ 后注册方失败并提示改服务名——**绝不静默覆盖**（静默覆盖会让先注册的工具无声失联）。

### R-MCP-07 来源身份

- 每个 MCP 工具注册时记录身份 `{ server, name }`：server = 配置服务名，name = 服务侧声明的内部工具名。
- 身份是权限服务键匹配（R-PRM-04）与 UI 分组展示的唯一事实源——任何需要知道「这个工具来自哪个服务」的地方都查身份，**从不解析 LLM 可见名**（哈希标签不可读也无妨）。

### R-MCP-08 启停与 CRUD

- `enabled` 停用 = 断开连接 + 摘除工具，配置保留（调试/临时关闭）。
- 增删改启停经 /mcp 面板（TUI 表单视图）或 WebUI 设置（状态卡片），两端走同一套消息。

### R-MCP-09 服务键权限

- 权限桶键支持 `mcp:<服务名>`（必须带前缀，裸服务名键加载期拒绝）：`whole: true` 整组生效（服务升级新增工具自动覆盖）；`whole: false` 按 patterns 匹配服务内部工具名/通配——**工具启用匹配，永不涉及执行参数**。
- 服务名零字符约束：前缀键与内建工具名、其它服务名无歧义。
- 匹配按注册期身份（R-MCP-07），服务离线时规则保留、重连自动生效。

### R-MCP-10 调用

- 模型按标签调用 → 适配器经归属转发给服务（向服务发送的是**服务侧原始工具名**，不是命名空间标签）→ 结果文本回填模型。
- 单次调用 60s 超时；服务离线/未注册 → 结果报错回模型（不终止对话）。

## 边界与立法

- 服务名零约束是立法（`mcp:` 前缀隔离保证无歧义）；唯一拒绝场景：裸服务名键与内建工具同名（加载期拒绝，见 05-权限与安全 R-PRM-03）。
- 工具数量上限、服务级元工具聚合（把 N 个工具折叠成 1 个）均为**非目标**——原生 JSON Schema 透传优先。
- 项目级 server 定义于 `.dogegg/.mcp.json`，随仓库共享（注意：.gitignore 现状忽略 `.dogegg/`，共享需自行调整 ignore，属部署侧决策）。
