# R-TLB 工具系统-内建

7 个内建工具覆盖「读写文件 + 执行命令 + 探索目录」的基本面。全部实现同一契约、注册进同一注册表、走同一权限网关——MCP 等外部工具接入时也遵循这套契约（见 04-工具系统-MCP）。

## 工作原理概述

**契约即边界。** 每个工具是一个实现 `Tool` 接口的对象：`name`（LLM 可见名）、`description`（模型判断何时用的依据）、`schema`（zod，校验模型给出的参数）、`parameters`（暴露给模型的 OpenAI JSON Schema）、`execute(args, ctx)`。`execute` 的返回值是 `{ content }`（成功）或 `{ error }`（失败）——**错误是给模型看的信息，不是异常**：工具失败会作为 tool 消息回填，模型自行决定重试、换路或向用户说明，对话永不因工具失败中断。`ctx` 携带 `cwd`（当前工作目录，/cd 后变化）、`signal`（取消信号）、`shellProgram` 与 `shellTimeoutMs`（仅 shell 使用）。

**执行链路。** 模型的 tool_call 到达后按固定顺序处理：

1. JSON.parse arguments → zod schema 校验；
2. 权限分类（路径类参数先经 realpath 归一，见 05-权限与安全）；
3. 广播 `tool_start` → `execute` → 输出治理截断（8000 字符 cap）→ 广播 `tool_end`（成功/失败都发，带 error 标记）；
4. tool 消息回填 context/history。

这条链对内建与 MCP 工具完全一致——UI 渲染层不需要区分工具来源。

**探索漏斗与共享底座。** ls（看一层）→ glob（按名筛）→ grep（按内容搜）构成探索漏斗，后两者共享同一个递归遍历器 walker：

- 迭代式 DFS，readdir 排序保证跨平台确定性产出；
- 按目录名黑名单剪枝（IGNORED_DIRS：node_modules/.git/dist/build/out/.next/coverage/.dogegg——覆盖构建产物 90% 痛点且零解析成本）；
- symlink 一律跳过（目录 symlink 成环、文件 symlink 逃逸 root，都会让「遍历范围 = root 子树」的隐含承诺失效）；
- 目录间隙检查取消信号；
- gitignore 过滤以谓词形式叠加在 walker 上（glob/grep 读会话 cwd 的 .gitignore 编译成 matcher；ls 刻意不受黑名单/gitignore 约束——用户点名看的目录应如实呈现）。

**输出治理的确定性上界。** 工具回执会整体进入 context，无上界的输出（一次性 cat 大文件、大仓库的宽泛搜索）等于把上下文窗口的主动权交给文件系统。治理分两层：

- 通用层：tool-executor 对所有回执 8000 字符截断，尾行标注「…（输出过长，已截断）」；
- 工具内层：ls 500 条、glob 100 命中、grep 四层递进——截断处一律注明「还剩多少 + 怎么办」，让模型能自行收窄而不是重试同一模式。

**注册表是唯一关口。** 工具注册/摘除只发生在 ToolRegistry：名称合规转换、冲突可见失败、身份记录三件事在一个 `register()` 里完成（见 R-TLB-08）。`schemas()` 每次现算——注册表变化即时反映到模型请求。

## 通用需求（所有内建工具共享）

### R-TLB-00 统一契约与上下文注入

**需求动机**：如果每个工具自行处理路径解析、取消、输出截断，行为必然漂移（有的跟 cwd 有的不跟、有的能取消有的不能）。统一契约让「工具怎么被调用」只有一个答案。

**详细行为**：

- `execute(args, ctx)` 中 `args` 已过 zod 校验；参数校验失败（模型输出非法参数）→ 回填「参数校验失败」，不执行工具。
- `ctx.cwd` 是会话工作目录——所有文件类工具以 `join(cwd, path)` 解析相对路径，`/cd` 切换后天然生效。
- `ctx.signal` 是轮次 AbortController 的 signal——shell 挂 abort 监听杀进程树，遍历器在目录间隙 throwIfAborted。
- `ctx.shellProgram`/`ctx.shellTimeoutMs` 仅 shell 消费（缺省按平台解析 / 120s）。

**边界与失败模式**：

- 工具内部异常被 executor 兜底 catch 转 tool_end（error 标记）——保证 tool_start 总有配对的 tool_end。
- `{ error }` 返回值回填为 `ERROR: <原因>` 形式的 tool 消息（内容仍可被模型读取分析）。

**场景走查**：模型在 /cd 到 `D:\work\app` 后调 read_file('src/index.ts') → 实际读取 `D:\work\app\src\index.ts`；同一调用在取消后立即中断。

### R-TLB-01 read_file 读取文件

**需求动机**：读文件是 agent 的第一高频操作——理解代码、检查修改结果、读取技能指令都依赖它。需要保证权限按真实位置判定（符号链接不能成为越界读取的漏洞）。

**详细行为**：

- 读取 `join(cwd, path)` 全文以 utf8 返回给模型；路径支持相对（cwd）/绝对。
- 权限按「真实位置」判定：权限层在匹配前把 path 参数经 `realpathSync` 归一——符号链接指向 cwd 外时词法匹配会被骗，真实位置越界即失配落 ask（防逃逸，ADR-0010）。
- read_file 出厂默认在 allow 桶（whole: true）——只读安全且探索顺畅的前提。

**边界与失败模式**：

- 目标不存在 → error「ENOENT…」回模型，模型可换 glob/ls 重新定位。
- 目标在权限 allow 规则路径内但经 symlink 实际在外 → 判定落 ask 而非静默放行（fail-closed）。
- 二进制文件会整份按 utf8 读出（read_file 无内容嗅探——grep 侧才有二进制探测），输出治理层兜底截断。

**场景走查**：模型调 `read_file { path: 'docs/api.md' }` → cwd 内真实文件 → 内容直接回填 → 模型据此回答；`read_file { path: 'link-to-secrets' }`（symlink 指向 cwd 外）→ 权限层 realpath 发现越界 → 落 ask 弹审批。

### R-TLB-02 write_file 写入文件

**需求动机**：整文件写入是「从零生成」的路径（新建组件、生成配置）。新建文件没有「真实位置」可 realpath——权限必须按「将落入的真实父目录 + 文件名」判定，否则新建路径能绕过路径规则。

**详细行为**：

- 以 utf8 整体覆写/创建 `join(cwd, path)`，内容来自参数 `content`（可创建多级父目录）。
- 覆盖已有文件是显式行为：内容整体替换，不做合并——需要局部修改时应走 edit_file。
- 权限判定：参数归一时目标不存在 → 真实父目录 realpath + 文件名拼接（`realTargetPath` 的第二分支）；父目录也不存在 → 词法解析兜底。
- 出厂默认在 ask 桶（whole: true）——写入需审批。

**边界与失败模式**：

- 写入失败（只读目录/磁盘满）→ error 回模型。
- 「错误覆盖」的防线不是工具而是权限 ask + 模型先读后写的习惯（description 引导）。
- `D:\work\app\link-dir\x.txt` 中 link-dir 指向 cwd 外 → 父目录 realpath 越界 → 落 ask。

**场景走查**：模型调 `write_file { path: 'src/new-util.ts', content: '...' }` → ask 审批（新建文件也走完整判定）→ 用户「对此范围不再询问」→ 范围模式 `./src/**` 落库，同目录后续写入免审批。

### R-TLB-03 edit_file 精准编辑

**需求动机**：LLM 重写整个文件容易丢内容（长文件 token 限制 + 幻觉），精准的「旧片段 → 新片段」替换是 code agent 的核心约束——旧片段逐字符匹配天然限制了改动范围。

**详细行为**：

- 参数 `path` + `old_string` + `new_string`，old_string 需与文件内容**逐字符一致**（含缩进/空白）。
- 执行：读全文 → `old_string` 不存在 → `{ error: 'old_string 未找到' }`（模型需先 read_file 核对内容再改）→ 存在则**替换首次出现的那一处**并写回。
- 同时计算锚点——old_string 在原文件中的 1-based 起始行（`text.slice(0, indexOf).split('\n').length`）。
- 回执 `已替换 1 处（原第 N 行起）`一举两得：模型知道改动落点便于后续连续编辑；UI（shared/tool-display）解析该锚点给 diff 标真实行号（旧会话回放无锚点时不标行号，不编造坐标）。
- 模型侧约束：想改多处需提供带更多上下文的 old_string 或多次调用——工具本身不强制唯一命中，替换第一处并如实回执。

**边界与失败模式**：

- old_string 在文件中出现多次时，若命中位置与模型意图不符，模型可根据回执行号自行修正（扩大上下文重试）。
- 「未找到」是最高频失败——回执明确指示「先读再改」。
- 权限按 path 主参数判定（与 read_file 同族，realpath 归一）。

**场景走查**：模型调 `edit_file { path: 'src/index.ts', old_string: 'const port = 3000', new_string: 'const port = Number(process.env.PORT ?? 3000)' }` → 首处替换成功，回执「已替换 1 处（原第 12 行起）」→ UI 展开块渲染 +/- diff 并标注第 12 行。

### R-TLB-04 shell 执行命令

**需求动机**：跑测试、装依赖、git 操作都要 shell。但模型的 shell 先验来自训练数据（Unix 偏置）——Windows 上不告知实际解释器就会频繁写错语法（`ls`/`&&`/`$VAR` 在 cmd 里全错）。且交互式常驻进程（dev server）不设超时会卡死整轮对话。

**详细行为**：

- **解释器选择**（resolveShell）：配置的 `shellProgram`（config 顶层键）映射为 `{ program, flag, kind }`——cmd→`cmd /c`、powershell→`powershell -Command`、pwsh→`pwsh -Command`、bash/sh→`-c`；缺省按平台（win: cmd，其它: bash）。统一 `spawn(program, [flag, command])` 显式指定，不用 `{ shell: true }`。
- **PATH 扫描校验**（detectShells）：配置值必须在本机扫描结果内（Windows 按 PATH×PATHEXT 找 powershell.exe/pwsh.exe/bash.exe，cmd 视为必然可用；Unix 找 bash），否则回退平台默认——配置了不存在的 bash 不会导致全部命令失败。含非 ASCII 的值（误存占位文本）同样回退；未知程序名（nu/fish）不猜测语义回退默认；扫描结果运行期缓存。
- **执行**：`spawn(program, [flag, command], { cwd, detached: !isWin })`（POSIX detached 用于进程组 kill），stdout/stderr 合并累积。
- **超时**：120s（ctx.shellTimeoutMs 可注入）——超时杀整个进程树（Windows `taskkill /PID <pid> /T /F`；POSIX `process.kill(-pid, SIGKILL)` 杀 detached 进程组），close 事件走正常回填路径，回执 = `exit=<code>（命令超过 120s 未结束，已终止进程树；如需长任务请放后台并轮询输出）\n<已有输出>`。
- **环境引导注入**：系统提示追加「## Shell 环境」段（`shellGuidance`）——平台、当前 shell 种类与 `program flag`、该 kind 的语法要点（cmd：没有 ls/grep/cat，环境变量 `%VAR%`，复杂逻辑拆分或 node -e；powershell 5.1：不支持 `&&` `||`，用分号或 `if ($?)`；pwsh 7：支持 `&&`；bash/sh：标准 POSIX）。每类要点宁少勿错——只列确定性高的事实。
- 取消时 killTree 挂在 ctx.signal 的 abort 上。权限按 command 主参数平文本通配匹配（`git *`，见 05-权限与安全）。

**边界与失败模式**：

- spawn 失败（解释器损毁等极端）→ `{ error }` 回模型。
- 超时回执自带「已有输出 + 超时说明」，模型可据此调整（改后台轮询）。
- 命令 exit≠0 是正常回填（UI 显示 ✕ 退出 N），不是工具错误——命令失败与工具失败对模型是两种信息。

**场景走查**：Windows + shellProgram=pwsh → 模型看到「当前 shell 为 pwsh，支持 &&」→ 调 `shell { command: 'pnpm test && pnpm build' }` → 120s 内完成 → 回执 `exit=0\n<输出>`，UI 折叠头显示「$ pnpm test && pnpm build · N 行输出」。

### R-TLB-05 ls 目录列举

**需求动机**：模型需要先看项目结构再决定读什么——一层目录视图（目录在前 + 文件大小）是最快的拓扑感知方式；不代理 shell 的 dir/ls，保证跨平台结构化输出。

**详细行为**：

- 列出 `join(cwd, path)` 一层内容：目录条目加 `/` 后缀在前、文件条目附人类可读大小（B/KB/MB）在后，各自按名排序；单层不递归（递归找文件是 glob 的事）。
- 隐藏文件（`.` 开头）正常显示——agent 需要看 .github/.gitignore 等。
- 条目封顶 500（MAX_ENTRIES），超出截断并注明「仅显示前 500 项，共 N 项」。
- **刻意不受黑名单/gitignore 约束**：用户点名看的目录应如实呈现。
- symlink 条目跳过（与 walker 同一立场）。

**边界与失败模式**：

- 目录不存在 → error「无法读取目录 …」回模型；空目录回「（空目录）」。
- 大小获取失败（竞态删除）不致命——条目仍列出，大小显示 `?`。
- 权限判定按 path 主参数（read_file 同族）。

**场景走查**：模型调 `ls { path: '.' }` → 回执 `src/\n docs/\n package.json  1.2 KB\n …` → 据此决定下一步 read_file 哪个文件。

### R-TLB-06 glob 模式筛文件

**需求动机**：「找出所有测试文件」「找配置在哪」需要按文件名模式递归搜索——只匹配路径不读内容（按内容搜是 grep 的事），大仓库的命中数必须有上界。

**详细行为**：

- 参数 `pattern`（必填）+ `path`（可选起点目录，缺省 cwd 根）。
- pattern 经 bridge 的 `globToRegExp` 编译（与权限参数化规则**共用一份实现**，一份实现三端永不漂移）：`**` 跨任意段（`**/x` 含根级 x、`src/**` 不匹配 src 本身）、`*` 单段内任意（不跨 `/`）、`?` 单字符、其余字面量自动转义；模式非法 → error 回模型。
- 遍历用共享 walker：黑名单剪枝 + symlink 跳过 + `.gitignore`（会话 cwd 根）过滤 + 取消信号；matcher 编译一次、遍历内复用。
- 命中封顶 100（MAX_MATCHES），超出截断并提示「请收窄 pattern」。
- 产出为 posix 相对路径。

**边界与失败模式**：

- 根目录不存在显式报错（「路径不存在：…」）——区分「模式写错」与「路径写错」，否则模型侧不可判别。
- walker 对单目录读失败是「跳过继续」语义（探索不因单点失败中断）。
- 权限按 path 主参数判定（给了 path 就判 path，缺省判 cwd）。

**场景走查**：模型调 `glob { pattern: '**/*.test.ts' }` → 回执 37 个相对路径 → 再对其中三个 read_file。

### R-TLB-07 grep 内容搜索

**需求动机**：定位「某个函数在哪定义」「TODO 在哪」需要跨文件内容搜索，且必须跨平台（不依赖 shell grep——Windows 没有）。搜索结果天然不可控，需要最严格的输出治理。

**详细行为**：

- 参数：`pattern`（正则，逐行匹配）、`path`（可选，文件或目录）、`glob`（可选文件名过滤）、`case_insensitive`、`output_mode`（content=命中行缺省 / files_with_matches=只列文件 / count=每文件命中数——description 引导「先粗后细：大搜索先用 files_with_matches 锁定文件再精搜」）。
- 正则非法 → error 指明「无效的正则表达式…请修正后重试」。
- 回执格式 `相对路径:行号: 内容`（content 模式）是**回执即契约**——UI formatter 按此前缀解析展示，格式改动必须工具与 ui/shared/tool-display 两处同步。
- **输出治理四层**：
  - ① 单行截断 500 字符（minified 行防护）；
  - ② 单文件命中封顶 20（超出停止扫本文件，附「该文件还有 N 处未显示」——补数走全文重计）；
  - ③ 总命中封顶 100（提前结束遍历）；
  - ④ 总字符 cap 8000（写满即置 truncated，后续写入拒绝）。
- 附带防护：超过 1MB 的文件跳过（回执注明跳过数）；前 8KB 探测 NUL 字节判二进制并跳过；`\r` 归一（Windows 行尾不影响命中与行号）。
- glob 过滤对「完整相对路径」与「文件名」任一命中即通过（`*.ts` 应匹配 src/x.ts 的用户直觉）。
- 遍历底座与 glob 相同（walker + gitignore + 取消信号）；单文件模式（path 指向文件）直接读该文件。

**边界与失败模式**：

- 单文件读取失败（竞态删除/权限）跳过不致命。
- 无命中回「（无命中，已跳过 N 个超大文件）」；任何截断层触发都附「请用更具体的 pattern 或 glob 参数收窄」。
- 权限按 path 主参数判定。

**场景走查**：模型调 `grep { pattern: 'formatDate', glob: '*.ts', output_mode: 'files_with_matches' }` → 3 个文件 → 再 content 模式精搜其一 → `src/utils/date.ts:12: export function formatDate(…)`。

### R-TLB-08 统一注册表与合规关口（ADR-0012）

**需求动机**：LLM 供应商对函数名有硬约束（字符集 `[a-zA-Z0-9_-]`、长度 ≤64，OpenAI 系与 Anthropic 系一致），校验发生在 API 请求层且**拒绝整个请求**。一个命名非法的 MCP server 如果把非法名直接发给模型，会让每一次对话请求整体 400——关口必须设在注册层。

**详细行为**：

- 所有工具在唯一注册表注册/摘除，`register(tool, identity)` 同时做三件事：
  1. **名称合规转换**——原名合规则原样注册；不合规整体哈希为 `h-<sha256 前 12 位 hex>` 确定性标签（同名必同标签），变换落在 Tool 对象本身（name 字段被改写），保证 `schemas()` 发出的名字必然合规；
  2. **冲突可见失败**——目标标签已被占用时抛错（「工具注册名冲突：X 已被占用——请调整来源命名（如 /mcp 中的服务名）」），绝不静默覆盖（静默顶掉会让先注册的工具无声失联）；
  3. **身份记录**——每个工具带 ToolIdentity（`{ kind: 'builtin' }` 或 `{ kind: 'mcp', server, name }`），与工具同增同删。
- 身份是「工具从哪来」的唯一事实源：权限服务键匹配、UI 分组展示、MCP 按归属摘除（`labelsWhere` 按身份找标签——哈希标签不带 `mcp__` 前缀，前缀扫描会漏删）都查这里，**从不解析 LLM 可见名**。
- `schemas()` 每次现算；`unregister` 不存在时静默（幂等）。

**边界与失败模式**：

- MCP 服务注册中途冲突 → 该服务整体摘除（先摘后挂 + 失败回滚），其它服务照常。
- 注册表不变量「凡注册必有身份」——`listTools()` 的 `?? builtin` 兜底仅为类型完备。

**场景走查**：某 MCP server 声明内部工具名 `浏览器.导航` → 注册关口哈希为 `h-3f9a2b7c1d0e` → 模型看到并调用该标签 → 执行时按身份转发原始名给服务（见 R-MCP-10）。

## 边界与立法

- 工具集是封闭枚举：新增内建工具需要实现 Tool 契约 + 注册 + 权限主参数登记（`PRIMARY_SPECIFIER`——非 path 主参数必须显式声明）+ 文档同步。
- MCP 等外部工具**不修改**内建工具集，只向注册表追加（见 04-工具系统-MCP）。
- 工具回执格式（shell 的 `exit=` 前缀、grep 的 `路径:行号: `、edit_file 的行号锚点）是 UI 解析契约——改动必须工具与 ui/shared/tool-display 两处同步。
