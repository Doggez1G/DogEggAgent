## 域机制概览

**契约即边界。** 每个工具是一个实现 `Tool` 接口的对象：`name`（LLM 可见名）、`description`（模型判断何时用的依据）、`schema`（zod，校验模型给出的参数）、`parameters`（暴露给模型的 OpenAI JSON Schema）、`execute(args, ctx)`。`execute` 的返回值是 `{ content }`（成功）或 `{ error }`（失败）——**错误是给模型看的信息，不是异常**：工具失败会作为 tool 消息回填，模型自行决定重试、换路或向用户说明，对话永不因工具失败中断。`ctx` 携带 `cwd`（当前工作目录，/cd 后变化）、`signal`（取消信号）、`shellProgram` 与 `shellTimeoutMs`（仅 shell 使用）。

**执行链路。** 模型的 tool_call 到达后按固定顺序处理：① JSON.parse arguments → zod schema 校验；② 权限分类（路径类参数先经 realpath 归一，见 05-权限与安全）；③ 广播 `tool_start` → `execute` → 输出治理截断（8000 字符 cap）→ 广播 `tool_end`（成功/失败都发，带 error 标记）；④ tool 消息回填 context/history。这条链对内建与 MCP 工具完全一致——UI 渲染层不需要区分工具来源。

**探索漏斗与共享底座。** ls（看一层）→ glob（按名筛）→ grep（按内容搜）构成探索漏斗，后两者共享同一个递归遍历器 walker：迭代式 DFS，readdir 排序保证跨平台确定性产出；按目录名黑名单剪枝（IGNORED_DIRS：node_modules/.git/dist/build/out/.next/coverage/.dogegg——覆盖构建产物 90% 痛点且零解析成本）；symlink 一律跳过（目录 symlink 成环、文件 symlink 逃逸 root，都会让「遍历范围 = root 子树」的隐含承诺失效）；目录间隙检查取消信号；gitignore 过滤以谓词形式叠加在 walker 上（glob/grep 读会话 cwd 的 .gitignore 编译成 matcher；ls 刻意不受黑名单/gitignore 约束——用户点名看的目录应如实呈现）。

**输出治理的确定性上界。** 工具回执会整体进入 context，无上界的输出（一次性 cat 大文件、大仓库的宽泛搜索）等于把上下文窗口的主动权交给文件系统。治理分两层：通用层——tool-executor 对所有回执 8000 字符截断，尾行标注「…（输出过长，已截断）」；工具内层——ls 500 条、glob 100 命中、grep 四层递进——截断处一律注明「还剩多少 + 怎么办」，让模型能自行收窄而不是重试同一模式。

**注册表是唯一关口。** 工具注册/摘除只发生在 ToolRegistry：名称合规转换、冲突可见失败、身份记录三件事在一个 `register()` 里完成（见 R-TLB-08）。`schemas()` 每次现算——注册表变化即时反映到模型请求。

**边界与立法。** 工具集是封闭枚举：新增内建工具需要实现 Tool 契约 + 注册 + 权限主参数登记（`PRIMARY_SPECIFIER`——非 path 主参数必须显式声明）+ 文档同步。MCP 等外部工具**不修改**内建工具集，只向注册表追加（见 04-工具系统-MCP）。工具回执格式（shell 的 `exit=` 前缀、grep 的 `路径:行号: `、edit_file 的行号锚点）是 UI 解析契约——改动必须工具与 ui/shared/tool-display 两处同步。

### R-TLB-00 统一契约与上下文注入

- **需求背景与动机**：如果每个工具自行处理路径解析、取消、输出截断，行为必然漂移——有的跟 cwd 有的不跟、有的能取消有的不能、有的截断输出有的撑爆窗口。统一契约让「工具怎么被调用」只有一个答案，也让 MCP 等外部工具接入时无需重造这些语义。
- **功能规格**：
  1. **数据形态**：Tool 契约五成员——`name`（LLM 可见名）、`description`（模型判断何时用的依据）、`schema`（zod）、`parameters`（暴露给模型的 OpenAI JSON Schema）、`execute(args, ctx)`。
  2. **输入与前置**：`execute(args, ctx)` 中 `args` 已过 zod 校验；参数校验失败（模型输出非法参数）→ 回填「参数校验失败」，不执行工具。
  3. **ToolContext 字段级**：
     - `cwd`：会话工作目录——所有文件类工具经 `resolveTargetPath(cwd, path)` 解析目标（绝对参数原样 resolve，相对参数基于 cwd resolve；禁止 join——Windows 上 join(cwd, 绝对路径) 会吞掉盘符冒号产生变形路径，权限分类与实际读写会指向不同文件），`/cd` 切换后天然生效；
     - `signal`：轮次 AbortController 的 signal——shell 挂 abort 监听杀进程树，遍历器在目录间隙 throwIfAborted；
     - `shellProgram` / `shellTimeoutMs`：仅 shell 消费（缺省按平台解析 / 120s）。
  4. **返回值**：`{ content }`（成功）或 `{ error }`（失败）——错误是给模型看的信息，不是异常；`{ error }` 回填为 `ERROR: <原因>` 形式的 tool 消息（内容仍可被模型读取分析）。
  5. **执行链路**：JSON.parse arguments → zod 校验 → 权限分类 → 广播 `tool_start` → `execute` → 输出治理截断（8000 字符 cap，尾行标注「…（输出过长，已截断）」）→ 广播 `tool_end`（成功/失败都发，带 error 标记）→ tool 消息回填；链路对内建与 MCP 工具完全一致。
  6. **取消粒度**：ctx 由 loop 在每个工具调用时构造（`{ cwd, signal, shellProgram }`，取自轮次参数）——取消粒度在工具边界：loop 在每个工具执行前轮询协作标志；长时工具（shell/遍历类）内部再消费 signal 实现即时中断。
  7. **主参数登记（立法）**：权限模式字符串对应工具的哪个参数由 `PRIMARY_SPECIFIER = { shell: 'command' }` 声明，其余文件类工具缺省 `path`（`primarySpecifier` 兜底）；`BUILTIN_PATH_TOOLS = ['read_file', 'write_file', 'edit_file', 'ls', 'glob', 'grep']`——路径作用域前缀校验只对这些键生效。新增非 path 主参数工具必须在此登记。
  8. **新增内建工具接入清单**：实现 Tool 契约 + 注册（withBuiltins）+ 权限主参数登记 + 文档同步——四步缺一则行为不完整（无权限规则或与文档漂移）。
- **边界与失败模式**：
  - 工具内部异常被 executor 兜底 catch 转 tool_end（error 标记）——保证 tool_start 总有配对的 tool_end。
  - `{ error }` 返回值回填为 `ERROR: <原因>` 形式的 tool 消息（内容仍可被模型读取分析）。
  - 截断由 executor 统一施加，工具内无需重复实现通用层（工具内层治理可再叠加，如 grep 四层）。
  - 短时单次 IO 的文件类工具（read/write/edit/ls）不消费 signal——工具边界的协作检查点已保证取消后不启动下一个工具。
- **验收标准**：
  1. 当 `/cd` 切换目录后模型调 `read_file { path: 'src/index.ts' }`，则实际读取新 cwd 下的同名文件。
  2. 当模型给出的参数未过 zod schema，则回填「参数校验失败」，工具本体未执行。
  3. 当工具返回 `{ error }`，则 tool 消息内容为 `ERROR: <原因>` 且轮次继续。
  4. 当工具回执超过 8000 字符，则回执被截断且尾行含「…（输出过长，已截断）」。
  5. 当工具 execute 抛异常，则 tool_end 仍发出（error 标记），无悬挂「执行中」块。
  6. 当工具执行完成，则 tool_end 的 output 与回填 tool 消息的 content 完全一致（同源产出）。
- **场景走查**：模型在 /cd 到 `D:\work\app` 后调 read_file('src/index.ts') → 实际读取 `D:\work\app\src\index.ts`；同一调用在取消后立即中断。

### R-TLB-01 read_file 读取文件

- **需求背景与动机**：读文件是 agent 的第一高频操作——理解代码、检查修改结果、读取技能指令都依赖它。读操作必须默认放行（探索顺畅的前提），但放行不能成为越界通道：符号链接指向 cwd 外时，词法匹配会被骗，权限必须按「真实位置」判定。
- **功能规格**：
  1. **输入与前置**：参数 `path`（支持相对 cwd / 绝对），读取 resolveTargetPath 解析后的目标文件全文以 utf8 返回给模型。
  2. **权限规则**：按「真实位置」判定——权限层在匹配前把 path 参数经 `realpathSync` 归一——符号链接指向 cwd 外时词法匹配会被骗，真实位置越界即失配落 ask（防逃逸，ADR-0010）。
  3. **默认权限**：read_file 出厂默认在 allow 桶（whole: true）——只读安全且探索顺畅的前提。
  4. **输出与用户可见表现**：成功时文件全文作为回执（经 8000 字符通用截断）；失败时 error 回模型。
- **边界与失败模式**：
  - 目标不存在 → error「ENOENT…」回模型，模型可换 glob/ls 重新定位。
  - 目标是目录而非文件 → readFile 报错 error 回模型（errno 因平台而异）。
  - 目标在权限 allow 规则路径内但经 symlink 实际在外 → 判定落 ask 而非静默放行（fail-closed）。
  - 超过 1MB 的文件在读取前被 stat 拦下 → error「文件超过 1MB（N 字节），请改用 grep 定位后再读取所需片段」——整份读进内存既可能 OOM 也会一次性灌爆上下文。
  - 前 8KB 含 NUL 字节判二进制（与 grep 的二进制探测同口径同函数，内容判定不依赖扩展名）→ error「二进制文件，未读取内容（请确认文件类型，或用 grep/glob 定位文本文件）」——探测必须发生在解码之前；grep 跳过的文件 read_file 也拒绝读，两侧对同一文件结论一致。
  - UTF-8 BOM（解码后即首字符 \uFEFF）在返回前剥离——BOM 混在首行会被模型当作内容的一部分复述出去。
- **验收标准**：
  1. 当 path 为 cwd 内真实文件，则文件全文以 utf8 回填为 tool 消息。
  2. 当 path 经 symlink 实际指向 cwd 外，则权限判定落 ask 而非静默放行。
  3. 当目标不存在，则回执为 error「ENOENT…」，模型可继续用 glob/ls 定位。
  4. 当文件超过 8000 字符，则回执被截断并标注「…（输出过长，已截断）」；当文件超过 1MB 或前 8KB 含 NUL 字节（二进制），则读取被拒绝并 error 指引改走 grep/glob。
- **场景走查**：模型调 `read_file { path: 'docs/api.md' }` → cwd 内真实文件 → 内容直接回填 → 模型据此回答；`read_file { path: 'link-to-secrets' }`（symlink 指向 cwd 外）→ 权限层 realpath 发现越界 → 落 ask 弹审批。

### R-TLB-02 write_file 写入文件

- **需求背景与动机**：整文件写入是「从零生成」的路径（新建组件、生成配置）。新建文件没有「真实位置」可 realpath——权限必须按「将落入的真实父目录 + 文件名」判定，否则新建路径能绕过路径规则（词法上在 cwd 内、实际经父目录 symlink 落到外面）。
- **功能规格**：
  1. **输入与前置**：参数 `path` + `content`，以 utf8 整体覆写/创建 resolveTargetPath(cwd, path) 解析后的目标；落盘走原子写（tmp + 同目录 rename，见 shared/atomic.ts——直接 writeFile 是「先截断再写入」两步，中途崩溃/断电/磁盘满会留下半截文件且无法自愈）；父目录必须已存在（writeFile 不创建父目录——目标目录缺失时以 ENOENT 失败，需先建目录或改用已有路径）。
  2. **覆盖语义**：覆盖已有文件是显式行为：内容整体替换，不做合并——需要局部修改时应走 edit_file。
  3. **权限规则**：参数归一时目标不存在 → 真实父目录 realpath + 文件名拼接（`realTargetPath` 的第二分支）；父目录也不存在 → 词法解析兜底。
  4. **默认权限**：出厂默认在 ask 桶（whole: true）——写入需审批。
  5. **输出与用户可见表现**：成功回执 `已写入 <path>`；失败（只读目录/磁盘满/父目录缺失）→ error 回模型。
- **边界与失败模式**：
  - 写入失败（只读目录/磁盘满）→ error 回模型。
  - 目标父目录不存在 → error（ENOENT）回模型——工具不代建目录，需先建目录或改用已有路径。
  - 「错误覆盖」的防线不是工具而是权限 ask + 模型先读后写的习惯（description 引导）。
  - `D:\work\app\link-dir\x.txt` 中 link-dir 指向 cwd 外 → 父目录 realpath 越界 → 落 ask。
- **验收标准**：
  1. 当对已有文件 write_file，则内容整体替换为参数 content，无合并残留。
  2. 当目标父目录不存在，则返回 error（ENOENT），不静默创建目录。
  3. 当写入成功，则文件内容与参数 content 逐字节一致，回执为「已写入 <path>」。
  4. 当目标父目录经 symlink 指向 cwd 外，则权限判定落 ask。
  5. 当用户对 write_file 审批选「对此范围不再询问」，则范围模式（如 `./src/**`）落库，同范围后续写入免审批。
- **场景走查**：模型调 `write_file { path: 'src/new-util.ts', content: '...' }` → ask 审批（新建文件也走完整判定）→ 用户「对此范围不再询问」→ 范围模式 `./src/**` 落库，同目录后续写入免审批。

### R-TLB-03 edit_file 精准编辑

- **需求背景与动机**：LLM 重写整个文件容易丢内容（长文件 token 限制 + 幻觉——重写 500 行文件时悄悄删掉两行函数是真实事故）。精准的「旧片段 → 新片段」替换是 code agent 的核心约束——旧片段逐字符匹配天然限制了改动范围，匹配不上就不动手。
- **功能规格**：
  1. **输入与前置**：参数 `path` + `old_string` + `new_string`，old_string 需与文件内容**逐字符一致**（含缩进/空白）。
  2. **处理规则**：读全文 → `old_string` 不存在 → `{ error: 'old_string 未找到' }`（模型需先 read_file 核对内容再改）→ 存在则**替换首次出现的那一处**并写回——替换用函数形态 `text.replace(old_string, () => new_string)`：字符串形态的替换值里 `$$`、`$&`、`$'` 等替换序列会被 String.replace 重新解释（`$&` = 整个匹配、`$$` = 字面 $ 等），函数返回值按字面插入不做二次解释，`new_string` 原样落盘；写回走原子写（tmp + rename，整文件 utf8 覆写）。`new_string` 为空串即删除片段（合法操作）。
  3. **锚点计算**：同时计算锚点——old_string 在原文件中的 1-based 起始行（`text.slice(0, indexOf).split('\n').length`）。
  4. **输出与用户可见表现**：回执 `已替换 1 处（原第 N 行起）`一举两得——模型知道改动落点便于后续连续编辑；UI（shared/tool-display）解析该锚点给 diff 标真实行号（旧会话回放无锚点时不标行号，不编造坐标）。
  5. **模型侧约束**：想改多处需提供带更多上下文的 old_string 或多次调用——工具本身不强制唯一命中，替换第一处并如实回执。
  6. **权限规则**：按 path 主参数判定（与 read_file 同族，realpath 归一）。
- **边界与失败模式**：
  - old_string 在文件中出现多次时，若命中位置与模型意图不符，模型可根据回执行号自行修正（扩大上下文重试）。
  - 「未找到」是最高频失败——回执明确指示「先读再改」。
  - 权限按 path 主参数判定（与 read_file 同族，realpath 归一）。
- **验收标准**：
  1. 当 old_string 存在于文件，则首次出现处被替换为 new_string，其余内容逐字节不变。
  2. 当 old_string 不存在，则回执 error「old_string 未找到」，文件不被修改。
  3. 当 new_string 为空串，则 old_string 片段被删除（删除操作合法）。
  3. 当替换成功，则回执含 `已替换 1 处（原第 N 行起）`，N 为 old_string 首字符所在的原文件行号。
  4. 当 UI 渲染展开块，则 diff 标注真实行号；无锚点的旧会话回放不标行号、不编造坐标。
  5. 当 old_string 出现多次，则仅第一处被替换且回执如实（模型可据行号扩大上下文重试）。
  6. 当 new_string 含 `$$`、`$&`、`$'` 等替换序列，则这些序列按字面写入文件，不被重新解释。
- **场景走查**：模型调 `edit_file { path: 'src/index.ts', old_string: 'const port = 3000', new_string: 'const port = Number(process.env.PORT ?? 3000)' }` → 首处替换成功，回执「已替换 1 处（原第 12 行起）」→ UI 展开块渲染 +/- diff 并标注第 12 行。

### R-TLB-04 shell 执行命令

- **需求背景与动机**：跑测试、装依赖、git 操作都要 shell。但模型的 shell 先验来自训练数据（Unix 偏置）——Windows 上不告知实际解释器就会频繁写错语法（`ls`/`&&`/`$VAR` 在 cmd 里全错）。且交互式常驻进程（dev server）不设超时会卡死整轮对话——模型在等一个永不退出的进程，用户只能取消整轮。
- **功能规格**：
  1. **解释器选择**（resolveShell）：配置的 `shellProgram`（config 顶层键）映射为 `{ program, flag, kind }`；缺省按平台（win: cmd，其它: bash）。统一 `spawn(program, [flag, command])` 显式指定，不用 `{ shell: true }`。映射表：
     | shellProgram 配置值 | program | flag | kind |
     |---|---|---|---|
     | `cmd` | cmd | `/c` | cmd |
     | `powershell` | powershell | `-Command` | powershell |
     | `pwsh` | pwsh | `-Command` | pwsh |
     | `bash` | bash | `-c` | bash |
     | `sh` | sh | `-c` | sh |
     | （缺省） | win: cmd / 其它: bash | `/c` / `-c` | 同 program |
  2. **PATH 扫描校验**（detectShells）：配置值必须在本机扫描结果内（Windows 按 PATH×PATHEXT 找 powershell.exe/pwsh.exe/bash.exe，cmd 视为必然可用；Unix 以 sh 为基线、按 PATH 找 bash），否则回退平台默认——配置了不存在的 bash 不会导致全部命令失败。含非 ASCII 的值（误存占位文本）同样回退；未知程序名（nu/fish）不猜测语义回退默认；扫描结果运行期缓存。**bash 身份消歧**：win32 上 PATH 扫描命中的 bash 落点在 System32 目录下（大小写不敏感）判为 WSL 启动器，从检测结果剔除（CreateProcess 对裸名 spawn 的搜索序 System32 恒先于 PATH——不消歧会出现「检测说有 Git Bash、执行起来却是 WSL bash」两套坐标脱节；Git Bash 从不装在 System32，判据不误伤）；消歧后 bash 候选一个不剩则配置不可选 bash（fail-closed，只收窄不放宽）。
  3. **执行**：按解释器分两支 spawn（不用 `{ shell: true }`，避开 DEP0190 弃用警告）。cmd 分支（win）：`spawn(ComSpec ?? 'cmd.exe', ['/d', '/s', '/c', `"${command}"`], { cwd, windowsVerbatimArguments: true })`——verbatim 引号包裹形态：裸名数组形态下 node 按 MSVCRT 规则转义参数，命令内嵌的 `"` 被改写成 `\"` 而 cmd.exe 不认（含引号命令被错拆，如 `findstr /c:"hello world"`）；`/d` 跳过 AutoRun 注册表项（用户 cmd 启动脚本会污染输出），`/s` + 外层包裹 + verbatim 三者配套把命令串逐字节原样送达 cmd.exe。powershell/pwsh/bash/sh 分支：`spawn(shellExe, [flag, command], { cwd, detached: !isWin })`（POSIX detached 用于进程组 kill；shellExe 优先用 PATH 扫描得到的绝对路径——绝对路径 spawn 绕过 CreateProcess 的 System32-先于-PATH 搜索序，保证「检测到的 shell」与「实际启动的 shell」是同一个文件，解析不到回退裸名）。两支 stdio 均为 `['ignore', 'pipe', 'pipe']`——stdin 显式 'ignore'：子进程 stdin 指向空设备，读 stdin 的交互命令（缺参数的脚本、等待确认的 CLI）立即得 EOF、按「无输入」自然失败，而非挂满 120s 超时才被杀；stdout/stderr 'pipe' 供采集。
  4. **超时**：120s（ctx.shellTimeoutMs 可注入）——超时杀整个进程树（Windows `taskkill /PID <pid> /T /F`；POSIX `process.kill(-pid, SIGKILL)` 杀 detached 进程组），close 事件走正常回填路径，回执 = `exit=<code>（命令超过 120s 未结束，已终止进程树；如需长任务请放后台并轮询输出）\n<已有输出>`。
  5. **环境引导注入**：系统提示追加「## Shell 环境」段（`shellGuidance`）——平台、当前 shell 种类与 `program flag`、该 kind 的语法要点（cmd：没有 ls/grep/cat，环境变量 `%VAR%`，复杂逻辑拆分或 node -e；powershell 5.1：不支持 `&&` `||`，用分号或 `if ($?)`；pwsh 7：支持 `&&`；bash/sh：标准 POSIX）。每类要点宁少勿错——只列确定性高的事实。引导段挂在 ContextAssembler 的动态段回调上（与 skills 广告段拼接），每次 systemPrompt() 现算——shellProgram 变更下一轮请求即生效。
  6. **输出合并与有界采集**：stdout/stderr 合并累积（按到达序追加，无交错顺序保证）；采集容量有界——两端流共用 1MB 上限（与 grep 的 1MB/文件防护同口径），超限后停止累积、丢弃字节数记入回执末尾「[输出超过采集上限，已丢弃 N 字节]」（失控命令不把 agent 进程拖向 OOM，截断要有回执）；按 Buffer 块累积、close 时一次性 concat + utf8 解码——逐 chunk toString 会把跨 chunk 切断的多字节字符解码成乱码。
  7. **超时注入**：单命令超时缺省 120s 常量，`ctx.shellTimeoutMs` 可注入（测试接缝）。
  8. **取消**：取消时 killTree 挂在 ctx.signal 的 abort 上。权限按 command 主参数平文本通配匹配（`git *`，见 05-权限与安全）——`*` 通配到命令结尾的任意字符序列（含 / 与空格）、`?` 任意单字符、锚定匹配；命令是平文本无层级概念，`git *` 一条即够。
  9. **输出与用户可见表现**：正常回执 `exit=<code>\n<输出>`；UI 折叠头显示「$ <命令> · N 行输出」。
- **边界与失败模式**：
  - spawn 失败（解释器损毁等极端）→ `{ error }` 回模型。
  - 超时回执自带「已有输出 + 超时说明」，模型可据此调整（改后台轮询）。
  - 杀进程后的二级看门狗：kill（超时/取消触发）后 close 仍可能永不到达（taskkill 失败、逃逸守护进程持有 stdio 管道）——5s 宽限一过销毁输出流、按已采集输出强制收场（回执附「[进程未正常退出，已按已有输出返回]」），整轮对话不挂死。
  - 命令 exit≠0 是正常回填（UI 显示 ✕ 退出 N），不是工具错误——命令失败与工具失败对模型是两种信息。
- **验收标准**：
  1. 当配置 shellProgram=pwsh 且本机存在 pwsh.exe，则命令经 `pwsh -Command` 执行且回执带 `exit=` 前缀。
  2. 当配置了本机不存在的 bash（Windows 无 bash.exe），则回退平台默认 cmd，命令照常执行。
  3. 当命令超过 120s 未退出，则进程树被杀，回执含超时说明与已产生输出。
  4. 当命令 exit≠0，则作为正常回执回填（UI 显示 ✕ 退出 N），工具层面不算失败。
  5. 当命令只向 stderr 输出且 exit=0，则 stderr 内容仍进入回执（stdout/stderr 合并累积）。
  6. 当用户在命令执行中取消，则子进程树立即被杀（Windows taskkill /T /F、POSIX 进程组 SIGKILL）。
  7. 当系统提示组装，则「## Shell 环境」段包含实际解释器 kind 与对应语法要点。
  8. 当命令是读 stdin 的交互命令（如缺参数的脚本），则 stdin 得到立即 EOF、命令按「无输入」快速失败退出，不挂满 120s 超时。
  9. 当 shellProgram=cmd 且命令含内嵌引号（如 `findstr /c:"hello world"`），则命令串逐字节原样到达 cmd.exe（verbatim 形态），引号不被转义错拆。
  10. 当 Windows 本机只有 System32 的 WSL bash（无 Git Bash），则 bash 从扫描结果剔除、配置 bash 回退 cmd——不会「检测 Git Bash、执行 WSL bash」。
- **场景走查**：Windows + shellProgram=pwsh → 模型看到「当前 shell 为 pwsh，支持 &&」→ 调 `shell { command: 'pnpm test && pnpm build' }` → 120s 内完成 → 回执 `exit=0\n<输出>`，UI 折叠头显示「$ pnpm test && pnpm build · N 行输出」。

### R-TLB-05 ls 目录列举

- **需求背景与动机**：模型需要先看项目结构再决定读什么——一层目录视图（目录在前 + 文件大小）是最快的拓扑感知方式；不代理 shell 的 dir/ls（跨平台结构化输出，Windows 没有 shell grep/dir 的统一语义），保证回执格式稳定可解析。
- **功能规格**：
  1. **输入与前置**：参数 `path`，列出 resolveTargetPath(cwd, path) 解析后目录的一层内容。
  2. **输出格式**：目录条目加 `/` 后缀在前、文件条目附人类可读大小（B/KB/MB）在后，各自按名排序；单层不递归（递归找文件是 glob 的事）。
  3. **隐藏文件**：隐藏文件（`.` 开头）正常显示——agent 需要看 .github/.gitignore 等。
  4. **封顶**：条目封顶 500（MAX_ENTRIES），超出截断并注明「仅显示前 500 项，共 N 项」。
  5. **大小格式**：文件条目人类可读大小——<1KB 显示「N B」、<1MB 显示「x.x KB」、否则「x.x MB」（模型与用户都按数量级理解文件，原始字节数是噪音）。
  6. **立法**：**刻意不受黑名单/gitignore 约束**——用户点名看的目录应如实呈现。
  7. **symlink 条目跳过**（与 walker 同一立场）。
  8. **权限规则**：按 path 主参数（read_file 同族）。
- **边界与失败模式**：
  - 目录不存在 → error「无法读取目录 …」回模型；空目录回「（空目录）」。
  - 大小获取失败（竞态删除）不致命——条目仍列出，大小显示 `?`。
  - 只产出目录与普通文件条目——其它类型（symlink/socket 等）不出现（symlink 与 walker 同一立场跳过）。
  - 权限判定按 path 主参数（read_file 同族）。
- **验收标准**：
  1. 当目录含子目录与文件，则回执目录条目（`/` 后缀）全部排在文件条目之前，两组各自按名排序。
  2. 当目录含 `.gitignore` 等隐藏文件，则正常列出。
  3. 当条目超过 500，则仅显示前 500 项并注明总数。
  4. 当某文件 stat 失败（竞态删除），则该条目仍在列表中且大小显示 `?`。
  5. 当目录内含 node_modules，则 ls 仍如实列出（不受遍历黑名单约束）。
  6. 当目录内含 symlink 条目，则该条目不出现在回执。
  7. 当目录为空，则回「（空目录）」。
- **场景走查**：模型调 `ls { path: '.' }` → 回执 `src/\n docs/\n package.json  1.2 KB\n …` → 据此决定下一步 read_file 哪个文件。

### R-TLB-06 glob 模式筛文件

- **需求背景与动机**：「找出所有测试文件」「找配置在哪」需要按文件名模式递归搜索——只匹配路径不读内容（按内容搜是 grep 的事），大仓库的命中数必须有上界；模式编译必须与权限参数化规则共用一份实现，否则「权限里写的模式」和「glob 里写的模式」语义漂移。
- **功能规格**：
  1. **输入与前置**：参数 `pattern`（必填）+ `path`（可选起点目录，缺省 cwd 根）。
  2. **模式编译**：pattern 经 bridge 的 `globToRegExp` 编译（与权限参数化规则**共用一份实现**，一份实现三端永不漂移）；pattern 中的反斜杠归一为 `/` 后编译；模式非法 → error 回模型。文法子集（刻意不实现 `[]` / `{}`）：
     | 语法 | 语义 |
     |---|---|
     | `**` | 跨任意路径段（`**/x` 含根级 x；`src/**` 匹配 src 下一切但不匹配 src 本身） |
     | `*` | 单段内任意字符（不跨 `/`） |
     | `?` | 单个字符（不含 `/`） |
     | 其余字面量 | 正则元字符自动转义（点号等无需用户处理） |
     | `[]` / `{}` | 文法子集外——按字面量匹配（自动转义） |
  3. **遍历规则**：遍历用共享 walker——黑名单剪枝 + symlink 跳过 + `.gitignore`（会话 cwd 根）过滤 + 取消信号；matcher 编译一次、遍历内复用。
  4. **产出格式**：产出为 posix 相对路径，命中结果按名排序；无命中回「（无匹配文件）」。
  5. **封顶**：命中封顶 100（MAX_MATCHES），超出截断并提示「请收窄 pattern」。
  6. **权限规则**：按 path 主参数判定（给了 path 就判 path，缺省判 cwd）。
- **边界与失败模式**：
  - 根目录不存在显式报错（「路径不存在：…」）——区分「模式写错」与「路径写错」，否则模型侧不可判别。
  - walker 对单目录读失败是「跳过继续」语义（探索不因单点失败中断）。
  - 权限按 path 主参数判定（给了 path 就判 path，缺省判 cwd）。
- **验收标准**：
  1. 当 `pattern: '**/*.test.ts'` 在含测试的项目执行，则回执为命中文件的 posix 相对路径列表。
  2. 当命中超过 100，则仅显示前 100 个并附「请收窄 pattern」提示。
  3. 当 path 指向不存在的目录，则显式报「路径不存在：…」而非空结果。
  4. 当遍历经过 node_modules/.git，则这些目录整棵被剪枝不产出命中。
  5. 当遍历期间用户取消，则在下一个目录间隙以 AbortError 中断。
  6. 当模式含 `[` 或 `{`（文法子集外字符），则按字面量匹配（自动转义），不报错也不当字符组解释。
  7. 当模式非法（如未闭合的段），则 error 回模型并指明 pattern。
- **场景走查**：模型调 `glob { pattern: '**/*.test.ts' }` → 回执 37 个相对路径 → 再对其中三个 read_file。

### R-TLB-07 grep 内容搜索

- **需求背景与动机**：定位「某个函数在哪定义」「TODO 在哪」需要跨文件内容搜索，且必须跨平台（不依赖 shell grep——Windows 没有）。搜索结果天然不可控（一个宽泛正则在大仓库可命中几十万行），需要最严格的输出治理——否则一次搜索就吃掉整个上下文窗口。
- **功能规格**：
  1. **输入与前置**：参数 `pattern`（正则，逐行匹配）、`path`（可选，文件或目录）、`glob`（可选文件名过滤）、`case_insensitive`。output_mode 三模式（description 引导「先粗后细：大搜索先用 files_with_matches 锁定文件再精搜」）：
     | output_mode | 输出形态 |
     |---|---|
     | `content`（缺省） | `相对路径:行号: 内容`（命中行） |
     | `files_with_matches` | 每行一个命中文件路径 |
     | `count` | 每行 `<路径>: <命中数>` |
  2. **正则校验**：正则非法 → error 指明「无效的正则表达式…请修正后重试」。
  3. **回执契约**：回执格式 `相对路径:行号: 内容`（content 模式）是**回执即契约**——UI formatter 按此前缀解析展示，格式改动必须工具与 ui/shared/tool-display 两处同步。
  4. **输出治理四层**：
     - ① 单行截断 500 字符（minified 行防护）；
     - ② 单文件命中封顶 20（超出停止扫本文件，附「该文件还有 N 处未显示」——补数走全文重计）；
     - ③ 总命中封顶 100（提前结束遍历）；
     - ④ 总字符 cap 8000（写满即置 truncated，后续写入一律拒绝，提前结束遍历）。
  5. **文件级模式输出**：files_with_matches 每行一个命中路径；count 每行 `<路径>: <命中数>`——行级输出不产出，命中只计数、循环后统一写入。
  6. **尾部说明行**：任何截断层触发 → 追加「（输出已截断，请用更具体的 pattern 或 glob 参数收窄搜索）」；有超大文件跳过 → 追加「（已跳过 N 个超过 1MB 的文件）」。
  7. **附带防护**：超过 1MB 的文件跳过（回执注明跳过数）；前 8KB 探测 NUL 字节判二进制并跳过——判定依赖内容而非扩展名白名单（扩展名枚举不完，误判代价是少搜一个文件，方向安全）；`\r` 归一（Windows 行尾不影响命中与行号）。
  8. **glob 过滤语义**：对「完整相对路径」与「文件名」任一命中即通过（`*.ts` 应匹配 src/x.ts 的用户直觉）。
  9. **遍历底座**：与 glob 相同（walker + gitignore + 取消信号）；单文件模式（path 指向文件）直接读该文件，展示路径取参数 path（或其 basename）。
  10. **权限规则**：按 path 主参数判定。
- **边界与失败模式**：
  - 单文件读取失败（竞态删除/权限）跳过不致命。
  - 无命中回「（无命中，已跳过 N 个超大文件）」；任何截断层触发都附「请用更具体的 pattern 或 glob 参数收窄」。
  - 权限按 path 主参数判定。
- **验收标准**：
  1. 当 content 模式命中 `src/utils/date.ts` 第 12 行，则回执行为 `src/utils/date.ts:12: <命中内容>`（UI 据此前缀解析展示）。
  2. 当单文件命中超过 20 处，则停止扫该文件并附「该文件还有 N 处未显示」（N 走全文重计）。
  3. 当总命中超过 100 或总输出超过 8000 字符，则提前结束并附收窄提示。
  4. 当文件超过 1MB 或前 8KB 含 NUL 字节，则跳过且回执注明跳过数。
  5. 当 `glob: '*.ts'` 且命中文件为 `src/x.ts`，则该文件通过过滤（路径与文件名双匹配）。
  6. 当无命中且存在被跳过的超大文件，则回「（无命中，已跳过 N 个超大文件）」。
  7. 当 Windows 文件含 `\r\n` 行尾，则命中与行号与 LF 文件一致（`\r` 归一）。
- **场景走查**：模型调 `grep { pattern: 'formatDate', glob: '*.ts', output_mode: 'files_with_matches' }` → 3 个文件 → 再 content 模式精搜其一 → `src/utils/date.ts:12: export function formatDate(…)`。

### R-TLB-08 统一注册表与合规关口（ADR-0012）

- **需求背景与动机**：LLM 供应商对函数名有硬约束（字符集 `[a-zA-Z0-9_-]`、长度 ≤64，OpenAI 系与 Anthropic 系一致），校验发生在 API 请求层且**拒绝整个请求**。一个命名非法的 MCP server 如果把非法名直接发给模型，会让每一次对话请求整体 400——故障面是「全部对话」而不只是「那个工具」。关口必须设在注册层：非法名进不来，合规名出得去。
- **功能规格**：
  1. **注册三合一**：所有工具在唯一注册表注册/摘除，`register(tool, identity)` 同时做三件事：
     1. **名称合规转换**——合规判定标准为 `TOOL_NAME_RE = /^[a-zA-Z0-9_-]{1,64}$/`（字符集与长度双约束，OpenAI 系与 Anthropic 系一致）；原名合规则原样注册；不合规整体哈希为 `h-<sha256 前 12 位 hex>` 确定性标签（同名必同标签），变换落在 Tool 对象本身（name 字段被改写），保证 `schemas()` 发出的名字必然合规；
     2. **冲突可见失败**——目标标签已被占用时抛错（「工具注册名冲突：X 已被占用——请调整来源命名（如 /mcp 中的服务名）」），绝不静默覆盖（静默顶掉会让先注册的工具无声失联）；
     3. **身份记录**——每个工具带 ToolIdentity（`{ kind: 'builtin' }` 或 `{ kind: 'mcp', server, name }`），与工具同增同删。
  2. **返回值与缺省**：register 返回最终注册标签（常规情况 === tool.name，哈希情况为 `h-<hash>`，调用方据此对接身份语义）；identity 缺省 `{ kind: 'builtin' }`——内建构造路径零改动接入。
  3. **身份唯一事实源**：身份是「工具从哪来」的唯一事实源——权限服务键匹配（PermissionManager 构造注入 `identities()` 只读快照）、UI 分组展示、MCP 按归属摘除（`labelsWhere` 按身份找标签——哈希标签不带 `mcp__` 前缀，前缀扫描会漏删）都查这里，**从不解析 LLM 可见名**。
  4. **内建注册序**：withBuiltins() 按 read_file → write_file → edit_file → shell → ls → glob → grep 顺序注册——schemas() 产出顺序与此一致（见 R-LLM-06）。
  5. **现算与幂等**：`schemas()` 每次现算；`unregister` 不存在时静默（幂等）。
  6. **数据形态**：ToolListItem = `{ name, description, identity }`——注册表不变量「凡注册必有身份」（`listTools()` 的 `?? builtin` 兜底仅为类型完备）。
- **边界与失败模式**：
  - MCP 服务注册中途冲突 → 该服务整体摘除（先摘后挂 + 失败回滚），其它服务照常。
  - 注册表不变量「凡注册必有身份」——`listTools()` 的 `?? builtin` 兜底仅为类型完备。
- **验收标准**：
  1. 当注册名为 `浏览器.导航`（非法字符），则注册标签为 `h-<sha256 前 12 位>`，schemas() 发出的名字匹配 `^[a-zA-Z0-9_-]{1,64}$`。
  2. 当同一非法名重复哈希，则两次标签一致（确定性，同名必同标签）。
  3. 当目标标签已被占用时注册，则抛「工具注册名冲突」且原工具未被顶掉。
  4. 当注册合规名工具，则 register 返回原名且 Tool 对象名不被改写（与现状逐字节一致）。
  5. 当按 MCP 服务身份摘除（labelsWhere），则该服务全部工具（含哈希标签者）被摘净。
  6. 当 unregister 一个不存在的名字，则静默返回（幂等），不报错。
- **场景走查**：某 MCP server 声明内部工具名 `浏览器.导航` → 注册关口哈希为 `h-3f9a2b7c1d0e` → 模型看到并调用该标签 → 执行时按身份转发原始名给服务（见 R-MCP-10）。
