# 01-配置指南

DogEggAgent 的全部持久配置集中在一个 JSON 文件中。本文逐字段说明写法与语义。

## 配置文件在哪

按顺序取**第一个存在的**：

1. 当前目录的 `.dogegg.json`（项目级覆盖——本目录下启动优先用它）；
2. `~/.dogegg/config.json`（用户级默认）。

都没有 → 出厂默认启动（无 provider，引导 /config）。

## 字段总览

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `systemPrompt` | string（可选） | 内置 | 追加/替换系统提示的自定义段 |
| `defaultProvider` | string（可选） | 首个 provider | 默认服务商（需能解析到模型） |
| `defaultModel` | string（可选） | 首个模型 | 默认模型 |
| `maxIterations` | number | `-1` | 单轮对话工具循环上限（`-1` 无限；`0` 非法） |
| `maxRetries` | number | `3` | LLM 请求失败重试次数 |
| `shellProgram` | string（可选） | 按平台 | shell 解释器（Windows `cmd`，其他 `bash`） |
| `permission` | object | 见下 | 工具权限三桶（桶 → 键 → `{ whole, patterns }` 规则） |
| `mcpServers` | array | `[]` | MCP 服务器列表（见下） |
| `providers` | array | `[]` | 模型服务商列表（见下） |

## providers（模型服务商）

```json
{
  "providers": [
    {
      "name": "glm",
      "protocol": "openai",
      "baseURL": "https://open.bigmodel.cn/api/paas/v4",
      "apiKey": "你的密钥",
      "models": [
        { "name": "glm-4.7", "contextWindow": 200000, "maxOutput": 16384, "reasoning": false }
      ]
    }
  ],
  "defaultProvider": "glm",
  "defaultModel": "glm-4.7"
}
```

- `protocol` 当前仅支持 `openai`（兼容协议）；
- `contextWindow` 驱动压缩阈值（80% 自动压缩）；`reasoning: true` 的模型思考占用输出预算（maxOutput 自动调整）；
- 校验层刻意放宽（字段允许暂空）以支持「先建节点再补内容」——能否对话由完整性与默认值解析判定。

## permission（权限三桶：桶 → 键 → { whole, patterns }）

三桶 `allow / reject / ask`，判定顺序固定：**reject > 会话提升 > ask > allow > 默认 ask**。

```json
{
  "permission": {
    "allow": {
      "read_file": { "whole": true,  "patterns": [] },
      "shell":     { "whole": false, "patterns": ["git *", "npm run *"] }
    },
    "ask":   { "edit_file": { "whole": false, "patterns": ["./src/**"] } },
    "reject": { "shell": { "whole": false, "patterns": ["rm -rf *"] } }
  }
}
```

**规则两态**：

- `whole: true` → 整键生效（该键覆盖的所有调用都按本桶处理）；patterns 保留但不参与匹配（取消整选后恢复）；
- `whole: false` → 只有命中 patterns 的调用按本桶处理；**空 patterns = 键存在但不命中**（编辑空选态）。

**键的两类**：

1. **内建工具名**——patterns 是主参数模式：

| 工具 | 主参数 | 模式示例 | 语义 |
|---|---|---|---|
| `shell` | `command` | `"git *"` | `*` = 任意字符（含空格与 `/`） |
| `read_file` 等 6 个文件类 | `path` | `"./docs/**"` | `*` 不跨 `/`，`**` 跨任意层 |

2. **MCP 服务键 `mcp:<服务名>`**——patterns 是**服务内部工具名**（如 `browser_close`、`browser_*`），是工具启用匹配，永不涉及执行参数。服务名零字符约束。

**作用域锚点（path 模式必须写）**：`./`（cwd）、`../`、`~/`（主目录）、盘符（绝对）、`*` 开头（从根）。裸模式（`docs/**`）加载即拒绝。此校验仅对内建 path 工具生效。

**出厂默认**（不写 `permission` 字段时）：`read_file`/`ls`/`glob`/`grep` 整工具放行；`write_file`/`edit_file`/`shell` 整工具 ask。显式配置**整体覆盖**出厂默认（不合并）。

**判定顺序**：reject > 会话提升 > ask > allow > 默认 ask。推论：「allow 整组 + ask 勾选个别」可行；「ask 整组 + allow 个别」不成立。

**已知取舍**：shell 命令通配会命中命令链（`git *` 也命中 `git x && rm y`）——参数化规则是便利而非安全边界，危险命令请用 ask/reject 显式压制。

### 会话内提升 vs 配置

审批弹层选「始终允许」的授权是**会话级**的（/permissions 可撤销，新建会话清空）；本节配置是**持久的**。两者独立生效，判定时会话提升优先于 ask 规则。

## mcpServers（MCP 服务器）

```json
{
  "mcpServers": [
    {
      "name": "playwright",
      "enabled": true,
      "transport": {
        "type": "stdio",
        "command": "npx",
        "args": ["-y", "@playwright/mcp"],
        "env": { "KEY": "V" }
      }
    }
  ]
}
```

- `transport.type` 二选一：`stdio`（本地进程：command/args/env）或 `http`（远程：url/headers）；
- `enabled: false` 停用不删除（断连摘工具，配置保留）；
- 项目级 server 写 `<repo>/.dogegg/.mcp.json`（同名字段覆盖全局，随仓库共享）。

## skills（技能目录与启停）

技能不是 config.json 字段，而是**目录约定**（详见下方「文件位置」）：

- 用户级 `~/.dogegg/skills/<技能名>/SKILL.md`、项目级 `<repo>/.dogegg/skills/<技能名>/SKILL.md`；
- SKILL.md frontmatter 写 `description`（模型判断何时使用的依据），正文是指令（`$ARGUMENTS` 占位符替换为命令参数）；
- 启停状态存旁挂文件 `~/.dogegg/.skills.json` 与 `<repo>/.dogegg/.skills.json`，形状 `{ "disabled": ["技能名", ...] }`（缺省即启用；损坏视为空名单自愈）。

## 文件位置速查

| 文件 | 位置 | 用途 |
|---|---|---|
| 用户配置 | `~/.dogegg/config.json` | 全局配置 |
| 项目配置 | `./.dogegg.json` | 本目录启动时优先 |
| 项目 MCP | `<repo>/.dogegg/.mcp.json` | 项目级 MCP 服务器 |
| 用户级技能启停 | `~/.dogegg/.skills.json` | 停用名单 |
| 项目级技能启停 | `<repo>/.dogegg/.skills.json` | 停用名单（随仓库共享） |
| 用户技能目录 | `~/.dogegg/skills/<名>/SKILL.md` | 个人技能 |
| 项目技能目录 | `<repo>/.dogegg/skills/<名>/SKILL.md` | 仓库技能 |
| 日志 | `~/.dogegg/logs/` | 调试日志（/log 查看） |

## 格式演进不兼容

配置格式只支持当前版本。旧格式（模式数组、条目数组、裸服务名键）加载**直接报错**并指明字段与文档。恢复方式：按报错改写、删除出错字段回退出厂默认后经 /config 重配。启动失败时旧文件不会被覆盖。
