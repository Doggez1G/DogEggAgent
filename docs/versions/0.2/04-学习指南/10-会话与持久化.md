# 10-会话与持久化

## 三个角色的分工（agent/src/session/）

- `conversation.ts` 的 `Conversation`：**运行期可变工作集**——history/context/thinking/sessionId/cwd/usage/compactions/title 的唯一持有者。
- `store.ts` 的 `SessionStore`：**JSON 落盘**——读写 `~/.dogegg/sessions/<id>.json`（`baseDir` 构造参数可注入，测试传临时目录）。
- `manager.ts` 的 `SessionManager`：**生命周期编排**——new/resume/delete/list/clear 的实现归属，全部先过 `blocked()`（R2：运行中发 notice 阻塞）。

## R1 双写与存档内容

核心立法（`store.ts` 的 `SessionSnapshot` 接口头注释 + `conversation.ts`）：**history = 完整原文，永不压缩**（给 UI 显示）；**context = 发给模型的消息，会被压缩**。两条流在 `pushUserMessage`（R1 双写）与 `applyTurnResult`（loop 返回的 context 整体替换工作集、newMessages 单向 append 进 history）维护。

存档字段（`SessionStore.save()` 落盘的 JSON）：

| 字段 | 内容 |
|---|---|
| `history` / `context` | 双流消息（OpenAI 线格式，`bridge/src/contract/shared.ts` 的 `Message`） |
| `sessionPermissions` | 会话内权限提升，按工具分组 `{ tool, patterns[] }`（patterns 空 = 整工具）；resume 时 restore（旧格式 `allowedTools` 数组不再读取） |
| `usage` | `{ promptTokens, completionTokens, turns }` 会话累计真实用量，resume 续计 |
| `compactions` | 累计压缩次数（自动走 `LoopResult.compactions`，手动走 `conversation.incrementCompaction()`） |
| `cwd` | 创建/切换时的工作目录，resume 恢复（项目→会话切换恢复目录） |
| `thinking` | 推理模型的思考内容数组（与 assistant 消息一一对应；不进 history/context，resume 后 UI 恢复思考块显示） |
| `title` | /rename 手动命名或首轮自动标题；缺省时列表展示 preview |

写入是**原子写**：先写 `<id>.json.tmp` 再 `renameSync`，避免半写文件损坏会话。快照组装唯一入口是 `conversation.snapshotFull(sessionPermissions, usage, compactions)`——三个落盘调用点（turn-runner 收尾 / sessionManager / agent 的 rename 与 set_cwd）共用。

## 落盘时机

- 每轮结束：`agent/src/turn/turn-runner.ts` 的 `saveOrNotice()`（finally 里；失败 emit notice「会话保存失败」不静默）。
- 新建会话：`SessionManager.newSession()` 立即保存空会话（侧栏即时显示）——但**替换场景例外**（见下）。
- 自动标题生成后、/rename 后、set_cwd 后：各自的 fire-and-forget 或显式保存。
- 手动 /compact 成功后。

落盘文件（`~/.dogegg/sessions/<id>.json`）的可读形态：

```json
{ "id": "…", "updatedAt": "2026-09-15T…",
  "history": [{ "role": "user", "content": "…" }, { "role": "assistant", "content": null, "tool_calls": [...] }],
  "context": [ "…同上但可能已被替换为摘要消息…" ],
  "sessionPermissions": [{ "tool": "shell", "patterns": [] }],
  "usage": { "promptTokens": 0, "completionTokens": 0, "turns": 1 },
  "compactions": 0, "cwd": "D:\\project\\demo", "thinking": [{ "text": "…" }],
  "title": "重构权限引擎" }
```

## resume 恢复

`SessionManager.resume(id)`：`sessions.load(id)` → `conversation.load(s)`（整体替换工作集，快照带 cwd 时一并恢复）→ `permission.reset() + restore(s.sessionPermissions)`（**提升随会话存档恢复**，旧格式字段无视）→ `emit session_ready`（带 history 全量 + thinking）。UI 侧收到 `session_ready` 后 `rebuildBlocksFromHistory()`（`ui/src/shared/reducer.ts`）离线重建消息块：assistant 的 tool_calls 与后续 tool 消息按 `tool_call_id` 配对成完整工具块，thinking 数组逐条消费（空字符串条目跳过）。

`load()` 对旧格式容错：无 history/context 字段时回退 `messages`、context 缺省取 history 拷贝。

## 删除当前会话的接管语义

`SessionManager.deleteSession(id)`（第 78 行）：删文件（幂等）→ `emit session_deleted` → **若删的是当前会话**，`newSession(undefined, { persist: false })` 立即换新空会话。两个立法点（注释原话）：内存旧工作集必须被替换，否则下一轮落盘会把刚删的会话原样写回（「复活」）；但不能立即落盘新会话，否则 `persist=false` 缺席时「刚删空的项目」又被空会话文件撑成非空——WebUI 的删除项目会被这个僵尸空会话挡住。新会话等首次对话才落盘。测试：`agent/test/session/delete-current.test.ts`。

## 项目分组

`SessionStore.list()` 读取所有 `.json`，取 `history` 末条非 tool 消息前 40 字符作 preview（用 history 而非 context——preview 要反映用户真实对话），**cwd 随条目下发**，按 `updatedAt` 降序。消费端：

- TUI 会话选择器（`ui/src/tui/features/sessions/view.tsx`）按 cwd 标注；
- WebUI 侧栏（`ui/src/webui/features/sessions/use-sessions.ts` + `ui/src/webui/components/sidebar/view.tsx`）把会话按 cwd 组成**项目树**：新增项目走 `new_session { cwd }`（经 /api/fs 目录浏览器选路径），删除项目 = 逐个 `delete_session` 该 cwd 下全部会话 + 前端 `forgetProject()`（`ui/src/webui/app/app.tsx` 的 `handleDeleteProject`）。

单文件损坏不阻断列表——`list()` try/catch 返回占位项「（文件损坏）」。

> 交叉阅读：sessionPermissions 的语义与 revoke 见 06-权限系统；落盘前的 context 压缩见 `agent/src/turn/compactor.ts`（非劣原则：摘要比原文长则不压缩）。
