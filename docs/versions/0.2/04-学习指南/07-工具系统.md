# 07-工具系统

## Tool 契约

`agent/src/tools/types.ts`（全文仅 24 行，值得通读）：

```ts
export interface Tool {
  name: string
  description: string
  schema: z.ZodTypeAny          // zod 校验 LLM 返回的参数（ToolExecutor 用）
  parameters: Record<string, unknown>   // 暴露给 LLM 的 OpenAI JSON Schema（registry.schemas() 用）
  execute(args: unknown, ctx: ToolContext): Promise<ToolResult>
}
export type ToolResult = { content: string } | { error: string }
export interface ToolContext { cwd: string; signal: AbortSignal; shellProgram?: string; shellTimeoutMs?: number }
```

两个关键约定：**错误返回 `{ error }` 而非抛异常**——工具错误是「给模型的反馈」，回填为 tool 消息继续循环，不中断整轮（抛异常由 runAndEmit 的 try/catch 兜底，见 `agent/src/turn/tool-executor.ts`）；每个工具文件夹内 `schema.ts`（zod + JSON parameters）与 `tool.ts`（实现）分离，`index.ts` re-export。

一个工具的完整文件形状（edit_file 为例）：

```
agent/src/tools/edit_file/
├── index.ts      # re-export EditFileTool（唯一脸面）
├── schema.ts     # editFileSchema（zod：path/old_string/new_string）+ editFileParameters（OpenAI JSON Schema）
└── tool.ts       # class EditFileTool implements Tool
```

## 注册表统一关口

`agent/src/tools/registry.ts` 的 `ToolRegistry.register()` 同时做三件事（类头注释称「统一关口立法」）：

1. **合规转换**：`TOOL_NAME_RE = /^[a-zA-Z0-9_-]{1,64}$/` 是供应商 API 对函数名的硬约束（不合规会被整个请求 400）。原名合规原样注册；不合规整体哈希为 `h-<sha256 前 12 位>` 确定性标签（同名必同标签），变换落在 Tool 对象的 name 字段上，保证 `schemas()` 发出的名字必然合规。
2. **冲突可见失败**：目标标签已占用时 `throw`（错误信息提示「请调整来源命名」），绝不静默覆盖——静默顶掉会让先注册的工具无声失联。
3. **身份记录**：每个工具带 `ToolIdentity`（`identityById` Map），与工具同增同删（`unregister` 双删）。身份是一切「工具从哪来」语义的唯一事实源：权限服务键匹配（见 06-权限系统）、UI 来源标注（`tools_list` 载荷）都查它，**从不解析 LLM 可见名**（哈希标签不透明也无妨）。

`withBuiltins()` 注册 7 个内建工具；`schemas()` 每次现算组装 `{ type: 'function', function: {...} }[]`；`labelsWhere(pred)` 按身份找标签（MCP 按服务摘除的依据）。

```ts
// agent/src/tools/registry.ts（register 核心三步，第 53~71 行）
register(tool: Tool, identity: ToolIdentity = { kind: 'builtin' }): string {
  const label = TOOL_NAME_RE.test(tool.name) ? tool.name
    : `h-${createHash('sha256').update(tool.name).digest('hex').slice(0, 12)}`
  if (this.tools.has(label)) throw new Error(`工具注册名冲突：${label}…`)
  // 哈希改写保留原型：class 实现的 Tool 方法在原型上，浅拷贝会把 execute/schema 一起丢掉。
  this.tools.set(
    label,
    label === tool.name
      ? tool
      : Object.assign(Object.create(Object.getPrototypeOf(tool)), tool, { name: label }),
  )
  this.identityById.set(label, identity)
  return label
}
```

## 7 个内建工具逐个要点

**shell**（`agent/src/tools/shell/tool.ts`）：显式解释器 spawn、不用 `shell:true`（避开 DEP0190）。解释器选择在 `support/interpreter.ts` 的 `resolveShell()`：配置的 `shellProgram` 映射为 `{program, flag, kind}`；未配置按平台（win: `cmd /c`，其它：`bash -c`）；**未知解释器或本机未检出（`support/detect.ts` 的 `detectShells`）回退平台默认**，不猜测语义。spawn 形态按解释器分两支：win 的 cmd 分支用 verbatim 引号包裹形态——`spawn(ComSpec ?? 'cmd.exe', ['/d', '/s', '/c', `"${command}"`], { windowsVerbatimArguments: true })`（MSVCRT 转义与 cmd 引号规则不兼容，`/d` 跳过 AutoRun、`/s` 配套引号剥离、verbatim 禁止 node 转义，三者缺一不可）；powershell/pwsh/bash/sh 保持 `spawn(exe, [flag, command])` 数组形态，执行程序优先用 `support/detect.ts` 的 `resolveShellPath()` 解析的**绝对路径**（绕过 CreateProcess 的 System32 先于 PATH 搜索序；PATH 扫描命中 System32 目录下的 bash 判为 WSL 启动器剔除，防「检测说 Git Bash、执行是 WSL bash」脱节）。stdin 显式 `'ignore'`（读输入的交互命令立即得 EOF，不再挂满超时）。超时 `SHELL_TIMEOUT_MS = 120_000`——超时杀进程树（`support/kill-tree.ts`，POSIX 用 detached 进程组 `kill(-pid)`，Windows 用 taskkill /T）并把已有输出 + 超时说明回填模型，另有二级看门狗兜「杀后 close 永不到达」。输出采集有界（1MB cap，超限丢弃字节数在回执注明）。取消三件套之一：`killTree` 挂在 `ctx.signal` 的 abort 上。`support/guidance.ts` 的 `shellGuidance()` 把「实际解释器 + 语法要点」注入系统提示（模型训练偏向 bash，Windows 上不注入则 cmd 语法差异是失败主因）。

**edit_file**（`agent/src/tools/edit_file/tool.ts`）：old_string 逐字符匹配、替换**首次出现**（`String.replace` 单次语义）；找不到返回 `old_string 未找到`。替换用**函数形态** `text.replace(old_string, () => new_string)`——字符串形态的替换值里 `$&`/`$` `/`$'` 会被重新解释篡改，函数返回值按字面插入。落盘走 `atomicWriteFile` 原子写。回执带**行号锚点**：`startLine` = old_string 首次出现处的 1-based 行号，写进「已替换 1 处（原第 N 行起）」——模型知道改动落点便于连续编辑，UI 的 `ui/src/shared/tool-display.ts` 也解析它给 diff 标真实行号（「回执即契约」：格式改动须两处同步）。

**ls**（`agent/src/tools/ls/tool.ts`）：单层不递归、结构化输出（目录在前加 `/`、文件在后带人类可读大小）；隐藏文件正常显示（agent 需要看 .gitignore）；`MAX_ENTRIES = 500` 封顶并注明总数。

**glob / grep 共享遍历器**（`agent/src/tools/traverse/walker.ts` 的 `walkFiles()`）：迭代式 DFS 产出 posix 相对路径；`ignore.ts` 的 `IGNORED_DIRS` 黑名单剪枝（node_modules/.git/dist/build/out/.next/coverage/.dogegg）；**symlink 一律跳过**（防环与逃逸 root）；目录间隙 `signal.throwIfAborted()` 支持取消中断；条目排序保证跨平台确定顺序。glob（`glob/tool.ts`）：`globToRegExp` 来自 bridge（与权限参数化规则同一份实现），`MAX_MATCHES = 100` 封顶；grep（`grep/tool.ts`）：输出治理**四层**——单行 500 字符截断 → 单文件 20 命中封顶 → 总命中 100 封顶 → 总输出 8000 字符 cap，外加 1MB 大文件跳过与 8KB 头 NUL 探测跳过二进制；`output_mode` 三态（content/files_with_matches/count）；回执格式 `相对路径:行号: 内容`。gitignore 过滤经 `traverse/ignore-gitignore.ts` 的 `loadGitIgnore`（会话 cwd 根）注入 walker——「用户项目的忽略意愿就是搜索的忽略意愿」。

**read_file / write_file**（各自 `tool.ts`）：read_file 先 stat 拦下超 1MB 的大文件（指引改走 grep 定位），再读原始 Buffer 做**前 8KB NUL 探测**（复用 traverse 的 `isBinaryFile`，与 grep「二进制跳过」同一口径——二进制直接拒绝不吐乱码），解码后剥 UTF-8 BOM 首字符；write_file 用 `atomicWriteFile` 原子写（整文件覆写中途崩溃的半截内容不可自愈）。失败均返回 error 串。

**路径解析统一入口**：文件类工具（read/write/edit/ls/glob/grep）的目标路径都经 `agent/src/shared/target-path.ts` 的 `resolveTargetPath(cwd, path)`——一律 `resolve` 而非 `join`（Windows 上 `join(cwd, 绝对路径)` 会吞掉盘符冒号产生变形路径，权限分类与实际打开会指向不同文件）；绝对参数原样 resolve、相对参数基于会话 cwd resolve，`set_cwd` 切换目录后天然生效。不做存在性检查与 cwd 边界限制——越界与否由权限引擎按真实位置判定（见 06-权限系统）。

## 输出治理

工具回执的最后关卡在 `agent/src/turn/tool-executor.ts` 的 `runAndEmit()`：`'content' in result ? truncate(result.content) : ERROR: ...`，`truncate` 来自 `agent/src/context/truncate.ts`（`TOOL_RESULT_CAP = 8000`，超出加「已截断」标注）。三层治理叠加：工具内部封顶（ls 500/glob 100/grep 四层）→ 统一 8000 cap → 压缩机制兜底（见 `agent/src/turn/compactor.ts`）。原则：截断处**注明**而非静默砍断，让模型知道还有更多并自行收窄。

> 权限侧：工具本身不做权限判定——全部经 `ToolExecutor` 的 classify 网关（见 02-一条消息的旅程 与 06-权限系统）。
