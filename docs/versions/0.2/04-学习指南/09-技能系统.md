# 09-技能系统

Skills 是「预置的指令文件」：每个 skill 是一个含 `SKILL.md` 的目录，调用时正文作为用户消息进入轮次。实现全在 `agent/src/skills/manager.ts`（约 235 行）与 `agent/src/skills/parser.ts`，类头注释即立法清单。

## 两级目录与命名立法

- **只扫两个目录**：用户级 `~/.dogegg/skills/`（构造参数注入，测试可换临时目录）、项目级 `<cwd>/.dogegg/skills/`（`setProjectDir(cwd)` 随会话目录走，/cd 后由门面重扫广播）。
- **skill 名 = 目录名**（唯一事实源），必须匹配 `SKILL_NAME_RE = /^[a-z0-9][a-z0-9-]*$/`——防路径穿越 + 保证命令名合法。SKILL.md frontmatter 里的 `name:` 仅文档性（`parser.ts` 头注释）。
- **同名冲突**：项目级覆盖用户级（调用/联想取项目级），`list()` 两条都返回（面板两组都可见）。
- 缓存：`list()` 结果缓存于 `this.cache`——系统提示段与 token 估算是热路径；写操作/`setProjectDir`/`invalidate()` 失效。`agent.ts` 的 `emitSkillsList()` 广播前**先 invalidate**，保证外部手改文件可见。

## frontmatter 解析（parser.ts）

`parseSkillMd()` 是**无 YAML 依赖**的最小解析：识别 `---` 围栏，块内只取 `description:` 单行键值（渐进披露的关键字段），其余键忽略；无围栏时全文即正文。`skeletonSkillMd()` 生成骨架（name/description + `$ARGUMENTS` 提示行 + 占位正文）——「增」操作的产物，格式正确、立即可用。

## 渐进披露（promptSection 一行广告）

`promptSection()`（manager.ts 第 211 行）是注入系统提示的清单段（经 `agent/src/context/assembler.ts` 的 `extra` 回调拼进 systemPrompt）：每个可用 skill **只列一行** `- 名字：描述（路径）`，加一段引导「请求与描述相关时，先用 read_file 读取其 SKILL.md 获取完整指令再执行」。条数有上限（`PROMPT_SECTION_LIMIT = 60`）——技能段是 system prompt 的固定开销，压缩省不回来；超限只列前 60 条并指路 /skills 完整清单。正文不进提示——模型按需自取，这就是渐进披露：几十个 skill 也不撑爆上下文。无可用 skill 返回空串（不注入）。停用/缺失条目**永不广告**（`filter(s => s.enabled && !s.missing)`）。

## 停用名单三态合成

| 状态 | 判定 | 系统提示 | 联想 | 调用 |
|---|---|---|---|---|
| 启用 | 在目录 + 可解析 + 不在名单 | 一行广告 | 出现 | 可竞争 |

| 缺失(missing) | 名单在案但目录消失 | 不出现 | 出现（标「目录已不存在」） | 退出竞争 |

## CRUD（skills_manage 消息的实现归属）

`agent/src/agent.ts` 的 `handleSkillsManage()`（第 425 行）分发五个 action，失败转 `notice`（带 `channel: 'skills'`，面板内联可见）：

- **create**：`create(scope, name, description)` 生成骨架；名称非法/已存在抛错；同名重建（此前停用后被删）视为全新开始——从停用名单移除。
- **update**：整文件替换 SKILL.md（TUI 的落点是 `$EDITOR`：`ui/src/tui/app/app.tsx` 的 `openInEditor()` 暂停 raw mode → `spawnSync` 阻塞至编辑器退出 → 恢复并重拉清单；WebUI 是编辑弹框）。
- **delete**：`rmSync` 整目录（幂等），名单同步清理不留孤儿。
- **get**：回 `skill_content` 消息（编辑弹框/预览数据源），不重播清单。
- **toggle**：`setEnabled()` 增删名单条目；对 missing 条目「启用」即清理孤儿记录（`agent.ts` 文案区分「已清理」与「已启用」）。

所有写操作前过 `assertInside()` 双保险：name 再过 NAME_RE + `join` 结果 `startsWith(dir)` 确认不越出根目录。

## forInvocation：$ARGUMENTS 替换

`forInvocation(name, args)`（第 188 行）：在**可用**（enabled 且非 missing）条目里竞争，项目级优先命中 → 读正文 → 含 `$ARGUMENTS` 占位则 `replaceAll('$ARGUMENTS', trimmedArgs)`（函数式替换——字符串形态的替换值会把 `$$`/`$&` 等特殊序列重新解释改写参数），无占位且带参时追加「用户参数：…」段。停用即退出竞争（项目级停用时同名用户级照常生效）；全部未命中抛错（门面转 notice）。

调用入口两条：UI 消息 `invoke_skill`（`agent.ts` 第 666 行——`skills.forInvocation` 后直接 `turnRunner.submit(skillText, ...)`，**skill 就是普通用户消息**，不进 loop 的特殊分支；开轮前同样等 MCP 重建收敛）；斜杠命令 `/name args`（`ui/src/shared/commands.ts` 的 `parseCommand` 把非保留字首词映射为 `invoke_skill`，内置命令优先防同名覆盖）。
