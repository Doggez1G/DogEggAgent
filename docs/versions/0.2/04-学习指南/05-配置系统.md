# 05-配置系统

## config.json 的字段（schema 真相）

一份最小可用的配置长这样（字段默认值由 zod 填充，落盘时全量展开）：

```json
{
  "defaultProvider": "deepseek",
  "defaultModel": "deepseek-chat",
  "providers": [{
    "name": "deepseek", "protocol": "openai",
    "baseURL": "https://api.deepseek.com/v1", "apiKey": "sk-...",
    "models": [{ "name": "deepseek-chat", "contextWindow": 128000, "maxOutput": 16384, "reasoning": false }]
  }],
  "permission": {
    "allow": { "read_file": { "whole": true, "patterns": [] } },
    "reject": {},
    "ask": { "shell": { "whole": true, "patterns": [] } }
  },
  "mcpServers": [{ "name": "playwright", "enabled": true, "transport": { "type": "stdio", "command": "npx", "args": ["@playwright/mcp@latest"] } }]
}
```

Schema 定义在 `bridge/src/contract/config.ts` 的 `configSchema`，全部字段带默认值（zod `.default()`）：

| 字段 | 说明 |
|---|---|
| `providers[]` | `providerSchema`：name/protocol（当前仅 `'openai'`）/baseURL/apiKey/models[] |
| `models[]` | `modelSchema`：name/contextWindow(默认 128000)/maxOutput(默认 16384)/reasoning(默认 false) |
| `defaultProvider` / `defaultModel` | 未设时加载期回退到首个（见下 `ConfigStore.load`） |
| `systemPrompt` | 存**路径**而非正文，`agent/src/context/prompt/load.ts` 现读 |
| `maxIterations` | -1 无限（默认）/ 正整数上限；0 非法（refine 拒绝） |
| `maxRetries` | 默认 3 |
| `shellProgram` | 可选解释器名，`agent/src/tools/shell/support/interpreter.ts` 的 `resolveShell` 消费 |
| `permission` | v3 三桶（见 06-权限系统）；出厂默认：读类工具 allow、写类/命令 ask |
| `mcpServers[]` | `mcpServerSchema`：name/enabled/transport（stdio \| http 判别联合） |

「能否对话」由 `isConfigured()`（同文件）判定而非 schema 强制——schema 刻意放宽（name/baseURL 允许暂时为空），支持 /config 里「先建空节点、逐字段填写」的编辑流。

## 加载路径（ConfigStore.load + loadConfigOrExit）

`agent/src/config/store.ts`：

- `findConfig()`（模块私有）：项目内 `.dogegg.json` 优先，否则 `~/.dogegg/config.json`，都没有返回 null。
- `load(raw?)`：`configSchema.parse(data)` 完成 zod 校验 + 默认值填充；若有 provider 则补默认 provider/model（空配置保持无默认，让程序能启动、引导用户去 /config）。
- `save(config, path?)`：写回既有路径或 `~/.dogegg/config.json`；`defaultPath` 构造参数是**测试接缝**——会触发落盘的测试必须注入临时路径，否则覆写用户真实配置。

报错路径在组合根 `bin/dogegg.ts` 的 `loadConfigOrExit()`：catch `ZodError` 后把 issues 逐条拼成 `${path}：${message}`，输出**可执行的恢复指引**——待修文件（`store.sourcePath()`）、改写为 `{whole, patterns}` 或整段删 permission 回默认、本地实际存在的 `docs/config.md` 路径——然后 `process.exit(1)`。绝不裸抛 zod 堆栈。`main-web.ts` 有同构版本。

## 运行时解析与联动

- `agent/src/config/resolve.ts` 的 `resolveCurrent(config)`：defaultProvider 未命中回落首个 provider，model 同理。`agent.ts` 的 `current()` 是唯一消费入口（status 推送与参数解析都从这取）。
- 配置编辑成功后 `agent.ts` 的 `onConfigChanged()`（第 333 行）整体替换 ctx 中可变的三成员：`ctx.config = config`；`PermissionManager` 重建但先 `snapshotPermissions()` 后 `restore()`（**运行时提升跨配置编辑保留**）；`ContextAssembler` 重建（新 systemPrompt/skills/shell 引导下轮生效）；随后 `rebuildMcp()` diff 重建 + `emitStatusState()` 即时刷新状态栏。

## 编辑器原语（config_set / add / remove + validate / 回滚）

链路：UI 发 `config_set/add/remove` → `agent/src/config/controller.ts` 的 `ConfigController`（统一入口 `edit()`：`gate.busy` 阻塞 → 委托 editor → 失败 emit notice → 成功则 `onConfigChanged` + `configs.save` + `emit config_updated`）→ `agent/src/config/editor/editor.ts` 的 `ConfigEditor`。

- `set(path, value)`：`editor/paths.ts` 的 `parseConfigSet` 把点号路径文法解析成操作对象（非法路径返回 ok:false），`editor/mutate.ts` 的 `applySet` 落到 config。
- `add(path, value)` / `remove(path, index, providerIndex?)`：同构；remove 只认 `providers` 与 `models` 两个路径，`providerIndex` 处理「models 属于哪个 provider」的二层消歧。
- `setMcpServers(servers)`：/mcp 面板全局写原语，不走点号文法（数组结构由 zod 整体校验）。
- **回滚机制**（`editor.ts` 的 `afterEdit()`）：每次变更后 `editor/validate.ts` 的 `validateConfig` 做 `configSchema.safeParse` + `findDuplicateName` 重名检查；失败返回 `lastGood` 快照 + 首条 issue 消息，config 回滚、错误经 notice 面板可见。`lastGood` 始终是最近一次校验通过的 `structuredClone`。
- 编辑期语义细节：schema 刻意放宽让「空名 provider/model」可以共存（`findDuplicateName` 仅对**非空名**判重，`editor/validate.ts` 第 3 行注释），所以「先建三个空节点再逐个填」的编辑流不会被中途卡死；`isConfigured` 只在 submit/轮次入口把关。
- `/config` 树怎么用这些原语：`ui/src/tui/features/config/build.ts` 的 `buildEntries()` 把每层字段翻译成 `TreeCtx.set/add/remove` 回调（`ui/src/tui/features/config/entries.ts`），最终都变 `port.post({ type: 'config_set' | ... })` 消息——**UI 不持有配置写逻辑**。

## 配置演进不兼容原则

`contract/config.ts` 头注释立法：v3 结构化 permission 是**唯一合法格式**，旧格式（M1 条目数组 / v2 字符串数组）**不受兼容**——加载即报错并指引（ADR-0013）。理由：兼容层的解释代码会永久盘踞在权限这种安全关键路径上；报错 + 人话指引 + 一键回出厂默认（删字段）比静默转换更诚实。`permissionSchema` 的 `superRefine` 还做作用域前缀与服务键 `mcp:` 前缀的加载期校验（详见 06-权限系统）。
