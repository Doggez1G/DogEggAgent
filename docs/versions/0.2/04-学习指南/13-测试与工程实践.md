# 13-测试与工程实践

## vitest 全仓组织（76 个测试文件）

根 `package.json`：`npm test` = vitest watch，`npm run test:run` 全量单次；`npm run typecheck` 对四包 tsconfig 分别 noEmit。配置在根 `vitest.config.ts`。CI 在 `.github/workflows/ci.yml`（push/PR 跑构建 + typecheck + 全量测试）。测试按包镜像源码结构（`<包>/test/` 与 `<包>/src/` 同构）：

- `agent/test/`（51 个）：`turn/`（loop/state/compactor/title/summarize/tool-executor/turn-runner-progress）、`tools/`（registry/shell/shell-killflow/file-tools/glob/grep/ls/traverse/ignore-gitignore/detect）、`permission/`（permission/realpath/derive/mcp-server-keys）、`config/`（loader/editor/controller/resolve + editor/paths）、`session/`（session/delete-current/set-cwd/clear-persist/conversation-checkpoint/session-switch）、`skills/`（skills/skills-edge/parser/invoke）、`mcp/`、`llm/`（request/retry/stream/streaming）、`context/`（context/prompt-load）、`shared/`（logger/logger-rotate/utils）、门面级 `agent.test.ts`/`agent.turn.test.ts`/`agent.recovery.test.ts`/`agent.system-prompt.test.ts`/`agent.mcp-notice.test.ts`。
- `bridge/test/`（6 个）：`architecture.test.ts`（见 03）、`channel.test.ts`（Port 时序）、`glob.test.ts`（匹配文法）+ 契约 schema 三件（`agent-to-ui-schema`/`ui-to-agent-schema`/`config-schema`）。
- `server/test/`（6 个）：`channel/`（`sse.test.ts` + `sse-e2e.test.ts`，真实 HTTP 往返）、`http/`（http-server/static-files）、`fs/browse`、`shells/detect`。
- `ui/test/`（13 个）：`shared/`（reducer/commands/status/tool-display——两端的公共防线）+ `tui/`（config 树/keys/markdown/path-suggest/theme/view-state）+ `webui/`（logic/mcp-form/sse-client）。

命名与写法惯例：中文 describe/it 描述（与源码注释语言一致）；每个测试文件对应一个「知识单元」而非一个源文件——如 `delete-current.test.ts` 只测「删除当前会话的接管语义」这一条立法。

## 测试接缝注入

`agent/src/agent.ts` 的 `AgentOptions` 是接缝清单（第 27 行，头注释直接写明用途）：

```ts
client?: LlmClient            // 表征测试注入假 client（不打真 API）
sessionsDir?: string          // 会话目录 → 临时目录（缺省 ~/.dogegg/sessions）
registry?: ToolRegistry       // 工具注册表子集（隔离被测工具）
skillsUserDir?: string        // 用户级 skills 目录 → 临时目录
configPath?: string           // ⚠️ 会触发配置保存的测试必须注入，否则覆写用户真实配置
mcpStartupTimeoutMs?: number  // MCP 启动超时（缺省 30s）——挂死 server 用例注入小值
```

组合根（`bin/dogegg.ts` / `main-web.ts`）只传 `logger`——其余参数是纯测试接缝。同类接缝还有：`SessionStore(baseDir)`、`SkillsManager(userDir)`、`ConfigStore(defaultPath)`、`ToolRegistry` 可独立构造（`new ToolRegistry([...])`）、TUI keys handler 的 spy api（`ui/test/tui/keys.test.ts`）。表征测试的典型写法：假 `LlmClient` 回放预设的 tool_calls 序列，断言 emit 出的消息序列——`agent/test/turn/loop.test.ts` 即此模式。

## 架构测试（依赖矩阵）

`bridge/test/architecture.test.ts` 把 AGENTS.md 的架构约束变成可执行断言，四组：

1. **依赖方向**：agent↛ui、ui↛agent、bridge↛兄弟包、server↛ui、webui↛agent/server、shared↛agent。
2. **模块边界**：所有 index.ts(x) 只允许 import 与 re-export 行；跨域相对 import 只允许一层路径。
3. **agent 子域矩阵**：能力域间依赖边白名单（turn→session/llm/tools/context/permission/ROOT 等），`shared` 作为跨域底层支撑层显式豁免（任何域可依赖）。
4. **前端边界**：tui 与 webui 互不依赖；features/components 不得 import 装配层 `app/`。

实现是文件系统扫描 + import 正则抽取（无 AST 依赖），放在 bridge——「桥是边界的所有者，由它守门」。新增包/改 import 习惯前先跑 `npm test` 看它红不红。

## 提交规范

git log 显示全仓使用**中文 conventional commits**：`type(scope): 中文描述`，type 用 feat/fix/refactor/docs/test/chore，scope 是模块名（permission/skills/tui/webui/mcp/session…），破坏性变更加 `!`（如 `refactor(permission)!: 服务键强制 mcp: 前缀——撤销双写法回退（用户立法：裸键不支持）`）。描述风格是「结论 + 立法理由」——读 git log 本身就能学到每次架构决策的动机。
