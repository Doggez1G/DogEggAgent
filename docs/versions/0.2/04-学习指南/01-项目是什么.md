# 01-项目是什么

## 产品定位

DogEggAgent 是一个**对话式代码编辑 agent**：用户在终端或浏览器里用自然语言布置任务，模型（OpenAI 兼容协议）通过循环调用工具（读/写/改文件、执行 shell、搜索代码）自主完成工作。README 的自我描述是「Code-editing agent with terminal (Ink) and browser (React) frontends over a headless core —— built to learn how agents work」，学习如何实现 agent 本身就是项目目标之一，所以代码里的「立法」注释密度很高。

关键词是 **headless core**：核心（agent 包）没有任何 UI 依赖，它只通过一个 `AgentPort` 接口（`bridge/src/channel/port.ts`）收发消息。终端前端与浏览器前端都只是把消息渲染出来的「观察者」。

## 能力全景

- **对话循环**：`agent/src/turn/loop.ts` 的 `AgentLoop` 实现「问模型 → 有 tool_calls 就执行 → 结果回填 → 再问」的主循环，配 10 态状态机（`agent/src/turn/state.ts`）驱动 UI 反馈。
- **内建工具 ×7**：`agent/src/tools/` 下 read_file / write_file / edit_file / shell / ls / glob / grep（详见 07-工具系统）。
- **MCP 客户端**：`agent/src/mcp/manager.ts` 连接外部 MCP server（stdio / Streamable HTTP 双 transport），其工具适配进统一注册表（详见 08-MCP客户端）。
- **权限系统**：`bridge/src/contract/permission.ts` 的三桶匹配引擎 + `agent/src/permission/manager.ts` 的运行时会话提升；读类工具默认放行、写类/命令默认询问（详见 06-权限系统）。
- **技能（skills）**：`agent/src/skills/manager.ts` 扫描 `~/.dogegg/skills/` 与 `<cwd>/.dogegg/skills/` 的 SKILL.md，渐进披露进系统提示，`/名字` 即可调用（详见 09-技能系统）。
- **双端 UI**：TUI（Ink，`ui/src/tui/`）与 WebUI（React + SSE，`ui/src/webui/`），共享同一套消息契约与共享 reducer（`ui/src/shared/`，详见 11/12 章）。
- **会话持久化**：`agent/src/session/store.ts` 把 history/context/权限提升/用量/压缩计数落成 `~/.dogegg/sessions/<id>.json`，resume 完整恢复（详见 10-会话与持久化）。
- **上下文工程**：`agent/src/context/` 负责 token 估算、窗口逼近 80% 时自动压缩（`COMPACTION_THRESHOLD = 0.8` 定义在 `bridge/src/contract/shared.ts`，跨端共用）。
- **传输双通道**：同进程 `InMemoryChannel`（`bridge/src/channel/in-memory.ts`）给 TUI；`SseChannel` + POST（`server/src/channel/sse.ts`）给 WebUI（详见 04-消息契约）。

## 顶层目录一览

```
DogEggAgent/
├── bin/dogegg.ts        # 唯一 CLI 组合根：dogegg → TUI；dogegg -web → WebUI
├── main-web.ts          # dev:web 的 WebUI 组合根（VITE_DEV 时静态目录为 null）
├── agent/               # 核心包：对话循环/工具/权限/会话/MCP/skills/配置
├── bridge/              # 契约包：消息类型 + zod schema + Port 抽象 + 匹配引擎
├── ui/                  # 前端包：tui/ 与 webui/ 两个子域 + shared/
├── server/              # 传输包：SSE 通道 / HTTP 路由 / 静态文件 / fs 浏览 / shell 检测
├── build.mjs            # esbuild 打包脚本
├── vitest.config.ts     # 全仓测试配置
└── docs/                # docs/adr/（13 篇决策记录）+ docs/versions/0.2/（本指南所在）
```

## 四包 src 一览（按读代码的先后顺序）

**agent/src/**（最大的一包）
```
agent.ts        # 门面：唯一的 Agent 类，消息路由 + emit 埋点 + 依赖组装
ctx.ts          # AgentContext：config/permission/assembler/machine/gate 五件套
turn/           # 轮次引擎：runner/loop/state/tool-executor/pending/compactor/title
tools/          # 注册表 + 7 工具 + traverse 共享遍历器
permission/     # manager.ts（运行时层）+ derive.ts（范围提升推导）
session/        # conversation（工作集）/ manager（生命周期）/ store（落盘）
config/         # store/controller/resolve + editor/（编辑原语与回滚）
context/        # assembler/prompt/token/compaction/truncate
llm/            # client-for 分派 + provider/openai（fetch SSE 手写流）
mcp/            # manager.ts + project.ts（.dogegg/.mcp.json）
skills/         # manager.ts + parser.ts
shared/         # gate.ts（并发闸门）/ logger.ts / support.ts
```

**bridge/src/** —— `contract/`（shared/config/permission/glob/tools/agent-to-ui/ui-to-agent 及对应 schema）与 `channel/`（port/in-memory）。没有进程，只有「语言」。

**ui/src/** —— `shared/`（reducer/commands/tool-display 等两端共用纯逻辑）、`tui/`（app/components/features/theme/markdown）、`webui/`（app/components/features/channel/theme）。

**server/src/** —— `channel/sse.ts`、`http/`（http-server/router/static-files）、`fs/browse.ts`（WebUI 目录选择器后端）、`shells/detect.ts`（本机 shell 扫描）。

## 与同类工具的差异点

与 Claude Code 这类闭源 CLI 相比，DogEggAgent 的源码级特色是：**一个 agent 内核同时喂两个前端**（消息契约完全复用，见 12-WebUI 的「对称性」小节）；**权限引擎住契约包**（`classifyPermission` 是纯函数，UI 展示与 agent 判定共用一份实现，见 06-权限系统）；**配置编辑走消息原语**（`config_set/add/remove` 而非直接改文件，见 05-配置系统）。
