# 06-权限系统

权限分两层：**配置层三桶**（静态规则，schema 与匹配引擎住 `bridge/src/contract/`）+ **运行时会话提升**（`agent/src/permission/manager.ts` 内存态）。触发点在 `agent/src/turn/tool-executor.ts` 的 `execute()`（见 02-一条消息的旅程 第 7 站）。

## 运行时调用链（谁在什么时候调谁）

```text
ToolExecutor.execute (agent/src/turn/tool-executor.ts)
  └─ permission.classify(tool, args, cwd)        # agent/src/permission/manager.ts
       ├─ normalizeArgs:  args.path → realTargetPath（realpath 绝对 posix）
       ├─ normalizeRules: path 主参数桶键的 patterns 按锚点归一（mcp: 键跳过）
       └─ classifyPermission(cfg, tool, args, sessionRules, identities)   # bridge 纯函数
            ├─ toolEntryMatches: 键名精确/通配 → whole? → patterns 对主参数匹配
            └─ mcpServerHit:     ToolIdentity.kind==='mcp' → mcp:<server> 键
  └─ verdict==='ask' → requestPermission() 挂起 → 决议后 permission.apply() 落库
```

## 三桶 v3 结构

`bridge/src/contract/config.ts` 的 `permissionSchema`：`{ allow, reject, ask }` 每桶是 `Record<键, { whole: boolean, patterns: string[] }>`。语义立法：

- `whole: true` → 整键命中（整工具 / 整个 MCP 服务组），patterns 不参与匹配、仅作取消整选后的恢复内容；
- `whole: false` → patterns 生效（OR 匹配）；**空数组 = 键存在但不命中任何规则**（编辑中的空选态，fail-closed）；
- 出厂默认（configSchema 的 permission default）：`allow` 桶 whole 放行 read_file/ls/glob/grep（只读安全）；`ask` 桶 whole 询问 write_file/edit_file/shell；`reject` 空。未列出的工具一律 ask——**固定安全默认不可配置**（TUI 配置树里那行只读说明，见 `ui/src/tui/features/config/build.ts`）。

## 两类键

**内建工具名键**：如 `write_file`、`read_file`。`whole: false` 时模式落到**主参数**上匹配——主参数表 `PRIMARY_SPECIFIER`（config.ts）立法：`shell → 'command'`，其余（read/write/edit/ls/glob/grep）→ `'path'`（`primarySpecifier()` 缺省 path）。

**MCP 服务键**：`mcp:<服务裸名>`（如 `mcp:playwright`）。匹配在 `bridge/src/contract/permission.ts` 的 `mcpServerHit()`：按工具**注册期身份**（`ToolIdentity = { kind: 'mcp', server, name }`，来自注册表 `identities()`）找 `mcp:<server>` 键；`whole: true` 整组生效，否则 patterns 与**内部工具名**做 `matchWildcard`——【工具启用匹配，永不涉及执行参数】。`mcp:` 前缀立法（2026-09 提交 6e10780/a86cac8）：前缀使服务键与内建名键空间正交，「是不是服务键」语法自明；**裸服务名键加载期直接拒绝**（configSchema 的 superRefine 交叉校验 mcpServers 名单），杜绝静默失配；运行时 MCP 重建完成后还有一道 `warnMcpPermissionKeys()` 复查（裸服务名 / 遗留 `mcp__x__y` 标签形态键发 notice，见 `agent/src/agent.ts`）。

## 判定优先级（立法）

`classifyPermission()`（contract/permission.ts 第 42 行）五行定终身：

```ts
if (hit('reject')) return 'reject'
if (sessionHit(sessionRules, tool, args)) return 'allow'
if (hit('ask')) return 'ask'
if (hit('allow')) return 'allow'
return 'ask'
```

1. reject 硬拒绝最优先（安全立法）；
2. **sessionRules（会话提升）第二**——它是用户本会话内最新的显式意图，除 reject 外压过一切，否则对最常提升的 ask 桶工具提升会失效；配置层 reject 仍能压住它，且 /permissions 可撤销；
3. ask 规则压过 allow 规则——显式「例外强制确认」压过宽放行。

匹配函数按主参数分派：path 用 `matchGlob`（`*` 单段、`**` 跨段——段边界是安全性质）；command 与工具名用 `matchWildcard`（平文本，`*` 任意字符）。两函数都在 `bridge/src/contract/glob.ts`。sessionHit 内部同语义：patterns 空 = 整工具提升（运行时内存结构，不受「空选 = 不命中」立法约束）。

## realpath 防逃逸

`agent/src/permission/manager.ts` 的 `realTargetPath()`：classify 前把 args.path 归一为**真实绝对 posix 路径**——目标存在走 `realpathSync`（OS 沿符号链接解析，含 Windows junction）；目标不存在（write_file 新建）取**真实父目录 + 文件名**；极端情况词法 resolve 兜底。动机：cwd 内的链接指向 cwd 外时，词法路径在规则范围内而实际读取越界（ADR-0010 边界补全；测试 `agent/test/permission/realpath.test.ts`）。所有产出再过 `foldPath()`（P2-12 立法）：win32 上 path 类字符串统一 toLowerCase 后才可比（NTFS 大小写不敏感，bridge 引擎恒大小写敏感——模式侧 `normalizePattern`、参数侧、内置豁免表两侧同步 fold；posix 不 fold；shell 的 command 有大小写语义绝不 fold）。classify 与工具实际 open 是两次独立 IO，符号链接中途换向存在理论 TOCTOU 窗口——本地单用户威胁模型下接受（立法注释写明根治归执行层）。规则侧对称归一 `normalizePattern()`：`./`、`../` → cwd 作用域；`~/` → 主目录；绝对路径折叠；`*` 开头原样保留（glob 从根匹配）。

## 会话提升（apply / snapshot / restore / revoke）

`PermissionManager` 的 `sessionRules: Map<tool, string[]>`：

- **apply**（tool-executor 在决议后调）：`allow_always` → `set(tool, [])` 整工具；`allow_always_scoped` → 追加范围模式（去重；已是整工具则忽略窄范围；path 模式落库时解析为绝对）。范围模式来自 `agent/src/permission/derive.ts` 的 `deriveAlwaysScope()`：command 取首词（`git status` → `git *`）、path 取所在目录（`./docs/**`；文件在 cwd 根部回退精确 `./<file>`，防 `./**` 放行全项目）、推导不出返回 undefined（UI 退回三档，fail-safe）。
- **snapshot / restore**：导出/还原为 `ToolPermission[]`（`bridge/src/contract/shared.ts` 的按工具分组形态）。三个用途：配置编辑重建 manager 时保留授权、`/permissions` 展示（`agent.ts` 的 `permissions_request` 分支）、会话落盘（见 10-会话与持久化）。
- **revoke**：`agent.ts` 的 `permission_revoke` 分支——带 pattern 撤单条、不带撤整工具；撤光整条移除（与配置桶「删光模式留整工具」刻意不同：每条模式是独立授权事件）。
- **会话隔离**：`agent/src/session/manager.ts` 的 `newSession()` 调 `permission.reset()`，resume 时 `reset() + restore(存档)`。

## 加载期校验

`permissionSchema.superRefine`（config.ts 第 90 行）对 `BUILTIN_PATH_TOOLS`（六工具常量）的 patterns 校验**作用域锚点**：必须以 `./`、`../`、`~/`、`*`、盘符或 `/` 开头——字面量打头的裸模式（`docs/**`）从根匹配只能命中盘根条目，必然是忘了写锚点，拒绝加载。patterns 无论 whole 与否都校验（它们是「取消整选后生效」的待命态）。错误经 /config 编辑的 validate/回滚链路浮出（见 05-配置系统）。

> 内置读豁免：`classify()` 尾部对 read_file 落 ask 且目标在 skills 目录（`builtinReadDirs`，构造时已 fold 归一，与参数侧同一坐标系）内时自动 allow——系统提示引导模型读 SKILL.md，不应反复弹审批。
