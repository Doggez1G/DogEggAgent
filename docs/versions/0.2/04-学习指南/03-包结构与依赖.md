# 03-包结构与依赖

## 四包职责

```
agent ←→ bridge ←→ ui
                ←→ server（WebUI 传输）
```

- **@dogegg/agent**（`agent/src/`）：headless 核心。持有 `AgentPort` 订阅与消息路由，跑轮次循环、工具、权限、MCP、skills、会话、配置。**不知道 UI 存在**。
- **@dogegg/bridge**（`bridge/src/`）：契约包。只有两样东西——`contract/`（消息类型 + zod schema + 纯派生函数）与 `channel/`（`AgentPort`/`UiPort` 抽象 + `InMemoryChannel`）。**不依赖任何兄弟包**，也不依赖 Node 特有能力之外的重运行时。
- **@dogegg/ui**（`ui/src/`）：两个前端。`tui/`（Ink）与 `webui/`（React DOM）互不 import；`shared/`（`ui/src/shared/reducer.ts`、`commands.ts`、`tool-display.ts` 等）是两端共用的纯逻辑。只依赖 bridge。
- **@dogegg/server**（`server/src/`）：WebUI 传输层。`SseChannel`（实现 bridge 的 `AgentPort`）+ HTTP 路由 + 静态文件。可 import agent 与 bridge，但**不 import ui**——前端是构建产物被 serve（`server/src/http/static-files.ts`），不是代码被引用。

## 依赖立法（AGENTS.md §2.1 的源码落点）

1. **agent 不 import `@dogegg/ui`，ui 不 import `@dogegg/agent`**，二者都只依赖 bridge。agent 对外只暴露 `Agent` 类 + 消息（`agent/src/index.ts`）；ui 对外只暴露 `renderTui` 与 webui 入口（`ui/src/index.ts`）。
2. **bridge 不依赖任何兄弟包**——契约是边界所有者，只被依赖、不依赖人。
3. **server → agent + bridge 合法**。组合根只有两处：`bin/dogegg.ts`（TUI 与生产 WebUI：`new Agent(channel.agentPort, config, cwd)` + `renderTui(channel.uiPort)`，或 `new Agent(channel, ...)` + `new HttpServer(...)`）和 `main-web.ts`（dev:web）。只有组合根同时 import agent 与前端/服务器。
4. **barrel-only import**：跨模块 import 只能指向 `index.ts`（如 `../shared`、`../tools`），不能深路径（`../shared/errors` 非法）。每文件夹的 `index.ts` **仅 re-export，不写实现**——例如 `bridge/src/index.ts` 全部是 `export * from './contract/...'`；`agent/src/config/index.ts`、`agent/src/turn/index.ts` 同理。
5. **模块 = 文件夹**：一个模块一个文件夹，`index.ts` 是唯一对外脸面，文件夹内其他文件是私有实现（如 `agent/src/config/editor/` 下 `editor.ts`/`mutate.ts`/`paths.ts`/`validate.ts` 外部不可见）。

## 架构测试如何强制

`bridge/test/architecture.test.ts` 把上述约定变成可执行断言（放 bridge 是刻意的——桥守门）：

- **依赖矩阵**：`walk()` 扫四包全部 `.ts/.tsx`，正则抽出 import 语句，逐条断言——agent/ui 互不含对方包名；bridge 不含 agent/ui/server；server 不含 `@dogegg/ui`；`ui/src/webui` 不含 `@dogegg/agent` 与 `@dogegg/server`；`ui/src/shared` 不含 `@dogegg/agent`。
- **agent 子域矩阵**：能力域（turn/session/config/tools/llm/context/permission/skills/mcp）之间的依赖边逐条白名单（如 turn → session/llm/tools/context/permission/ROOT）；`shared` 是显式例外——跨域底层支撑层（gate/atomic/target-path 等）任何域可依赖。前端侧另有边界组：tui 与 webui 互不依赖、features/components 不得 import 装配层 `app/`。
- **index 纯 re-export**：所有 `index.ts(x)` 的非 import/注释行必须匹配 re-export 形式（`export ... from` / `export *` / `export type {...}`），出现 `export const/function/class` 即违规。
- **域门面一层**：跨域相对 import 只允许一层（`../config` 合法，`../config/editor` 违规；`segs[1] !== domain` 判定）。
- 体量红线已移除：「不堆功能进单文件」作为 review 准则而非机械行数断言（测试文件头注释写明 S2 决定）。

## 组合根：唯一允许「什么都 import」的地方

`bin/dogegg.ts`（约 110 行）是全仓唯一的 CLI 组合根，装配顺序值得背下来：

1. `loadConfigOrExit()` —— ConfigStore.load + 报错即退出（见 05-配置系统）；
2. TUI 分支：`new InMemoryChannel()` → `new Agent(channel.agentPort, config, cwd, { logger })` → `renderTui(channel.uiPort)`——两行完成「内核 × 前端」的连接；
3. WebUI 分支（`-web`）：`new SseChannel()`（它本身就是 AgentPort）→ `new Agent(channel, ...)` → `new HttpServer({ router: new Router({ channel }), staticDir, port }).start()`，且 `channel.onConnect = (send) => agent.resendSessionState(send)`（SSE 重连/刷新的会话快照单播恢复）。

两条分支在 Agent 创建后都接 `wireGracefulExit(agent)`（SIGINT/SIGTERM → `agent.dispose()` 优雅退出，第二信号强制退出）。`main-web.ts` 与此同构（dev:web 用），差异只在 `VITE_DEV=1` 时 staticDir 为 null（前端由 Vite dev server 代理）。注意 Agent 构造即自订阅 port——组合根不需要手动接线消息流。

## 模块 = 文件夹的真实样例

以 `agent/src/config/` 为例走一遍约束：`index.ts` 只有 `export { ConfigStore, ConfigParseError } from './store'` 形态的 re-export 行；`editor/` 子文件夹有自己的 `index.ts`（对外只暴露 `ConfigEditor`），`mutate.ts`/`paths.ts`/`validate.ts` 是私有实现——controller.ts 引它们必须写 `./editor`（经 barrel）而非 `./editor/validate`。再如 `agent/src/turn/index.ts` 把 `StateMachine/TurnRunner/AgentLoop/Compactor/summarizeHistory/PermissionResolution` 一并 re-export 给门面，门面 `agent.ts` 的 import 全部是一层路径。

## 为什么这样切（读代码时的判断依据）

- **消息契约独立成包**的原因：agent 与 ui 的唯一耦合面就是消息形状。`bridge/src/contract/agent-to-ui.ts` / `ui-to-agent.ts` 一改动，两端编译立刻红——类型系统充当集成测试。
- **纯派生函数也住 bridge**：`classifyPermission`（`contract/permission.ts`）、`globToRegExp`/`matchGlob`/`matchWildcard`（`contract/glob.ts`）、`isConfigured`（`contract/config.ts`）。它们的输入输出全是契约类型，且被 agent 与 ui 两端消费——放 bridge 保证「一份实现三端永不漂移」（glob.ts 头注释原话）。
- **ui/src/shared 的定位**：不是 agent/ui 的桥，而是 **TUI 与 WebUI 的桥**——同一份 reducer（`ui/src/shared/reducer.ts`）同时被 `ui/src/tui/app/use-chat.ts` 与 `ui/src/webui/features/chat/use-chat-state.ts` 消费，所以两个前端对同一消息流的渲染行为天然一致。

## 读 import 的速查

- `from '@dogegg/bridge'`：消息/配置/权限类型、schema、Port、InMemoryChannel——人人可用。
- `from '../turn'`、`'../tools'`：agent 包内跨模块，必须一层 barrel。
- `from './xxx'`：模块内私有文件，自由。
- `from '@dogegg/agent'` 出现在 bin/ 或 main-web.ts 之外 ⇒ 违规；出现在 ui ⇒ 违规。

## 自查实验

验证自己是否掌握了本章：打开 `agent/src/tools/traverse/index.ts`（能力文件夹——walker/ignore 被 glob 与 grep 两个工具消费，≥2 消费方才成立，注释原话）与 `ui/src/index.ts`（只 re-export `renderTui`），逐行问三个问题：这是纯 re-export 吗？它依赖了谁、合法吗？如果删掉这个 barrel，哪些跨模块 import 会变成深路径违规？能答上来说明依赖模型已经内化。
