# 04-消息契约

## bridge/src 的分层

```
bridge/src/
├── contract/            # 「语言」层：类型 + zod schema + 纯派生函数
│   ├── shared.ts        # State / Message / PermissionDecision / ToolIdentity / COMPACTION_THRESHOLD
│   ├── config.ts        # configSchema 全家 + permissionSchema + isConfigured
│   ├── permission.ts    # classifyPermission 匹配引擎（见 06-权限系统）
│   ├── glob.ts          # globToRegExp / matchGlob / matchWildcard（见 07-工具系统）
│   ├── tools.ts         # ToolIdentity / ToolListItem
│   ├── agent-to-ui.ts   # AgentToUiMessage 联合类型（26 种）
│   ├── ui-to-agent.ts   # UiToAgentMessage 联合类型（27 种）
│   ├── agent-to-ui-schema.ts / ui-to-agent-schema.ts   # 上述两者的 zod 运行时校验
└── channel/             # 「传输」层
    ├── port.ts          # AgentPort / UiPort 接口
    └── in-memory.ts     # 同进程对偶通道
```

类型文件与 schema 文件**成对存在**：`agent-to-ui.ts` 只写 TS 类型（编辑期），`agent-to-ui-schema.ts` 写 zod（运行期）。`bridge/src/index.ts` 把两者都 re-export。

## 消息的四个「流」

**对话流**（轮次的血肉）：上行 `submit`/`cancel`；下行 `state`/`text_delta`/`thought_delta`/`message`/`tool_pending`/`tool_start`/`tool_end`/`finished`/`error`/`notice`/`compaction`。注意 `message` 只带 `{ role, id }` 不带内容——内容靠 delta 流式到达，`id` 与 `tool_start` 同源供 UI 定位。

**权限流**：上行 `permission_decision`/`permission_revoke`/`permissions_request`；下行 `permission_request`（带 `alwaysScope?: { pattern }`）与 `permissions_list`。下行消息里凡 `id` 都是「挂起请求的关联键」。

**配置流**：上行 `config_request`/`config_set`/`config_add`/`config_remove`；下行 `config_state`（请求响应）与 `config_updated`（任何编辑成功后的广播）。WebUI 设置页与 TUI 配置树都只认这两条。

**管理流**（会话/工具/skills/MCP/系统信息）：上行 `new_session`/`resume_session`/`delete_session`/`list_sessions`/`rename_session`/`clear_history`/`tools_request`/`skills_request`/`skills_manage`/`invoke_skill`/`mcp_request`/`mcp_manage`/`set_cwd`/`context_request`/`status_request`/`system_request`/`log_request`/`quit`；下行对应 `session_ready`/`session_list`/`session_deleted`/`tools_list`/`skills_list`/`skill_content`/`mcp_list`/`context_state`/`status_state`/`system_state`/`log_state`/`history_cleared`。

## Port 抽象与双通道

`bridge/src/channel/port.ts` 是 bridge 唯一的新抽象：`AgentPort.onMessage(cb)/post(msg)` 与对偶的 `UiPort`，`post` 允许 `void | Promise<void>`（同步或异步传输都装得下）。

```ts
// bridge/src/channel/port.ts（节选）
export interface AgentPort {
  onMessage(cb: (msg: UiToAgentMessage) => void): () => void   // 返回退订函数
  post(msg: AgentToUiMessage): void | Promise<void>
}
export interface UiPort { /* 对偶：方向相反 */ }
```

- **InMemoryChannel**（`bridge/src/channel/in-memory.ts`）：两个 `Set` 监听器表，`agentPort.post` 同步遍历 `uiListeners`，反之亦然——与旧版 `agent.send/emit` 的时序语义完全一致。`bin/dogegg.ts` 里 `renderTui(channel.uiPort)` 就是全部装配。
- **SseChannel**（`server/src/channel/sse.ts`）：**只实现 AgentPort**（UI 侧直接消费 SSE 流，不需要 UiPort）。下行 `post()` 把消息 `JSON.stringify` 写进所有活跃 SSE 连接（多标签页共享同一事件流，都是同一 Agent 的观察者）；上行 `postHandler` 收 POST /api/message，body 上限 1MB，`uiToAgentMessageSchema.safeParse` 校验失败回 400，通过才触发 agentListeners。`sseHandler` 建立 `text/event-stream` 连接。路由在 `server/src/http/router.ts`（/api/events、/api/message、/api/fs、/api/shells）。

## 消息形状速读（举三例）

读契约先读三种代表消息，其余举一反三：

```ts
// ui-to-agent.ts——上行命令是「意图 + 载荷」，无 id（agent 不回执命令本身，回的是响应消息）
{ type: 'permission_decision'; id: string; decision: PermissionDecision }
{ type: 'skills_manage'; action: 'create'|'update'|'delete'|'get'|'toggle'; scope: 'project'|'user'; name: string; ... }

// agent-to-ui.ts——下行是「事件流」，tool 系列用同一 id 串联
{ type: 'permission_request'; id: string; tool: string; input: unknown; alwaysScope?: { pattern: string } }
{ type: 'mcp_list'; servers: { name; enabled; scope; transport; status: 'running'|'starting'|'error'|'stopped'; error?; tools }[] }
```

注意 `session_ready` 是最重的下行消息：带 `messages: Message[]` 全量历史与 `thinking`，resume/新建/清空都靠它重建 UI。

## 下行校验（WebUI 专属防线）

`ui/src/webui/channel/sse-client.ts` 的 `createSseUiPort()`：`EventSource.onmessage` 里 `agentToUiMessageSchema.safeParse`，**校验失败的消息静默丢弃**——服务器版本与前端版本错位时，新消息类型不会把渲染层炸掉。上行 `post()` 用 fetch POST /api/message，非 2xx 抛错（WebUI 的 `safePost` 会转 toast，见 `ui/src/webui/app/app.tsx`）。TUI 不做下行校验——同进程同版本，类型系统已兜底。

## 几个值得注意的契约决策

- **error 可序列化**：`agent-to-ui.ts` 里 error 是 `{ message, name? }` 而非 `Error` 实例——`JSON.stringify(Error)` 会丢 name/stack，进程内与 SSE 两个通道必须同构。
- **跨端常量放契约**：`COMPACTION_THRESHOLD = 0.8`（`shared.ts`）同时决定后端自动压缩触发与 InfoPanel 过载变色——放契约防两端漂移。
- **`ToolIdentity` 住 contract/tools.ts**：权限服务键匹配（`contract/permission.ts`）与 `tools_list` 载荷都消费它，属契约数据而非 agent 私有。
- **schema 是判别联合**：`ui-to-agent-schema.ts` 用 `z.discriminatedUnion('type', [...])`，一个 type 一个对象 schema——增消息必须两处同步（类型 + schema），架构上靠 typecheck 兜底。
