# 06-权限引擎

权限引擎是 `bridge/src/contract/permission.ts` 的**纯派生函数** `classifyPermission`——无状态、无 IO，输入配置与调用事实，输出 allow/reject/ask。它是配置 schema 的唯一解释者，agent 运行时与两端 UI 展示共用同一实现（永不漂移）。

## 匹配流程（classifyPermission）

对一次调用 `(tool, args)`，按桶序求值：

```
hit(bucket) = 桶内任一规则的「名字分支」或「服务分支」命中
reject 命中 → reject；会话提升命中 → allow；ask 命中 → ask；allow 命中 → allow；否则 ask
```

- **名字分支**（toolEntryMatches，对所有工具生效）：桶键与完整工具名精确或平文本通配（遗留 `mcp__x__*` 手写键走此分支）；whole 规则直接命中；否则按主参数（shell→command 平文本通配、文件类→path 分段 glob）匹配 args——fail-closed：无参数可比/非字符串/全不命中 → 不命中。
- **服务分支**（mcpServerHit，仅 kind='mcp' 身份的工具）：按身份查 `mcp:<server>` 前缀键——whole 整组命中；patterns 与内部工具名做平文本通配（工具启用匹配，永不涉参数）。
- 身份快照由 agent 注入（注册表 identities()）——匹配从不解析 LLM 可见名，服务名零约束。

## 加载期校验（contract/config.ts 的 superRefine）

- 内建 path 工具（BUILTIN_PATH_TOOLS）的 patterns 必须带作用域锚点（`./` `../` `~/` 盘符 `*`）——裸模式拒绝加载；无论 whole 与否都校验（patterns 是待命态）。
- 裸服务名键（与 mcpServers 同名但未加 `mcp:` 前缀）拒绝加载——服务键强制前缀。

## 归一化（agent 侧 PermissionManager.normalizeRules）

- 判定前把 path 模式按锚点解析为绝对形式（`./`→cwd、`~/`→主目录、盘符 resolve、`*` 保留）；参数侧同步 realpath。shell 与 `mcp:` 前缀键跳过（无 cwd 概念）。
- 内置读豁免：read_file 落 ask 且目标在管理目录（如用户级 skills）内 → 自动放行（免反复审批）。

## 优先级立法（重申）

reject > 会话提升 > ask > allow > 默认 ask。推论与例外场景见需求分析 05-权限与安全。
