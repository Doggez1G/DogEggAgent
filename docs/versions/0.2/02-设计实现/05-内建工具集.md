# 05 - 内建工具集

> 职责：7 个内建工具（read_file / write_file / edit_file / shell / ls / glob / grep）的实现——每个工具是一个实现 `Tool` 契约的类（`agent/src/tools/types.ts:19-25`：`name / description / schema(zod) / parameters(OpenAI JSON schema) / execute(args, ctx)`），全部经注册表关口（《04》）与权限关口（《06》）后执行。

## 1. 职责与边界

每个工具一个文件夹（模块 = 文件夹），内分三职责：`tool.ts`（实现）/ `schema.ts`（zod + OpenAI JSON schema 双份参数定义）/ `index.ts`（re-export）。共享底座：

- `agent/src/tools/traverse/walker.ts`——glob/grep 共用递归遍历器；
- `agent/src/tools/traverse/ignore.ts`——内置目录黑名单 + 二进制判定；
- `agent/src/tools/traverse/ignore-gitignore.ts`——.gitignore 核心子集谓词；
- `agent/src/tools/shell/support/`——解释器解析（interpreter.ts）、本机扫描（detect.ts）、进程树杀（kill-tree.ts）、系统提示引导（guidance.ts）。

**输出治理总立法**：所有回执有确定上界，截断处注明"还剩多少 + 怎么办"——让模型能自行修正而非重试同一模式（glob/tool.ts:10 注释的先例表述）。最终统一兜底是 ToolExecutor 的 `truncate`（context/truncate.ts:3-8，8000 字符 cap）。

### 1.1 参数 schema 的双份维护

每个工具文件夹的 `schema.ts` 同时维护两份定义（以 grep 为例，grep/schema.ts:4-10 与 :13-28）：`grepSchema`（zod，运行时校验 LLM 返回参数——ToolExecutor 的 `schema.parse` 用它）与 `grepParameters`（OpenAI JSON Schema，进请求体给模型看参数说明）。两份**手工对齐**——字段名、必填性必须一致，description 写给模型的行为引导（如 output_mode 的"先粗后细"）。这是刻意不做的自动化（v1 工具数量小，手写 description 的表达力优先于 zod→JSON Schema 的机械转换）。

## 2. 权限主参数总表

权限引擎按"主参数"匹配模式（bridge/src/contract/config.ts:67 的 `PRIMARY_SPECIFIER = { shell: 'command' }`，其余默认 `'path'`）：

| 工具 | 主参数 | 匹配函数 | 默认权限（出厂，config.ts:126-138） |
|---|---|---|---|
| read_file | path | matchGlob（分段 glob） | allow（whole） |
| write_file | path | matchGlob | ask（whole） |
| edit_file | path | matchGlob | ask（whole） |
| shell | command | matchWildcard（平文本通配） | ask（whole） |
| ls / glob / grep | path | matchGlob | allow（whole） |

## 3. 七工具逐个走查

### 3.1 read_file（tools/read_file/tool.ts）

- **参数 schema**（read_file/schema.ts:4）：`z.object({ path: z.string() })`——相对 cwd 路径。
- **实现**（tool.ts:15-23）：`readFile(join(ctx.cwd, path), 'utf8')` 全文返回；失败返回 `{ error: String(e) }` 而非抛错——**工具错误不中断 loop，而是作为 tool 消息回填模型**（tool.ts:8 注释），模型看到错误文本后自行调整。无额外封顶——超大文件靠全局 truncate 兜底。
- **权限侧处理**：参数 path 在 PermissionManager.normalizeArgs 里被 realpath 归一（见《06》§3.2），工具本身不感知。

### 3.2 write_file（tools/write_file/tool.ts）

- **参数 schema**（write_file/schema.ts:4）：`{ path, content }`——整文件覆写或创建（不建多级目录，父目录缺失直接失败回模型）。
- **实现**（tool.ts:15-24）：`writeFile(join(ctx.cwd, path), content, 'utf8')`，成功回执"已写入 <path>"。
- **权限侧处理**：新建文件的目标不存在 → realpath 失败 → 权限按"真实父目录 + 文件名"判定（permission/manager.ts:130-135 的 realTargetPath 注释）。

### 3.3 edit_file（tools/edit_file/tool.ts）——存在性检查 + 替换首次出现

- **参数 schema**（edit_file/schema.ts:4）：`{ path, old_string, new_string }`，old_string 描述强调"需与文件内容逐字符一致"（schema.ts:9）。
- **唯一命中算法**（tool.ts:15-29）：`text.includes(old_string)` 不含 → `{ error: 'old_string 未找到' }`；**包含即替换首次出现**（`text.replace(old_string, new_string)`——String.replace 非全局，天然只替换第一处）。这是 code agent 的核心约束：逐字符匹配含缩进/空白，防止误替换（tool.ts:8 注释）。多处命中时模型应通过扩大 old_string 上下文来定位——当前实现不主动检测多处命中（替换的是确定性的首次出现）。
- **行号锚点回执**（tool.ts:21-25）：`startLine = text.slice(0, text.indexOf(old_string)).split('\n').length` 写进回执"已替换 1 处（原第 N 行起）"——一举两得：模型知道改动落点便于连续编辑；UI（ui/src/shared/tool-display）解析它给 diff 标真实行号。回执格式是"回执即契约"，改动需本工具与 UI 两处同步（grep/tool.ts:20-21 注释的同款立法）。

### 3.4 shell（tools/shell/tool.ts）——解释器选择与超时树杀

- **参数 schema**（shell/schema.ts:4）：`{ command: z.string() }`——单条命令字符串，解释器由配置决定，工具内不拆参数。
- **解释器选择**（shell/support/interpreter.ts:24-38）：`resolveShell(ctx.shellProgram)` 五步——① 空/空白 → 平台默认（win: `cmd /c`，其它: `bash -c`，interpreter.ts:19-21）；② 含非 ASCII（误存占位文本）→ 回退默认（:26）；③ 已知程序名映射表 `{cmd, powershell, pwsh, bash, sh}` → 标准程序 + flag + kind（:27-33）；④ 未知程序名（nu/fish）→ 不猜测语义，回退默认（:35）；⑤ 配置的 kind 不在本机扫描结果内 → 回退默认（:36）。**powershell（5.1）与 pwsh（7+）是两个 kind**——语法能力不同（5.1 无 `&&` `||`）（interpreter.ts:9 注释）。
- **本机扫描**（detect.ts:35-45）：PATH 扫描（Windows 按 PATHEXT 补扩展名，detect.ts:20-30），比逐个 spawn 探测快且确定；cmd 在 Windows 上视为必然可用（System32 恒在）；结果运行期缓存（detect.ts:32）。
- **spawn 细节**（tool.ts:28-32）：`spawn(program, [flag, command], { cwd, detached: !isWin })`——POSIX detached 使子进程在独立进程组，`kill(-pid)` 才能整组杀；Windows 不设 detached（taskkill /T 不需要）；不用 `shell:true`（DEP0190 弃用警告）。stdout/stderr 合并累积到一个 `out`（:35-36）。
- **超时树杀**（tool.ts:9-10, 41）：`SHELL_TIMEOUT_MS = 120_000`——交互式/常驻进程（dev server、游戏循环）不自行退出，无超时会卡死整轮对话；超时 `killTree(child)`，close 事件仍触发走正常回填路径，回执带说明"命令超过 120s 未结束，已终止进程树；如需长任务请放后台并轮询输出"（:47）——已有输出 + 超时说明一起回填，模型可据此调整。
- **进程树杀**（kill-tree.ts:7-22）：**按 OS 分不按 shell 类型分**——win32 用 `taskkill /PID <pid> /T /F`；POSIX 用 `process.kill(-pid, SIGKILL)` 杀整个 detached 进程组，失败降级 `child.kill`。
- **取消三件套之一**（tool.ts:37-39）：`ctx.signal.addEventListener('abort', () => killTree(child), { once: true })`——用户 cancel 时轮次的 AbortSignal 直达子进程树（《02》§3.6 的在飞中断在 shell 工具上的落点）。
- **系统提示引导**（guidance.ts）：`shellGuidance(spec)` 产出"## Shell 环境"段注入系统提示（agent.ts:75 组装时拼接）——模型训练分布偏 Unix/bash，不注入则 Windows 上 cmd/PowerShell 语法差异（无 grep、5.1 无 `&&`、`%VAR%`）就是失败主因（guidance.ts:4-7 注释）；每类解释器一段保守可执行的要点（宁少勿错）。

### 3.5 探索三件套与共享遍历器（ls / glob / grep + traverse/）

**walkFiles**（traverse/walker.ts:14-55）核心设计：

- 只产出 posix 形式的相对路径字符串，内容读取归调用方——遍历与消费分离，walker 不关心 pattern/正则（:5-7 注释）；
- **迭代式 DFS**（stack 而非递归，:25, 53 逆序压栈）——深层树调用栈浅、中断检查点规整，产出顺序接近字母序；
- **剪枝三规则**：IGNORED_DIRS 按目录名剪枝（node_modules/.git/dist/build/out/.next/coverage/.dogegg，ignore.ts:11-20）；**symlink 一律跳过**——目录链接造成环、文件链接逃逸 root，"遍历范围 = root 子树"的隐含承诺不破（walker.ts:11-12 注释）；.gitignore 谓词（文件与目录分别判定，:45, 48）；
- **确定性排序**（:36-38）：readdir 顺序依文件系统而异（NTFS 近字典序、ext4 哈希序），排序保证 grep 回执命中顺序跨平台确定；
- **取消与容错**：每个目录处理间隙 `signal.throwIfAborted()`（:27）；单目录 readdir 失败跳过继续（:33-34，探索性操作单点失败不致命）。

**gitignore 谓词**（ignore-gitignore.ts:37-71）：核心子集——`#` 注释、封口 `/` 仅目录、含 `/` 相对根锚定 / 纯名字匹配任意层级（前缀 `**/`，:30-32）、`* ** ?` 通配（复用 bridge 的 globToRegExp，:3）、`!` 取反靠**顺序语义**（后命中覆盖先命中，:62-70）；单条非法模式跳过不拖垮整体（:56-58）；文件不存在/读取失败返回 undefined（无规则行为不变，:39-44）。嵌套 .gitignore、字符组、转义刻意不支持（:12 立法）。

**ls**（ls/tool.ts:27-55）：单层 readdir（不递归——递归是 glob 的事，schema.ts:6）；目录在前加 `/` 后缀、文件在后附人类可读大小（B/KB/MB，:12-16）；大小获取失败显示 `?` 不致命（:38-40）；隐藏文件正常显示——agent 需要看 .github/.gitignore，黑名单只作用于递归遍历（:20 注释）；MAX_ENTRIES = 500 封顶注明总数（:48-50）；symlink 跳过与 walker 同一立场（:43）。

**glob**（glob/tool.ts:22-56）：`globToRegExp(pattern)` 编译一次遍历内复用（:26，matcher 来自 bridge——与权限参数化规则共用一份实现，:14 注释）；根路径 stat 预检——walker 对单目录失败是"跳过继续"，但**整个根不存在必须显式报错**，否则"模式写错"和"路径写错"在模型侧不可区分（:31-34 注释）；MAX_MATCHES = 100 封顶 + "请收窄 pattern"提示（:42, 50-53）；无命中回"（无匹配文件）"。

**grep**（grep/tool.ts:32-143）——治理最严的工具，**输出治理四层**（:9-16）：

1. `MAX_LINE_LENGTH = 500`：单行截断（minified/长字符串字面量），命中行 `相对路径:行号: 内容` 前缀格式（:118，"回执即契约"）；
2. `MAX_HITS_PER_FILE = 20`：单文件命中封顶（:109），超出后补"该文件还有 N 处未显示"（:123-126，countMatches 补数 :163-167）；
3. `MAX_TOTAL_HITS = 100`：总命中封顶，`break collect` 提前结束整个遍历（:110）；
4. `MAX_OUTPUT_LENGTH = 8000`：总字符 cap，pushLine 写满即置 truncated 拒绝后续写入（:70-78）。

其余要点：正则/ glob 非法各自返回带修正指引的 error（:38-49）；`output_mode` 三态 content/files_with_matches/count（schema 描述引导"先粗后细"大搜索策略）；glob 过滤对完整相对路径与文件名**任一命中即通过**——用户直觉 `*.ts` 应匹配 src/x.ts（:100 注释）；1MB 超大文件跳过计数（:90）；二进制探测读首 8KB 判 NUL（:146-160 + ignore.ts:23-27 的 isBinaryFile——刻意不用扩展名白名单，内容判定一条规则覆盖全部，误判方向安全）；`\r` 归一掉 Windows 行尾不影响行号（:103）；无命中时若有跳过大文件则在回执注明（:133-136）。

## 4. 关键立法与不变量

- **INV-1**：工具失败返回 `{ error }` 而非抛错——错误是给模型的信息，不是给调度器的异常（read_file/tool.ts:8 注释的统一约定；execute 抛错由 ToolExecutor runAndEmit 兜底）。
- **INV-2**：所有回执有确定上界（glob 100 / ls 500 / grep 四层 / 全局 8000 字符）。
- **INV-3**：遍历范围 = root 子树（symlink 全跳过 + 目录黑名单剪枝），探索永不逃逸、永不入环。
- **INV-4**：matcher 一份实现三端共用（bridge globToRegExp）——glob 工具、grep 过滤、权限参数化规则永不漂移。
- **INV-5**：回执格式是契约（edit 行号锚点、grep `path:line: content`），改动须工具与 ui/shared/tool-display 同步。
- **INV-6**：shell 子进程的生杀大权在 AbortSignal（用户取消）与超时定时器两条路径，都收敛到 killTree。

### 4.1 探索漏斗：三件套的协作工作流

三个探索工具被刻意设计成"先粗后细"的漏斗，grep 的 schema 描述直接引导模型（grep/schema.ts 的 output_mode description："大搜索先用 files_with_matches 锁定文件再精搜"）：

1. **ls**（单层拓扑）：看目录结构——目录在前加 `/`、文件附大小，模型先建立项目形态认知；
2. **glob**（路径匹配，不读内容）：按模式定位候选文件——只匹配路径，遍历器不打开文件，大仓库代价可控；
3. **grep**（内容搜索）：漏斗最后一层——先 `output_mode: 'files_with_matches'` 锁定文件，再对单文件 `output_mode: 'content'` 精读命中行（带行号）。

漏斗各层共用 walker 遍历器与 gitignore 过滤——忽略意愿（.gitignore + IGNORED_DIRS）在全漏斗一致，模型不会在 glob 里看到 node_modules 又在 grep 里被过滤产生困惑。

## 5. 失败模式与恢复

| 失败 | 行为 | 模型侧恢复 |
|---|---|---|
| 文件不存在/无权限 | `{ error: String(e) }` 回填 | 读错误文本改路径或先 ls 探查 |
| edit old_string 未找到 | `{ error: 'old_string 未找到' }` | 先 read_file 核对再重试 |
| shell 命令超时 | 杀树 + 已有输出 + 超时说明回填（tool.ts:46-48） | 按提示放后台/轮询或拆分命令 |
| shell spawn 失败（程序不存在） | child error → `{ error }`（:51-55） | 报告用户或换命令 |
| 大仓库遍历 | 四层/封顶截断 + 收窄指引 | 换更具体 pattern/path/output_mode |
| 遍历中用户取消 | throwIfAborted 上抛 → ToolExecutor catch → tool_end error | 轮次已 cancelled，无后续 |
| 单目录读失败/竞态删除 | 跳过继续，不中断整体（walker.ts:33-34、grep:98-99） | 无需恢复 |
| 配置了本机没有的 shell | resolveShell 回退平台默认（interpreter.ts:36） | 用户改配置（server /api/shells 可查询可用列表） |

## 6. 与其它子系统的接缝

- **→ 04 注册表**：withBuiltins 注册，identity 缺省 builtin。
- **→ 06 权限**：主参数表决定匹配函数；path 参数在权限侧 realpath 归一，工具自身不做权限判断。
- **→ 02 轮次**：ToolContext 的 cwd/signal/shellProgram 由 TurnInput 逐轮下传（loop.ts:193）；超时 killTree 与取消传播衔接。
- **→ 11/12 前端**：tool_display 按"回执即契约"格式解析渲染（行号锚点、命中前缀）。
- **→ 10 配置**：shellProgram/shellTimeoutMs 可配；server 的 /api/shells 供 WebUI 设置区列出本机可用解释器（server/src/http/router.ts:41-46）。
