# 08 - 技能系统

> 职责：管理 Agent Skills（SKILL.md 指令文件）——两级目录扫描、旁挂停用名单的三态合成、CRUD 与启停、系统提示的渐进披露注入、调用时的正文渲染。实现集中在 `agent/src/skills/manager.ts` + `agent/src/skills/parser.ts`。

## 1. 职责与边界

| 文件 | 职责 |
|---|---|
| `agent/src/skills/manager.ts` | SkillsManager：list 三态合成、setEnabled、CRUD、forInvocation、promptSection、缓存 |
| `agent/src/skills/parser.ts` | SKILL.md 最小 frontmatter 解析 + 骨架生成 |
| `agent/src/agent.ts` | 消息层编排：skills_manage CRUD（:264-294）、invoke_skill（:407-415）、emitSkillsList 广播（:184-188） |
| `agent/src/permission/manager.ts` | builtinReadDirs 豁免（读 SKILL.md 不弹审批，manager.ts:37-41） |
| `bridge/src/contract/agent-to-ui.ts` | skills_list / skill_content 消息形状（:41-42） |

目录立法（manager.ts:8-17 注释）：只扫两个目录——用户级 `~/.dogegg/skills/`、项目级 `<cwd>/.dogegg/skills/`；**skill 名 = 目录名（唯一事实源）**，frontmatter 的 name 字段仅文档性（parser.ts:3 注释）；同名冲突项目级覆盖用户级（调用/联想取项目级），list() 两条都返回（面板两组都可见）；description 来自 frontmatter（渐进披露——系统提示与面板只展示它，正文按需读取）。

`SKILL_NAME_RE = /^[a-z0-9][a-z0-9-]*$/`（manager.ts:31）的三重作用：**防路径穿越**（不允许 `.` `/` `\` 等字符，`..` 无法构造）、**命令名合法性**（skill 名会变成 `/name` 斜杠命令）、**大小写归一**（全小写避免跨平台文件系统大小写敏感差异）。readdir 阶段就过滤非法目录名（list 的 :75），CRUD 阶段 assertInside 再拦一次。

## 2. 核心数据结构

```ts
// manager.ts:19-28
export interface SkillInfo {
  name: string            // = 目录名（唯一事实源）
  description: string     // frontmatter 的 description（渐进披露的唯一广告位）
  scope: 'project' | 'user'
  path: string            // SKILL.md 全路径（read_file 引导用）
  enabled: boolean        // false = 停用名单在案
  missing: boolean        // true = 名单在案但目录已消失（孤儿）
}
```

旁挂停用名单：状态文件与 skills 目录**同层**（`dirname(dir)/.skills.json`，manager.ts:106-110）——用户级 `~/.dogegg/.skills.json`、项目级 `<repo>/.dogegg/.skills.json`（与 .mcp.json 同构）；只记停用名单 `{ disabled: string[] }`（缺省即启用），**不碰主流 SKILL.md 格式**；项目级停用随 `.dogegg/` 进 git 与仓库共享（:13-15 立法）。

SKILL.md 形态（parser.ts:1-7 注释 + skeletonSkillMd :30-42）：`---` 包裹的 frontmatter 块内取 `description:` 单行键值（不引 YAML 依赖，其余键忽略，parser.ts:22-25）；正文是交给模型的完整指令，`$ARGUMENTS` 是参数占位符。

```markdown
---
name: deploy          ← 仅文档性（真名 = 目录名）
description: 部署到测试环境并检查健康检查端点
---
使用 $ARGUMENTS 作为用户传入的参数。
（在此写下交给模型的完整指令……）
```

解析器是**最小实现**（parser.ts:13-27）：首行必须 `---\n`、找闭合 `\n---`、块内逐行 `^description:\s*(.*)$` 提取（Windows CRLF 先归一，:14）。无闭合块 / 无 frontmatter → description 为空、全文作为正文——格式错误的 skill 降级可用而非失效。

### 2.1 三态合成的具体输出示例

假设用户级目录有 `deploy`（启用）、`lint`（在 .skills.json 停用名单）；项目级目录有 `lint`（启用）、`test`（SKILL.md 损坏）；用户级停用名单还留着早已删除的 `old-skill`。list() 产出（project 在前）：

| name | scope | enabled | missing | description 来源 |
|---|---|---|---|---|
| lint | project | true | false | 项目级 frontmatter |
| test | project | true | false | "（SKILL.md 解析失败——请检查 frontmatter/正文）" |
| deploy | user | true | false | 用户级 frontmatter |
| lint | user | false | false | 用户级 frontmatter（停用名单在案） |
| old-skill | user | false | true | "（目录已不存在）" |

同名 `lint` 两条都在（面板两组可见）；forInvocation/斜杠联想命中**项目级**（enabled 且非缺失条目内项目优先，manager.ts:184）；`old-skill` 只出现在面板（供清理），永不进 promptSection 与联想。

## 3. 关键流程走查

### 3.1 三态合成算法（list，manager.ts:63-101）

对每个 scope（project 在前、user 在后），产出三类条目的并集：

1. **正常条目**（:72-91）：目录存在则 readdir，目录名过 `SKILL_NAME_RE = /^[a-z0-9][a-z0-9-]*$/` 过滤（:31，小写字母数字连字符、字母开头——防路径穿越 + 命令名合法性）；`SKILL.md` 存在才收（:81）；读文件 parseSkillMd 取 description → `{ ..., enabled: !disabled.has(name), missing: false }`（:85）；
2. **解析失败条目**（:86-90）：SKILL.md 解析失败**照常可见不隐身**（description 标"（SKILL.md 解析失败——请检查 frontmatter/正文）"），仍参与停用名单语义（found 集合照常登记，:88）——诊断优先于静默；
3. **名单孤儿**（:94-97）：停用名单在案、但文件系统已消失（外部删除产生）→ 追加 `{ enabled: false, missing: true, description: '（目录已不存在）' }`——**可见供清理，永不进系统提示与调用**（:16-17 三态立法）。孤儿枚举在目录整体消失或不可读时也照常（:71, 77 的 entries 置空路径）。

合成结果写缓存 `this.cache = out`（:99）。

### 3.2 旁挂名单读写（容错语义，manager.ts:112-129）

- `readDisabled`（:113-123）：文件缺失 / JSON 损坏 / `disabled` 非数组 / 元素非字符串——**一律视为空名单**（不拖垮 skills 功能；外部手改损坏可删文件自愈，:112 注释）；
- `writeDisabled`（:125-129）：`mkdirSync(recursive)` + 两空格 JSON 落盘；
- `setEnabled`（:132-138）：启用 = 从名单移除；停用 = 追加（去重）；写盘后 invalidate。**启用一个 missing 条目 = 清理孤儿记录**（:131 注释）——agent.ts:276-279 对此区分文案（"已清理（移除孤儿记录）"vs"已启用"），避免误导为恢复了可用 skill。

### 3.3 渐进披露渲染（promptSection，manager.ts:194-204）

只列**可用条目**（`enabled && !missing` 过滤，:195——停用/缺失不广告）；**无 skill 返回空串不注入段**（:196——省上下文）；每条一行 `- 名字：描述（路径）`（:197）；段首立法指令："当用户请求与某个 skill 的描述相关时，**先用 read_file 读取其 SKILL.md 获取完整指令再执行**"（:201）——这就是渐进披露：系统提示只花一行广告位，正文按需经 read_file 加载（且该路径在 builtinReadDirs 豁免内不弹审批，见《06》§3.5）。注入点：ContextAssembler 构造的第三参数 `() => this.skills.promptSection() + shellGuidance(...)`（agent.ts:75）——每次组装系统提示时现取。

### 3.4 forInvocation 与 $ARGUMENTS（manager.ts:182-191）

1. 过滤可用条目 → 命中算法：同名条目**项目级优先**（`find((s) => s.scope === 'project') ?? available.find(...)`，:184）；
2. 未命中抛错（"未找到 skill：X（可能已停用或目录缺失）"）→ 门面转 notice（agent.ts:412-414）；正文为空也抛错（:187）；
3. 参数替换（:188-190）：body 含 `$ARGUMENTS` → `replaceAll` 替换为 trim 后的参数；**无占位且带参** → 追加 `\n\n用户参数：<args>` 段（骨架生成的默认正文就带占位，skeletonSkillMd:37）；
4. 渲染产物作为**用户消息**进轮次：`turnRunner.submit(skillText, ...)`（agent.ts:411）——skill 是"预填的用户 prompt"，与手动输入同权同路径。

### 3.5 CRUD 与缓存失效（manager.ts:140-178 + agent.ts:264-294）

| 操作 | 语义 | 名单联动 |
|---|---|---|
| create（:142-152） | name 过 NAME_RE（非法抛错）→ 目录已存在抛错 → mkdir + 骨架 SKILL.md | **从停用名单移除**——同名重建视为全新开始、默认启用（:141 注释） |
| update（:155-161） | SKILL.md 整文件替换（TUI $EDITOR / WebUI 编辑弹框的落点） | 不动名单 |
| remove（:165-170） | `rmSync(recursive, force)` 整目录删除，**幂等**（不存在静默成功——也是 missing 条目"删除即清理"的落点） | 名单同步清理，不留孤儿（孤儿只由外部删除产生） |
| read（:173-178） | 返回 SKILL.md 全文（skill_content 消息，agent.ts:287） | 不动名单 |

路径安全**双保险**（assertInside，:207-213）：name 先过 NAME_RE，再确认 `join(dir, name)` 结果 `startsWith(dir)` 不越出根目录。门面层把所有 CRUD 抛错转 `notice channel='skills'`（agent.ts:291-293）——面板内联可见，不静默。

**缓存失效策略**（:35-51）：list() 结果缓存的原因——系统提示段与 token 估算在**每次状态变化时**都触发 list()，现扫文件系统会成为热路径。失效时机三个：任何写操作（create/update/remove/setEnabled 末尾都调 invalidate）、`setProjectDir`（/cd 切换目录，:43-46）、门面显式 invalidate——`emitSkillsList`（agent.ts:184-188）在每次 skills_request/管理操作后 invalidate + list，**外部手改文件也在此可见**（面板/联想的清单永远反映磁盘事实）。

### 3.6 面板 CRUD 的消息层走查（agent.ts:264-294）

以 skills_manage 五动作为完整回路（WebUI 设置页 / TUI /skills 面板 → notice + skills_list 刷新）：

1. `create`：manager.create 生成骨架 → notice"skill 已创建：X（scope）——正文记得用编辑器充实" → emitSkillsList（:267-270）；
2. `update`：全文替换 → emitSkillsList；`get`：回 `skill_content` 消息且**提前 return**（get 的响应不是清单，:287-288）；
3. `toggle`：先查 `wasMissing`（list() 里该条目的 missing 标志，:276）——文案区分"已启用"与"已清理（移除孤儿记录）"（:278-279），避免把清理误读为恢复；
4. `delete`：整目录删除 → notice → emitSkillsList；
5. 任何抛错（重名/非法名/越界）→ catch → `notice channel='skills'`（:291-293）——管理面板内联显示而非全局飘字。

**skills_request 的播种语义**（agent.ts:400-402）：每次都 `emitSkillsList()`（invalidate + 重扫 + 广播）——面板/命令联想的清单永远反映磁盘事实，外部手改 SKILL.md 或手动删目录后打开面板即见。

**门面的调用入口**（agent.ts:407-415）：`invoke_skill` 前置 isConfigured 检查 → `skills.forInvocation(name, args)` → 渲染产物 `turnRunner.submit(skillText, resolveTurnParams())`——skill 调用与普通 submit 走完全相同的轮次路径（权限、压缩、取消全部天然生效），没有第二条执行通道。

## 4. 关键立法与不变量

- **INV-1 名字唯一事实源**：skill 名 = 目录名，frontmatter name 仅文档性。
- **INV-2 三态完备**：启用 / 停用 / missing 三态互斥完备；missing 永不进 promptSection 与 forInvocation。
- **INV-3 旁挂名单只记停用**：缺省即启用；SKILL.md 主流格式零污染；项目级随 git 共享。
- **INV-4 读容错自愈**：名单损坏视为空、目录不可读视为空——skills 功能永不因状态文件挂掉。
- **INV-5 渐进披露**：提示词只花 description 一行；正文按需 read_file（读豁免免审批）。
- **INV-6 CRUD 全部限定根目录内**：NAME_RE + startsWith 双保险。
- **INV-7 项目级覆盖用户级**：调用与联想取项目级，面板两条都可见。
- **INV-8 停用不删除**：setEnabled 停用只进旁挂名单——SKILL.md 与目录原样保留，重新启用零恢复成本；enabled=false 是唯一"半存在"形态（missing 是另一种）。

## 5. 失败模式与恢复

| 失败 | 行为 | 恢复 |
|---|---|---|
| .skills.json 损坏/手改坏 | 视为空名单（:120-122） | 删文件即自愈；启停操作重写正确格式 |
| SKILL.md frontmatter 坏 | 条目照常可见、标注解析失败（:89） | 面板 get 全文诊断后 update 修复 |
| 外部删除目录但名单还在 | missing 孤儿条目可见（:96） | 面板"启用"（清理记录）或 remove |
| 目录不可读（权限） | entries 置空、孤儿枚举照常（:77） | 修权限后 invalidate 生效 |
| create 重名/非法名 | 抛错 → notice channel='skills' 内联提示 | 改名重试 |
| invoke 停用/缺失/空正文 | forInvocation 抛错 → notice（agent.ts:412-414） | 先启停或补正文 |
| /cd 后项目目录漂移 | setProjectDir + invalidate（:43-46），门面随后重扫广播（agent.ts:501-502） | 自动 |
| 项目级停用同名用户级 | 停用只作用于所在 scope；用户级条目照常参与竞争（list 两条独立） | 用户级可正常 invoke |

## 6. 与其它子系统的接缝

- **→ 06 权限**：用户级 skills 目录进 builtinReadDirs——read_file 读 SKILL.md 的 ask 豁免（manager.ts:22 构造注入，agent.ts:74）。
- **→ 02 轮次**：invoke_skill 把渲染产物作为用户消息 submit；promptSection 每轮组装进系统提示。
- **→ 05 工具**：模型按提示段用 read_file 按需加载正文（渐进披露的第二跳）。
- **→ 11/12 前端**：skills_list 六字段驱动 TUI features/skills 与 WebUI settings/skills；skills_manage 五动作 + invoke_skill 共用消息契约。
- **→ 09 会话**：set_cwd 连动 setProjectDir——skills 随项目环境走。
- **→ 05 工具展示**：渐进披露的第二跳由 read_file 完成——SKILL.md 可能很长，全量注入系统提示会挤占窗口；正文按需加载是上下文预算策略的一部分（与压缩管线同一问题域）。
- **← 12 WebUI**：设置页 Skills section 订阅 skills_list **全量**（含 enabled/missing 状态字段）做启停管理，而 use-skills 联想池过滤可用条目——同一广播两种消费粒度（use-skills.ts:9-10 注释）。
