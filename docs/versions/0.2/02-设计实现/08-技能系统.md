# 08-技能系统

`agent/src/skills/manager.ts` 的 `SkillsManager`：两级目录扫描 + 旁挂停用名单的三态合成 + CRUD + 渐进披露渲染。

## 三态合成（list）

```
对每个 scope（project / user）：
  扫描目录（目录名 = skill 名，NAME_RE 校验；SKILL.md 存在才收）
  读停用名单（<skills 目录同层>/.skills.json 的 { disabled: [...] }，损坏视为空）
  合成：目录条目 enabled = !名单命中（missing: false）
  名单孤儿（名单在案、目录已消失）→ 追加条目 { enabled: false, missing: true }
解析失败的 SKILL.md → 以「解析失败」条目可见（不隐身，仍参与停用语义）
```

- 名单文件与 skills 目录同层（`~/.dogegg/.skills.json`、`<repo>/.dogegg/.skills.json`），只记停用名单，缺省即启用；损坏视为空名单自愈。
- 缓存：list() 结果缓存（热路径——promptSection 每轮触发），任何写操作 / setProjectDir / invalidate() 失效；外部手改经门面 invalidate 可见。

## 生效过滤

- `promptSection()`（系统提示广告段）与 `forInvocation()`（调用渲染）都只消费 `enabled && !missing` 的条目——停用/缺失退出竞争（项目级停用时同名用户级照常生效）。
- 命中渲染：正文 `$ARGUMENTS` 替换为命令参数（无占位且有参 → 追加「用户参数」段）。

## CRUD 与启停

- create（骨架生成 + 移除同名停用记录）/ update（全文替换）/ remove（整目录删除 force 幂等 + 清理名单）/ read（全文，编辑数据源）。
- `setEnabled(scope, name, enabled)`：增删停用名单 → 写盘 → invalidate——TUI `t` 键与 WebUI 按钮的落点。
- 路径安全双保险：NAME_RE + join 后必须仍在根目录内（assertInside）。
