# 10-配置体系与编辑器

配置 = 一个 JSON 文件（`agent/src/config/store.ts` 加载，`bridge/src/contract/config.ts` 定义 schema 与出厂默认）+ 一个内存编辑器（`agent/src/config/editor/`）。

## 加载（store.ts）

- 路径策略：项目 `.dogegg.json` 优先，否则 `~/.dogegg/config.json`；都没有 → 出厂默认（无 provider，引导 /config）。
- zod 解析填默认值；**校验失败即抛**——bin 的 `loadConfigOrExit` 打印人话原因（zod issue 含配置内路径）+ 本地文档路径 + 恢复指引后退出（不覆写文件）。
- 加载期立法：作用域锚点校验（内建 path 工具的 patterns）、服务键强制前缀交叉校验（裸服务名键拒绝，ADR-0013）。

## 编辑器（editor/）

- UI 的编辑不直接改 JSON，而是发 `config_set / config_add / config_remove` 消息——`parseConfigSet` 把点号路径解析为强类型操作（顶层标量 / permission 整桶 / provider 字段 / model 字段），`applySet` 应用后经 **zod 整体校验 + 失败回滚**——配置永远处于合法状态。
- permission 是整桶替换原语：UI 重算整桶对象提交，天然原子。

## 出厂默认

- 读类工具（read_file/ls/glob/grep）整工具 allow；写类与 shell 整工具 ask——仅当配置文件**完全不写 permission** 时生效；显式配置整体覆盖（不合并）。

## 演进原则（ADR-0013）

- 配置格式**不做旧版兼容**：schema 只接受当前版本；格式不符加载报错（人话 + 文档指引 + 退出）。格式即版本，无版本号字段、无迁移机器。
- 校验宽松/严格的分界：provider 字段放宽支持编辑流；权限模式严格（fail-closed）。
