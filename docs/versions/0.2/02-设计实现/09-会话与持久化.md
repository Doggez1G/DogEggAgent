# 09 - 会话与持久化

> 职责：把"发生过什么 + 授权到哪 + 干到哪"完整存档到磁盘，并在 resume 时精确还原。三个文件分工：`agent/src/session/conversation.ts`（内存工作集，R1 双写分离的唯一持有者）、`agent/src/session/store.ts`（JSON 落盘与读取）、`agent/src/session/manager.ts`（会话生命周期命令）。

## 1. 职责与边界

| 文件 | 职责 |
|---|---|
| `agent/src/session/conversation.ts` | Conversation 工作集：history/context/thinking/id/cwd/usage/compactions/title |
| `agent/src/session/store.ts` | SessionStore：`~/.dogegg/sessions/<id>.json` 的原子读写删列表 |
| `agent/src/session/manager.ts` | SessionManager：new/resume/delete/list/clear 的实现归属 |
| `agent/src/ctx.ts` | AgentContext（workset 的接线板，conversation 由门面注入） |
| `agent/src/turn/turn-runner.ts` | 轮次收尾落盘（saveOrNotice）与标题落盘 |
| `agent/src/agent.ts` | rename/set_cwd 的即时落盘（:466-523） |

依赖矩阵中 session 域只依赖 shared 与 ROOT（architecture.test.ts:130-139）——它不知道 turn/mcp/permission 的存在，接收的是结构子集 `TurnDelta`（conversation.ts:5-14：LoopResult 的形状子集，**session 不依赖 turn**）。

## 2. 核心数据结构：存档 JSON 形状逐字段

`SessionSnapshot`（store.ts:13-24）序列化后的文件形状（store.ts:48-59 的写入顺序）：

| 字段 | 类型 | 语义 |
|---|---|---|
| `id` | string | 会话唯一 id（`newId()` 生成），文件名 `<id>.json` |
| `updatedAt` | string | 写入时 `new Date().toISOString()`（save 时打点，列表排序依据） |
| `history` | Message[] | **完整原文**（永不压缩，UI 显示与 preview 用）——R1 双写的历史侧 |
| `context` | Message[] | **发给模型的消息**（可能已压缩成摘要）——R1 双写的模型侧；resume 后模型续接的是它 |
| `sessionPermissions` | ToolPermission[] | 会话内权限提升（`{tool, patterns}` 分组；patterns 空 = 整工具，非空 = 范围模式，path 已是绝对形式） |
| `usage` | `{promptTokens, completionTokens, turns}` | 会话累计**真实**用量（API 返回值，resume 续计） |
| `compactions` | number | 累计压缩次数（/context 仪表盘展示） |
| `title?` | string | /rename 手动命名或首轮自动标题；缺省时列表展示 preview（:20-21） |
| `cwd` | string | 创建/切换时的工作目录（resume 恢复，项目→会话切换还原目录，:11-12） |
| `thinking` | `{text}[]` | 推理模型思考内容数组（与 assistant 消息一一对应，空串占位；恢复思考块显示，**不进 history/context**，:12-13） |

`SessionSummary`（store.ts:27-33）是列表投影：`id / updatedAt / preview / cwd / title`。preview 取 **history 末条非 tool 消息**的前 40 字符（store.ts:96-98）——用 history 而非 context，因为 preview 要反映用户真实对话而非压缩摘要。

一个落盘文件的实际形状（带注释示意）：

```jsonc
{
  "id": "a1b2c3d4e5f6",
  "updatedAt": "2026-09-15T08:30:00.000Z",
  "history": [ { "role": "user", "content": "修复登录 bug" },
               { "role": "assistant", "content": null,
                 "tool_calls": [{ "id": "t1", "type": "function",
                                  "function": { "name": "edit_file", "arguments": "{...}" } }] },
               { "role": "tool", "tool_call_id": "t1", "content": "已替换 1 处（原第 42 行起）" } ],
  "context": [ /* 同上，但长对话时此处可能已被压缩为一条摘要消息 */ ],
  "sessionPermissions": [ { "tool": "shell", "patterns": [] },
                          { "tool": "write_file", "patterns": ["/work/proj/docs/**"] } ],
  "usage": { "promptTokens": 51230, "completionTokens": 8814, "turns": 6 },
  "compactions": 1,
  "title": "修复登录 bug",
  "cwd": "D:\\work\\proj",
  "thinking": [ { "text": "用户要求…（推理全文）" }, { "text": "" } ]
}
```

注意三处细节：history 与 context **独立序列化**（压缩只改 context）；sessionPermissions 的 path 模式已是落库时解析好的**绝对 posix 形式**（《06》§3.6 第 4 步）；thinking 末条的空串占位对应一条无 reasoning 的 assistant 消息（一一对应立法，《02》INV-7）。title 有值才序列化（store.ts:58 的条件展开）——缺省字段保持 undefined 语义。

## 3. 关键流程走查

### 3.1 落盘时机全景（snapshotFull 的五个调用点）

`conversation.snapshotFull(sessionPermissions, usage, compactions)`（conversation.ts:149-151）是组装快照的**唯一入口**，三参数由各自提供方传入。调用点：

1. **轮次收尾**：TurnRunner.finally → saveOrNotice（turn-runner.ts:185-197）——成功/取消/错误都落盘；失败发 notice"会话保存失败（磁盘空间不足或权限问题）"不静默；
2. **手动压缩后**（turn-runner.ts:155-161）；
3. **标题落盘**（turn-runner.ts:68-75，静默失败）；
4. **/rename 即时落盘**（agent.ts:471-479，静默失败——命名本身已有 notice 回执）；
5. **/set_cwd 即时落盘**（agent.ts:507-516）——会话文件携带 cwd，WebUI 侧栏按 cwd 分组项目树，**不即时保存的话新项目要等下一轮对话落盘后才出现**（agent.ts:505-506 注释）。

### 3.2 原子写（store.ts:44-61）

`save` 三步：`mkdirSync(recursive)` 建目录 → 写 `target + '.tmp'` → `renameSync(tmp, target)`。**原子写立法**：rename 在同一文件系统上是原子操作，避免半写文件损坏会话（store.ts:40 注释）——进程在 writeFileSync 中途被杀只留 .tmp 垃圾，正本完整。

### 3.3 resume 恢复链（manager.ts:46-64 + conversation.ts:136-146）

1. `sessions.load(id)`（manager.ts:49）：JSON.parse + **逐字段容错归一**（store.ts:63-76）——`history ?? messages`（兼容只有 messages 的旧格式）、`context ?? [...history]`（旧格式 context 重建为 history 拷贝）、`sessionPermissions ?? []`（**旧格式 allowedTools 不再读取——旧会话的提升视为空，重新询问一次即可**，:68 注释）、usage/compactions/thinking 各有零值兜底；
2. `conversation.load(s)`（manager.ts:50 → conversation.ts:136-146）：整体替换工作集——history/context/thinking/sessionId；**快照带 cwd 时一并恢复**（:141，`if (s.cwd) this.cwdValue = s.cwd`）；usage 续计、lastTurn 清零（本轮还没有"上一轮"）、compactions/title 恢复；
3. `permission.reset() + restore(s.sessionPermissions)`（manager.ts:52-53）——先清（可能残留上一会话的提升）再按存档还原；旧格式字段无视；
4. emit `session_ready`（messages = history 全量 + thinking）：UI 聊天区重现完整对话与思考块（:54-60）。
5. **恢复不影响运行体**：MCP 按当前配置重连、工具可用性由当前配置决定——会话存档不冻结运行环境。

### 3.4 新建与会话隔离（manager.ts:30-44）

`newSession(cwd?, opts?)`：可选指定工作目录（WebUI 项目树添加会话用，校验是目录否则 notice）→ `conversation.reset()`（全新 id + 空工作集，conversation.ts:124-133）→ `permission.reset()`（**会话隔离：allow_always 只对当前会话生效**，manager.ts:40）→ 默认立即保存空会话（侧栏即时显示，:41-42）→ emit session_ready。

`persist: false` 变体只换内存不落盘——删除当前会话的替换场景专用（见 3.5）。

### 3.5 删除当前会话的接管（manager.ts:78-94）

1. `sessions.delete(id)`（store.ts:79-82，文件不存在静默幂等）→ emit session_deleted；
2. **删除的是当前会话** → 立即 `newSession(undefined, { persist: false })`（:90-93）。两难的两个方向都被立法堵死（:87-89 注释）：
   - 内存旧工作集**必须被替换**：否则下一轮落盘会把刚删掉的会话原样写回（"复活"）；
   - 新会话**不能立即落盘**：否则删空的项目永远非空，WebUI 的"删除项目"（删除该项目下全部会话 = 项目遗忘）会被这个僵尸空会话挡住。

### 3.6 列表与项目分组（store.ts:88-107）

`list()`：readdir 过滤 `.json` → 逐文件解析投影 summary → **按 updatedAt 降序**（最新在前）。容错立法：**单个文件损坏不阻断整个列表**——跳过解析失败的文件、返回占位项 `{ preview: '（文件损坏）' }`（:93, 102-104）。`cwd` 随 summary 下发——WebUI 侧栏按 cwd 分组项目树（agent-to-ui.ts:17），同一项目的会话聚合；"项目遗忘"= 删除该项目下全部会话。

### 3.7 /rename 与标题优先级（agent.ts:466-483）

1. `/rename <名称>`：trim 后空则 notice 用法提示；有值 → `conversation.setTitle(title)` → 立即 snapshotFull 落盘（静默失败——命名 notice 已是回执）→ notice"会话已命名"→ 重推 session_list（:466-482）；
2. **优先级立法**：自动标题（turn-runner maybeAutoTitle）写回前查 `conversation.getTitle()`，已有标题（含 /rename 手动命名）则丢弃自动结果——"生成期间 /rename 已落（竞态窗口），手动命名优先"（turn-runner.ts:47 注释）；
3. 标题经 session_list 广播到两端状态栏/侧栏（TUI use-agent-events 的 session_list 分支同步 title；WebUI 侧栏显示 `title || preview`）。

### 3.8 WebUI 删除项目的完整链路（app.tsx:95-106 → manager.ts）

1. UI 统计该项目下会话数（`sessions.filter(s => s.cwd === projectCwd)`）→ confirm 弹框明示"将删除其下 N 个会话的记录。项目目录本身不会被删除"（:98-100）；
2. 确认后逐个 `port.post({type:'delete_session', id})` + `forgetProject(projectCwd)`（:102-103）——knownProjects 是 UI 侧集合，项目显示与否由它决定（use-sessions.ts:20-26 只增不自动减）；
3. agent 侧逐个删文件；若删除的是**当前会话**，触发 3.5 的接管逻辑（persist=false 新空会话）——"删空的项目永远非空"的僵尸问题就此被两端合力堵死。

### 3.9 用量双口径（conversation.ts:16-21, 73-84）

- **会话累计口径**：`usage { promptTokens, completionTokens, turns }`——跨轮累计、持久化、resume 续计（每轮 `applyTurnResult` 累加，:77-82）；
- **单轮口径**：`lastTurn`——最近一轮的快照（:81，`this.lastTurn = { ...result.usage }`，每次覆盖）；**不持久化**（load 时清零，:143）。
- 双口径的用途（bridge agent-to-ui.ts:28-31）：`context_state.lastTurn` 与本地估算并排展示——**可见估算器校准误差**；`sessionUsage` 是跨会话累计。数据源头是 LlmUsage（API `stream_options.include_usage` 精确值，见《03》§2.3），与本地粗估（estimate.ts）是两套体系。

## 4. 关键立法与不变量

- **INV-1 R1 双写持久化**：history 与 context 都落盘——resume 后"用户看到的"（history）与"模型续接的"（context）各自精确还原；压缩丢给模型的信息不丢给用户。
- **INV-2 原子写**：tmp + rename，磁盘上永远没有半写正本。
- **INV-3 提升临时、配置持久**：sessionPermissions 随会话存续（resume 还原、new 清空）；config 三桶跨会话不变。
- **INV-4 幂等删除**：delete 文件不存在静默成功（UI 与磁盘状态短暂不一致时无副作用）。
- **INV-5 损坏不扩散**：列表单文件损坏返回占位项；load 失败发 notice"文件不存在或已损坏"（manager.ts:61-63）——当前会话工作集不受污染。
- **INV-6 落盘失败可见**：轮次收尾的保存失败发 notice；次要路径（标题/命名）静默——按打扰成本分级。

## 5. 失败模式与恢复

| 失败 | 行为 | 恢复 |
|---|---|---|
| 轮次收尾写盘失败 | notice"会话保存失败（磁盘空间不足或权限问题）"（turn-runner.ts:195） | 用户清磁盘/修权限，下一轮重试 |
| resume 文件不存在/损坏 | notice"会话 X 加载失败"（manager.ts:61-63） | 会话列表重选；当前会话不受影响 |
| 旧格式会话文件 | load 逐字段兜底（messages→history、无 context 重建、allowedTools 丢弃） | 无缝升级，最多权限重问一次 |
| 列表中个别文件损坏 | 占位项"（文件损坏）"，列表其余正常（store.ts:102-104） | 手动删坏文件 |
| 半写文件（进程中断） | 原子写保证正本完好；残留 .tmp 不参与列表（filter `.json` 会含 .tmp? 否——`.tmp` 后缀不以 `.json` 结尾） | 无需恢复 |
| 删除当前会话 | persist=false 新会话接管（防复活/防僵尸空会话） | 首轮对话后才持久化 |
| /cd 后 cwd 与存档不一致 | set_cwd 即时落盘（agent.ts:507-516）；resume 恢复存档 cwd | 自动收敛 |
| thinking 与 assistant 数错位 | 一一对应立法（空串占位，《02》INV-7）+ resume 重建跳过空串 | 无需恢复 |
| 删除会话时正在运行 | deleteSession 的 blocked() 守卫发 notice（manager.ts:19-25, 78-79）——运行中不能删正在使用的会话 | 等轮次结束或取消后重试 |
| resume 残留上一会话的提升 | restore 前强制 reset（manager.ts:52-53）——提升从不跨会话泄漏 | 无需恢复 |

## 6. 与其它子系统的接缝

- **→ 02 轮次**：pushUserMessage / applyTurnResult / replaceContext 是轮次与工作集的全部交接面；TurnDelta 结构子集避免 session 依赖 turn。
- **→ 06 权限**：snapshotFull 的 sessionPermissions 参数由 `permission.snapshotPermissions()` 提供；resume 链里 reset+restore。
- **→ 07 MCP / 08 skills**：cwd 恢复后项目级配置（.mcp.json / .dogegg/skills）随新 cwd 生效；newSession(cwd) 同理。
- **→ 10 配置**：配置与会话是两套持久化（config.json vs sessions/*.json），互不嵌套。
- **→ 11/12 前端**：session_list/ session_ready/ session_deleted 消息驱动 TUI sessionPicker 与 WebUI 侧栏项目树。
