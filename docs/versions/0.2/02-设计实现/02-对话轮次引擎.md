# 02-对话轮次引擎

一轮对话由三个协作件驱动（`agent/src/turn/`）：`TurnRunner`（轮次编排与会话落盘）、`AgentLoop`（LLM↔工具循环）、`StateMachine`（状态对 UI 广播）。

## 状态机

`idle / thinking / responding / tool_calling / waiting_permission / executing / finished / cancelled / error / compacting`——每次转移发 `state` 消息，UI 状态栏与输入态随之变化。转移合法性由转移表约束（非法转移忽略）。

## 一轮的编排（TurnRunner.run）

1. 取 context（压缩检查：估算 > 80% 窗口 → 先走压缩管线）→ 组装请求（systemPrompt + 工具 schemas + history/context）。
2. 调 LLM（流式）：正文/思考增量逐条 emit；`tool_calls` 聚合完整参数。
3. 无工具调用 → 正文即最终回复 → finished（自动标题、落盘）。
4. 有工具调用 → 逐个：权限网关 → 执行 → 结果作为工具消息回填 → 回到 2（循环，受 maxIterations 约束）。
5. 异常路径：LLM 错误重试 maxRetries 次后 → error（原文回填输入框）；用户 cancel → abort 信号 → cancelled。

## 压缩管线（ADR-0011）

- 触发：手动 /compact 或估算 > 80% 窗口。
- 实现：把当前完整 context 交给 LLM 按「任务交接」结构化提示词总结（任务目标/已完成步骤/涉及文件/决策/未完成/用户偏好），产出的摘要作为一条用户角色消息替换整个 context。
- 立法：无尾巴、无淘汰、无硬丢弃；history 永不淘汰（R1），摘要丢失可回查原文。
- 摘要失败 → 轮次 error（诚实失败）；压缩计数与前后 token 进面板。

## 关键实现点

- 工具结果以 user 角色工具消息回填（`tool_call_id` 关联）——符合 OpenAI 协议的循环约束。
- maxOutput/reasoning 调整：reasoning 模型请求参数自动压缩输出预算（思考占额度）。
- LLM 请求失败重试由请求层处理（maxRetries），轮次层只看最终成败。
