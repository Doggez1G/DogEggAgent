# 01-四包架构与消息契约

## 四包职责

| 包 | 职责 | 依赖 |
|---|---|---|
| `@dogegg/bridge` | 契约与纯逻辑：消息类型、配置 schema、权限引擎、glob/通配、通道抽象（InMemory/SSE Port） | zod |
| `@dogegg/agent` | 后端域：对话轮次、LLM 接入、工具、权限运行时、skills、MCP、会话、配置编辑 | bridge |
| `@dogegg/ui` | 前端域：TUI（Ink）与 WebUI（React）共享的 reducer/命令/展示逻辑 + 两套界面 | bridge |
| `@dogegg/server` | WebUI 传输：HTTP + SSE 通道 + 静态托管 | agent、bridge |

## 依赖立法

- `agent ←→ bridge ←→ ui`：两端都只依赖 bridge（消息契约 + 纯派生逻辑），**互相不可见**。
- `server` 可 import agent 与 bridge，但**不 import ui**（前端是构建产物被静态托管）。
- 组合根唯一：`bin/dogegg.ts` 同时 import agent/ui/server 完成装配（TUI 走 InMemoryChannel；`-web` 走 SseChannel + HTTP 路由）。
- 跨模块 import 只能指向 `index.ts`（包脸面纯 re-export）；模块 = 文件夹，`index.ts` 之外都是私有实现。
- 该矩阵由**架构测试**强制（依赖方向违规即测试失败）。

## 消息契约

`bridge/src/contract/` 是两端通信的唯一事实源：

- `agent-to-ui.ts` + `agent-to-ui-schema.ts`：下行消息（对话流 text/thought_delta、状态机 state、工具 tool_*、权限 permission_*、配置流 config_*、管理流 skills_*/mcp_*、系统流 system/log/context）。
- `ui-to-agent.ts` + `ui-to-agent-schema.ts`：上行消息（submit、各 manage/request、决策、cancel...）。
- 类型与 zod schema 一一对应；SSE 下行与 POST 上行都经 zod 校验，非法消息丢弃（不进 listener）。

## 通道抽象

`bridge/src/channel/` 定义 `AgentPort`（agent 视角的 UI 方向）与 `UiPort`，两个实现：

- `InMemoryChannel`：TUI 同进程直连（同步，零序列化）。
- `SseChannel`：WebUI —— GET /api/events 下行 SSE + POST /api/message 上行；多标签页共享同一 agent 事件流（观察者模式）。

agent 只面对 `AgentPort`——换通道零业务改动。
