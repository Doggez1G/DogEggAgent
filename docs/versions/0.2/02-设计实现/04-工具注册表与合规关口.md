# 04-工具注册表与合规关口

`agent/src/tools/registry.ts` 是所有工具进入系统的**唯一关口**：注册时完成合规转换、冲突可见失败、身份记录三件事——适用于内建工具与 MCP 等一切来源。

## 立法（register 的三个动作）

```ts
register(tool, identity = { kind: 'builtin' }): string
```

1. **合规转换（构造即合规）**：名称匹配 `TOOL_NAME_RE`（`^[a-zA-Z0-9_-]{1,64}$`，供应商 API 硬规定）→ 原样注册；不合规 → 整体哈希为 `h-<12位hex>` 确定性标签（sha256 截断，同名必同标签）。**变换落在 Tool 对象本身**（name 字段改写），保证 `schemas()` 发给模型的名字必然合规——否则一次非法名会让每轮请求整体 400。
2. **冲突可见失败**：目标标签已被占用 → 抛错（含标签/原名/指引），绝不静默覆盖——静默顶掉会让先注册的工具无声失联。
3. **身份记录**：每个工具携带 `ToolIdentity`（`builtin` / `mcp{server, name}`），与工具同增同删；`register` 返回最终标签供调用方对接归属。

## 查询与摘除

- `unregister(name)`：工具与身份同步删除（不存在时静默）。
- `identityOf / identities()（快照）/ labelsWhere(谓词)`：权限服务键匹配、按服务摘除、UI 分组的数据源。
- `listTools()`：tools_list 载荷（工具 + 身份）——「凡注册必有身份」是不变量。
- `schemas()` / `get` / `all`：全部使用（可能被改写后的）标签。

## 为什么关口在注册表

- 合规转换放注册表而非各来源：未来任何新工具来源自动被覆盖，不靠自觉；
- 身份放注册表而非 McpManager 侧：注册与摘除是同一关口，工具与身份天然一致，不存在孤儿身份。
