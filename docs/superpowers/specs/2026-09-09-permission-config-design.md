# 权限配置 v2 设计：桶内按工具分组 + 两端编辑器（M1.1）

> 状态：已实施；**书写形态已被 ADR-0012（服务键身份匹配）/ ADR-0013（桶值结构化 v3 + 演进不兼容）修订——v2 书写格式已废弃**
> 日期：2026-09-09
> 前置：M1 工具面扩展已实施（`2026-09-08-tooling-expansion-design.md`）——参数化匹配引擎、
> 判定优先级、路径归一化、出厂默认均已落地并锁定测试。本设计**不碰引擎与判定语义**，
> 只重排「配置的书写形态」并补齐两端编辑器（M1 遗留债：规则可写但编辑器只能选工具名）。

## 1. 背景与问题

M1 交付后暴露两个体验问题：

1. **同工具的规则散落在三个桶数组里**（`allow: [{tool:'shell',command:'git *'}, …]`）——
   人是以工具为中心想权限的（"shell：git 自动跑、rm 要问我"），桶视角让同一工具的政策需要跨三个数组拼装；
2. **两端编辑器配不了参数化规则**：TUI/WebUI 只能从下拉框选工具名扔进桶，规则只能手编 config.json。

## 2. 配置形态 v2：桶 → 工具 → 模式数组（空数组 = 整工具）

```json
"permission": {
  "allow": {
    "read_file": [],
    "shell": ["git *", "npm run *"]
  },
  "ask": {
    "shell": ["rm *"]
  },
  "reject": {
    "shell": ["rm -rf *"]
  }
}
```

- 三桶**顶层结构不变**（v0.1 以来的心智延续，安全巡检视角「我禁止了什么」天然成立）；
- 桶内从「条目数组」变「工具 → 模式数组」映射：**工具出现在桶里 = 授权动作；数组是可选的
  范围限定——空数组 = 整工具，有内容 = 按模式限定**（单一形态，无布尔简写）；
- **主参数表**（立法，与转换逻辑同居 bridge）：模式字符串对应工具的主参数——`shell → command`，
  其余工具 → `path`。grouped 形态的固有简化，新工具若有非 path 主参数需在此登记；
- **作用域立法（锚点声明，算子不兼职）**：路径模式的作用域由**锚点前缀显式声明**，归一化只做解析
  不决定作用域，glob 算子（`*`/`**`）在哪就按其本义匹配、不充当作用域标记：
  | 锚点 | 作用域 | 例 |
  |---|---|---|
  | `./` 或 `../` | 会话 cwd（`..` 可出 cwd） | `./**`、`../shared/**` |
  | `~/` | 主目录 | `~/notes/**` |
  | 盘符或 `/` | 该绝对子树 | `D:/proj/**` |
  | 无（`*` 开头） | 从文件系统根匹配 | `**/test`（全盘任意深度）、`*/test`（仅盘根一层） |
  字面量打头的裸模式（`docs/**`、`test`）从根匹配只能命中盘根条目，必然是忘了写锚点 → **拒绝加载**
  （schema superRefine，报错提示补锚点；编辑器内经 validate/回滚同样浮出）。匹配前参数统一归一为绝对
  posix 形式（`resolve(cwd, arg)`）。
- **匹配语义立法（按主参数分派，各用其贴合的函数）**：
  - `path` 主参数 → `matchGlob`（分段 glob）：`*` 单段内任意（不跨 `/`）、`**` 跨任意层、`?` 单字符，
    其余字面量，整串锚定。路径有层级，段边界是安全性质（`./docs/*` 刻意不覆盖 `./docs/sub/x`）；
  - `command` 主参数（shell）与工具名 → `matchWildcard`（平文本通配）：`*` = 任意字符序列（含 `/`，
    与 `**` 同义），命令没有层级概念，`git *` 通配到结尾即够——作用域概念只存在于路径。
  归一化用 `path.resolve` 对整条路径做词法折叠：任意位置、任意深度的 `..`/`.` 都处理
  （`../../x`、`a/b/../../c`、绝对路径夹 `..` 皆然），不只第一个。
  已知残余边界：词法归一化不追踪 symlink。
- **`permission.default` 不存在**：未列出工具一律询问是安全立法而非偏好设置（做成可配置 = 一行配置
  拆掉整个防线 + 手滑工具名静默全放行），编辑器仅作只读说明行展示；
- **跨工具通配（`read_*` 管多工具）随形态淘汰**：桶内工具键是精确名——少数派能力，值得放弃。

## 3. 兼容与内部分层（引擎零改动的关键）

**书写格式 / 内存模型 / 匹配模型三层分离**：

```
config.json（v2 grouped 格式，保存唯一格式）
    │  zod 加载：union(v2, legacy) → v2 归一化        ← bridge/contract/config.ts
    ▼
内存 Config.permission = v2 grouped 形态（编辑器直接读写的形态，dot-path 寻址稳定）
    │  classifyPermission 内部：grouped → 扁平条目（纯函数 toEntries）  ← bridge/contract/permission.ts
    ▼
匹配引擎 entryMatches（M1 原样：{tool, 主参数模式} 条目；空模式数组 → {tool} → 引擎本就按整工具处理）
```

- **legacy（M1 扁平条目数组）加载兼容**：字符串条目 → `bucket[tool] = []`；规则对象
  `{tool, command:'git *'}` → `bucket[tool] = ['git *']`（取主参数键的值）。保存统一写 v2；
- 判定优先级（reject > 会话提升 > ask 规则 > allow > 默认 ask）、路径/命令双匹配语义、
  fail-closed、会话提升机制——全部不变；
- 权限编辑统一走 `config_set` 打**整桶对象**（如 `permission.allow` = 整个新桶映射）而非逐键
  dot-path——绕开对象动态键的文法问题，validate/回滚机制现成兜底，且天然原子。

## 4. TUI 编辑器（配置树三层化）

现有骨架全复用（↑↓ 导航 / Enter 钻入 / Esc·← 返回 / d 删除 / 标量就地输入），permission 子树
两层变三层：

```
[面板] 配置 / permission                 [面板] 配置 / permission / allow
──────────────────────────────────      ──────────────────────────────────
  > allow       2 个工具                   > read_file    整工具
    ask         1 个工具                     shell        2 条模式（另在 ask 桶有 1 条）
    reject      1 个工具                     ＋ 添加工具
    （未列出的工具一律询问——固定安全默认）  ──────────────────────────────────
──────────────────────────────────        回车钻入 · d 从桶中移除 · esc 返回
  up/down · 回车钻入 · esc 返回

[面板] 配置 / permission / allow / shell
──────────────────────────────────
  > git *
    npm run *
    ＋ 添加模式
──────────────────────────────────
  回车编辑 · d 删该条 · esc 返回

（空数组态：）> （整工具生效——添加模式后将改为按模式限定）
             ＋ 添加模式
```

交互细节：

- 工具行：`d` 从桶中移除该工具（删整个键）；Enter 钻入模式列表；
- 模式行：Enter 就地编辑（复用标量输入流）、`d` 删该条；
- **两态转换显性化**：空数组态显示提示行；添加第一条模式成功后 notice「<tool> 在 <bucket> 桶已改为
  按模式限定（1 条）」；删光模式回到整工具（不自动移除工具——用户可能就要整桶生效）；
- 添加模式校验：非空、同桶同工具内不重复；
- 「另在 ask 桶有 N 条」跨桶提示：防「宽放行了为什么还问我」的困惑。

## 5. WebUI 编辑器（设置面板权限区重排）

保持三桶区块，桶内改为工具分组列表：

```
┌ Allow ─────────────────────────────────────┐
│ ▸ read_file        整工具          [移除]   │
│ ▾ shell            2 条模式         [移除]   │
│     [ git *  ×]  [ npm run *  ×]           │
│     [ 输入模式，回车添加__________ ]        │
│ ＋ 添加工具（下拉：KNOWN_TOOLS 过滤本桶已有）│
└────────────────────────────────────────────┘
```

- 工具组头：工具名 + 摘要（整工具 / N 条模式，摘要文案与 TUI 同源放 shared）+ 移除按钮（删整个键）；
- 模式 chip：点击文字 → 原地输入框（预填原值，Enter/失焦保存、Esc 取消）；`×` 删除；
- 添加输入框：回车添加，非空 + 去重校验（重复红边提示，不发消息）；
- 空桶态说明行；顶部固定文案「未列出的工具默认询问（固定安全默认）」；
- 所有编辑 = 重算该桶对象 → `config_set('permission.<bucket>', newBucket)`。
